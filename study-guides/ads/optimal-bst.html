Optimal BST

For a fixed dictionary with known access frequencies, choose a shape that minimizes expected search comparisons.

Big pictureBuild from a fresh sorted key listOperations and complexityCaveats and exam focusRepeat the calculation in an examComparing online explanations with the lecture

Big picture

A balanced tree minimizes height. An optimal BST minimizes weighted search cost, which can favor a frequently accessed key near the root even if the resulting shape is less balanced. Unlike Huffman leaves, BST keys must keep inorder order.

Build from a fresh sorted key list

Sort keys a₁ < … < aₙ. pᵢ is the probability of a successful query for aᵢ; qᵢ is the probability of failure in the gap between consecutive keys. All p and q values sum to 1. The lecture counts a successful root lookup as one comparison and an empty tree as zero.

wij=∑u=i+1jpu+∑u=ijqu
cii=0,wii=qi,cij=wij+mini<k≤j(ci,k−1+ckj)

Store the minimizing k in rᵢⱼ. Fill intervals of length 0, then 1, then 2, up to n. Reconstruct the tree with root a[r₀ₙ], then build its left and right intervals recursively.

The indexes mark interval boundaries. Row 0 starts before the first key; for example, cell (0,2) covers a₁,a₂ and gaps q₀,q₁,q₂. A diagonal cell (i,i) has no keys. Each visible matrix cell combines the cost matrix C and root matrix R, as in the lecture. Weight w is calculated beside the matrix; Sₖ means the trial total when key aₖ is chosen as root.

Operations and complexity

Search uses ordinary BST comparisons in O(h), potentially O(n). Expected comparison count is the optimized weighted cost. Standard construction is O(n3) time and O(n2) space. Root monotonicity can reduce the DP to O(n2) with a correctly inclusive candidate interval. Reconstruction takes O(n).

Dynamic insert, delete and meld do not preserve optimality. Recompute the model and rebuild when the fixed key set or probabilities change. lowerBound, min/max and traversal still follow BST ordering, but no balancing guarantee follows from optimal expected cost.

Search c in the freshly built optimal tree

1 · Compare with a

Since c is greater than a, BST ordering rules out the left subtree and the search continues right without inspecting its contents. This comparison is one unit of successful-search cost; equality would stop here instead.

2 · Compare with b

Since c is greater than b, continue into b’s right interval, preserving the sorted-key search invariant. A missing key in that interval would terminate at its external failure gap rather than at a stored key.

3 · Compare with c

Equality with c ends a successful search after three comparisons. The path length matches c’s depth and shows why a low-probability key can be slower even when the tree minimizes the distribution-weighted total.

Caveats and exam focus

Include unsuccessful-query probabilities if given. Do not set empty-interval cost to qᵢ while also using this lecture's zero-cost base case. Those are different cost conventions. The root-range optimization requires nonnegative weights. Expected O(1)-like cost for a skewed distribution does not bound worst-case height.

Repeat the calculation in an exam

Draw rows and columns 0 through n. Cell (i,j) covers keys aᵢ₊₁ through aⱼ, so it contains j−i keys. Start on the main diagonal, then fill successive diagonals above it. Filling a whole ordinary row first would require child costs that have not been calculated.

  1. Initialize diagonal costs and root indexes to zero; initialize diagonal weights with qᵢ.
  2. Sum all p and q values in the next interval. Extend its preceding weight by adding the new key's p and right-hand gap's q.
  3. Try root indexes i+1 through j. Read the left cost from (i,k−1) and right cost from (k,j), then add wᵢⱼ once.
  4. Save the minimum total and the root index that produced it. Use a consistent tie rule.
  5. Reconstruct from r₀ₙ, following the saved roots of its two child intervals. Stop when i=j.

Why add the interval weight once?

Every query entering this interval first compares with its root. The probability of that event is wᵢⱼ. The saved child costs already count comparisons within each child viewed on its own. Adding the interval weight pays for the new comparison above them. It already includes pₖ, so do not add the root probability again.

Indexing and special cases

An empty interval costs zero even if its failure probability is positive. A single-key tree still needs a root comparison for either adjacent failure gap, so its cost is the key's p plus both q values. With every q zero, the method reduces to the successful-query example. Zero or equal probabilities can produce tied roots; choose one consistently. Empty input has just c₀₀=0, r₀₀=0 and w₀₀=q₀.

Keep probabilities attached to their keys when sorting the input. Do not renormalize the p values alone when q carries part of the probability mass. The expected-cost optimum can be tall; it does not guarantee logarithmic worst-case search.
