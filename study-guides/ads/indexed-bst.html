Indexed BST

Add leftSize to each node, so the tree can answer “which item is at rank k?” without traversing all earlier items.

Rule

leftSize is the number of records in a node's left subtree. It is the node's rank within its own subtree, not necessarily its global rank. Ranks in the lecture and lab start at zero. Balancing this tree, for example as an indexed AVL tree, gives logarithmic height.

Fresh build from [20, 10, 30, 5, 15]

Input list[20, 10, 30, 5, 15]

1 · Insert 20

The empty search path ends at the root link, so 20 is installed as the sole record with leftSize 0; there is no prior count to change, and insertion stops.

2 · Insert 10 and 30

Both comparisons attach 10 left and 30 right of 20; only the left attachment increases 20.leftSize from 0 to 1, while equality would update rather than add a node.

3 · Insert 5 and 15

Keys 5 and 15 both enter 20's left subtree, so its count rises from 1 to 3; node 10 gains one left descendant, and inorder confirms the BST order [5,10,15,20,30].

Operations

get(key), put, remove, getByIndex, indexOf and lowerBound cost O(h). Thus a plain indexed BST has O(n) worst-case operations; an indexed balanced BST has O(logn). Initialization and general meld follow BST construction, then compute subtree counts bottom up. Inorder remains O(n).

getByIndex(2), then indexOf(30)

1 · Compare rank 2 at node 20

At root 20, leftSize 3 places ranks 0–2 left of the root; requested zero-based rank 2 therefore enters that subtree unchanged.

2 · Compare at node 10

At node 10, rank 2 is greater than leftSize 1, so the search goes right and skips 5 plus 10; subtract 1+1 to get local rank 0.

3 · Reach node 15

At node 15, local rank 0 equals leftSize 0, so equality selects 15 and terminates successfully; a null child instead means the index is out of range.

4 · Find rank of 30

For key 30, moving right from 20 skips three left records and 20, making offset 4; equality at 30 adds no more, so the zero-based rank is 4.

Maintain metadata during update and deletion

1 · Update existing key 5

Key 5 is found by equality; replacing its value leaves the node set unchanged, so every leftSize and the total count stay fixed.

2 · Delete 10 using predecessor 5

Deleting 10 replaces it with predecessor 5 and physically removes the old 5 leaf; 20 loses one left descendant (3→2), and the replacement has leftSize 0.

3 · Try to delete missing key 99

Search for 99 ends at a null child without finding a record; because no link changes, neither ancestor counts nor the total record count changes.

Application and caveats

Best-fit bin packing stores (remaining capacity, bin identity), takes lowerBound(item size), removes the old capacity and inserts the reduced capacity. Use a multimap or a compound key so equal capacities do not overwrite each other. The lecture's [4,7,3,6] with capacity 10 fills bins [4,6] and [7,3]. Balanced-tree operations make n placements O(nlogn).

For rank access, reject negative indexes and indexes ≥ size. On insertion/deletion, update counts only after confirming a record was added/removed. Rotations need local count repair. An indexed tree used as a positional sequence is ordered by position, rather than by its element values.

Does adding leftSize make an ordinary BST balanced?

Check your answer

No. It adds rank information, while height can still be linear. Balance requires a separate invariant.

What the index stores

For each node x, leftSize(x) is the number of records strictly below its left link. It is also the zero-based rank of x inside the subtree rooted at x; it is not generally the node's rank in the whole tree. The whole-tree rank is accumulated along a search path. This metadata supports selection and rank, but it does not constrain tree height: an ordinary indexed BST can still become a chain.

Select by index and compute rank with offsets

getByIndex(i) treats i as a local zero-based rank in the current subtree. On a right turn it discards both the left subtree and the current node, so subtract leftSize + 1. indexOf(key) carries the opposite quantity: a running count of records already skipped above the current subtree.

Operation step Current node leftSize Local index / running offset Decision
getByIndex(8) 40 7 local index 8 8 > 7: go right with index 8−7−1=0
60 1 local index 0 0 < 1: go left; keep local index 0
50 1 local index 0 0 < 1: go left; keep local index 0
45 0 local index 0 equality: return 45
indexOf(50) 40 7 offset 0 50 > 40: add 7+1, go right with offset 8
60 1 offset 8 50 < 60: go left, keep offset 8
50 1 offset 8 equality: add leftSize 1; return rank 9

The sorted sequence confirms getByIndex(8)=45 and indexOf(50)=9. Reject negative indexes and indexes at least the tree size before traversal. For a missing key, indexOf returns not-found; a separate insertion-rank API may return the number of keys smaller than it, but that is an explicit API choice rather than an exact-match result.

Duplicate insertion and a genuinely new left descendant

The 12-key tree already contains 25. put(25, updatedValue) changes only its payload: count stays 12 and every displayed leftSize remains identical. A missing key 99 likewise changes nothing. In contrast, inserting 27 adds one node. The path is 40-left, 20-right, 30-left, 25-right: only 40 and 30 take left links, so their counts rise from 7 to 8 and 0 to 1 respectively; 20 and 25 keep their counts.

Delete by rank, including a two-child target

Remove zero-based rank 3 from the original 12-key tree. Selection reaches key 20 because 3 is less than 40.leftSize 7, then equals 20.leftSize 3. Since 20 has two children, the lecture's predecessor method chooses the maximum key in its left subtree, 15, copies that record into the target position, and physically unlinks the predecessor leaf. The recursive delete succeeds, so only then are counts decremented along affected left links.

Remove index 3 (key 20), then repair metadata

1 · Select the requested rank

2 · Replace with predecessor 15 and unlink it

After deletion, inorder is [5,10,15,25,30,35,40,45,50,60,70], so 15 is at rank 2 and the removed key 20 is absent. A leaf removal unlinks one child pointer; a one-child removal splices that child into the parent link. For a two-child removal, the predecessor/successor is guaranteed to have at most one child, and metadata repair starts from its physical unlink point and returns toward the root. If a search for the key fails, propagate removed=False and change no counts.

Lower bound and best-fit bin packing

The best-fit rule needs the smallest available capacity at least as large as the next item. At each node for threshold s, save the node as a candidate when its capacity is ≥ s and continue left to seek a smaller qualifying capacity; when capacity < s, continue right. Equality is a fit. No candidate means no existing bin fits, so create a new bin. Because capacities can repeat, key each record by (remaining capacity, bin ID) or use a multimap; capacity alone must not overwrite a distinct bin.

For lecture input [4,7,3,6] with capacity 10, the dictionary operations are:

Item Smallest capacity ≥ item Update Dictionary after placement (capacity, bin)
4 none open B1, remaining 6 (6,B1)
7 none open B2, remaining 3 (3,B2), (6,B1)
3 (3,B2) remove (3,B2), insert (0,B2) (0,B2), (6,B1)
6 (6,B1) remove (6,B1), insert (0,B1) (0,B1), (0,B2)

The final bins are B1 [4,6] and B2 [7,3]. A plain BST takes O(h) per search/update, with O(n) worst-case height; the lecture's O(nlogn) total uses a balanced BST and duplicate-capacity dictionary. The lower-bound traversal is the usual ordered-tree technique; Lecture 8 motivates the query and specifies the duplicate pair representation.

Repairing counts after an optional rotation

The lecture presents indexed AVL trees as a way to combine rank access with logarithmic height, but it does not detail rotation metadata updates. In an augmented implementation, first rewire pointers, then recompute the lowered node's leftSize from its new left subtree, followed by the promoted node's leftSize. Build, traversal, extremes, and meld

Lecture 8 initializes by sorting, constructing a search tree, and outputting inorder; it gives O(nlogn) as a necessary sorting lower bound. Repeated plain-BST insertion costs O(nh) and can be O(n2) in a bad order. If already sorted input is available, direct balanced construction with bottom-up left-subtree counts is a supplemental implementation and takes O(n); it does not contradict the sorting lower bound.

inorder visits left, node, right and emits sorted keys in O(n). minimum follows left pointers and maximum follows right pointers, stopping at the first missing child; each costs O(h), and either is undefined for an empty tree. removeMin/removeMax use the same path, splice the at-most-one child, and decrement counts only at ancestors whose left link lost a record.

General meld must account for key comparisons and duplicate policy. Lecture 8 shows merging inorder lists and states that merging two size-n sorted lists needs up to 2n−1 comparisons, giving an Ω(n) meld lower bound; logarithmic general meld is therefore impossible. A straightforward approach merges inorder sequences, applies the chosen duplicate rule, builds a tree, and computes leftSize bottom-up in O(n+m). Specialized join of disjoint ranges is a different, supplemental operation.

Method decision table

Method Decision rule Stop condition and edge cases Cost and course boundary
get(key) / search Compare key and follow left or right. Equality succeeds; null link means missing. Empty tree misses immediately. O(h); O(n) worst for ordinary BST. Lecture 8 dictionary operations.
put(key,value) Search first; update equal key, otherwise attach one leaf. Increment leftSize only on successful insertion paths that take left links. Empty root installs count 0. Duplicate updates value and no counts. O(h); O(n) worst unbalanced. Lecture 8 slide 53 shows insertion.
update(key,value) Change the payload only after an exact key match. A missing update-only target returns not-found and changes no counts; put on that same missing key creates a record. O(h); worst O(n) plain BST. The distinction depends on the dictionary API contract.
remove(key) Search; leaf unlink, one-child splice, or replace a two-child node with predecessor/successor then unlink it. Decrement only after confirmed removal; missing key leaves every count unchanged. Root leaf empties tree; root one-child promotes child. O(h); O(n) worst. Lecture 8 slides 54–67.
getByIndex(i) / select Compare local rank with leftSize; left keeps i, equality returns node, right uses i−leftSize−1. Validate 0 ≤ i < size; a missing child signals invalid metadata or out-of-range input. O(h); O(n) worst plain BST. The comparison rule is Lecture 8 slides 22–23.
indexOf(key) / rank Exact-match search with running offset; on a right turn add leftSize+1; on equality add current leftSize. Missing key returns not-found. Insertion rank for absent keys is a separate API. O(h); running-offset formulation supplements the lecture's rank definition on slide 20.
removeByIndex(i) Select the indexed key, then run standard key deletion; repair leftSize only on successful recursive returns. Reject invalid index before mutation. A two-child target requires physical predecessor/successor unlink and count repair to root. O(h); O(n) worst plain BST. Composite operation built from lecture select and delete.
lowerBound(x) Keep candidate when node key ≥ x and go left; otherwise go right. Equality qualifies; no candidate means x exceeds maximum or tree is empty. O(h); supplemental ordered-search procedure. Used for Lecture 8 best fit.
bestFit(item) Lower-bound remaining capacity; replace selected (capacity,bin) record with its reduced pair. No fit opens a bin; equal capacities retain distinct bin IDs; reject items larger than bin capacity by creating a new bin. O(logn) per action only with balanced BST; O(n) per action worst plain BST. Lecture 8 slides 8–17.
inorder / ascend Traverse left, emit node, traverse right. Empty tree emits an empty sequence; BST order guarantees sorted keys. O(n). Lecture 8 uses inorder for output.
minimum, maximum Follow leftmost or rightmost child respectively. Stop when the next child is null; empty tree has no extremum. O(h); O(n) worst. Lecture 8 slide 69.
removeMin, removeMax Find the extreme, splice its optional sole child, and propagate successful count repair. Empty tree is unchanged; update ancestor counts only after a node is removed. O(h); follows lecture's remove and extreme paths.
initialize(records) Lecture route: sort, construct BST, emit inorder. For an already sorted sequence, a balanced bulk build is possible. Apply duplicate policy consistently; recompute all counts bottom-up. Lecture gives Ω(nlogn) sorting lower bound; repeated unbalanced insertion may cost O(n2).
meld(T1,T2) General meld merges sorted inorder streams, resolves equal keys by policy, rebuilds, and recomputes counts. Do not assume disjoint key ranges; specialized disjoint-range join has different preconditions. Ω(n+m) comparisons/work in general, not logarithmic; Lecture 8 slides 71–72.
positional sequence operations Interpret inorder position as sequence order, not element-value order; use select and rank metadata. Insertion/removal by position must repair counts; the sequence contract decides where a new position is inserted. Indexed BST is O(h); Lecture 8 slide 24 illustrates sequence representation and slide 25 gives O(logn) for indexed AVL.
rotate in an augmented balanced tree Rewire, then recompute the lowered node's leftSize followed by the promoted node's. Preserve inorder and parent/root links; do not claim the base indexed BST self-balances. Supplemental metadata rule; Lecture 8 names indexed AVL but leaves rotation mechanics to that structure.

For a particular tree, these search-path methods take O(h) actual time. Lecture 8's complexity table distinguishes an ordinary BST's O(n) worst case and O(logn) expected case from a balanced BST's O(logn) worst-case and expected bounds. Those are expected-time statements for dictionary operations, not guarantees from leftSize; rank/select still follow the same height. The lecture gives no amortized bound for an indexed BST, so none is claimed here.

Common mistakes and exam focus

  • leftSize counts nodes, not height and not the right subtree. It equals the node's rank only inside that node's own subtree.
  • Keep ranks zero-based. Equality is selected; a right turn skips leftSize + 1 records.
  • For indexOf, add skipped records to a running offset. For getByIndex, subtract skipped records from the local requested index; these are inverse views of the same inorder partition.
  • Duplicate put and unsuccessful deletion do not change size or metadata. Do not increment counts merely because a search traversed left.
  • Two-child deletion copies/moves a predecessor or successor but physically removes that record from its old location. Repair counts from the physical removal path, including the target's leftSize when its predecessor came from its left subtree.
  • The BST invariant orders keys; leftSize supports order statistics; a separate balance invariant is needed for logarithmic worst-case height.
  • For best fit, search for the least capacity ≥ item, not merely any fitting bin, and retain duplicate capacities with distinct bin identities.
  • Melding is not a logarithmic root-link operation for arbitrary interleaved key ranges; sorted-stream merge is linear in total input size.
