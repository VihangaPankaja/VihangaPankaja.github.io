Digital search and strings / Lecture 14

Suffix tree

Index every suffix of a source string. A substring query becomes a prefix search through those suffixes.

RuleSearch and special operationsConstruction, repeated strings and common stringsUpdate caveats and exam focusA larger suffix-list build: bananaRepetition and common-substring decisionsMethod decisions and stop conditionsCommon mistakesExam focusPractice

Rule

A suffix tree is a compressed trie with edge information for all nonempty suffixes of a string. Append a unique terminator # so no suffix is a proper prefix of another. Each leaf stores its suffix's starting position. Store edge labels as source intervals rather than copying long strings.

Build fresh from the suffix list of aba#

1 · Form the list

The list is the complete set of nonempty suffixes, indexed from 1; the final # is included in each suffix. This makes every suffix terminate at a distinct leaf and prevents one suffix from ending as a prefix of another. The list is the input to this teaching construction, not yet a tree.

2 · Insert suffixes aba# and ba#

Compare the first characters of aba# and ba#: a and b differ, so each suffix gets its own root edge and leaf. No shared prefix exists to compress below the root; continue with the remaining suffixes.

3 · Insert a# and split an edge

Insert a#: its first a matches the beginning of aba#, but the next characters differ (b versus #). Split the old edge after a, keep the old continuation ba# at leaf 1, and add # to leaf 3. The internal node now records the shared prefix a; continue with the remaining suffix.

4 · Insert #

The final suffix # has a root character not used by the other suffixes, so add one edge and leaf at position 4. All four suffixes terminate at distinct leaves, and every internal node branches; this completes this small naive construction.

Search and special operations

To search pattern p, compare characters along compressed edges. Finishing p in the middle of a matching edge is a success. A mismatch anywhere is failure. Existence search costs O(|p|) under constant-time child access. Reporting k occurrences costs O(|p|+k) with suitable leaf traversal or the lecture's linked leaves and subtree endpoint pointers.

Search a, then ab, then aa

1 · Search a

Follow the root edge a and stop exactly at its branch node after one matched character. Since the pattern is exhausted, the search succeeds; the descendant leaves 1 and 3 are precisely the two starts of a. If reporting all matches, visit those leaves (or use the lecture’s linked-leaf interval).

2 · Search ab

After matching a, take the b edge and compare only the needed character of its compressed label ba#. The query ends after that b, inside the edge, so it is present and its only descendant leaf is position 1. Stop as soon as the pattern is exhausted; do not require reaching a node.

3 · Search aa

The first a reaches the branch node, but its outgoing labels are b and #, not a. No edge can continue the query’s second character, so aa is absent even though its first character has a path. Stop at this missing child.

Construction, repeated strings and common strings

The simple fresh build inserts all suffixes and can take O(n2) character work. Efficient suffix-tree algorithms achieve the lecture's O(nr) array-node construction bound, which is O(n) for fixed alphabet size r. Do not claim the naive suffix insertion viewer attains that bound. A fixed-alphabet tree has O(n) nodes and edge-interval storage.

For the longest substring occurring at least m times, count leaves below each branch and choose the eligible branch with greatest string depth. Overlapping occurrences count. The lecture's problem wording says “more than m” but its algorithm tests ≥ m. These are different: use threshold m for at least m occurrences, and m+1 for strictly more than m. For a substring in both S and T, build on S$T# using distinct separators, label leaves by source, and choose the deepest branch with descendants from both. In the lecture, carport and airports share rport, while arport is a common subsequence but is not a substring common to both strings.

Update caveats and exam focus

This is primarily a static source index. Rebuilding after text changes is a clear supported approach. Generic insert/delete/meld of source strings is not a constant-time suffix-tree operation. Appending text needs an online construction algorithm, not one ordinary trie insertion. A terminator must not occur in the original alphabet. char# in the slides indicates matched character depth information, not merely the number of graph edges.

Suffix arrays, enhanced arrays, linearized/virtual suffix trees and suffix cactus/vectors are named relatives. The supplied lesson develops suffix-tree operations, so the revision steps here concentrate on that structure.

Why can a substring be found through suffixes?

Check your answer

Every occurrence starts at some source position. The substring is therefore a prefix of the suffix starting at that position.

A larger suffix-list build: banana

This fresh example inserts every suffix of the source banana, after appending the unique terminator #. Positions are 1-based. The edge labels in the diagrams are expanded for reading; an implementation can store source-string intervals instead. Each state preserves the already-inserted suffixes, and each internal node is created at the first point where two suffixes disagree.

Build fresh from the suffix list of banana#

1 · Form all seven nonempty suffixes

2 · Insert banana# (position 1)

3 · Insert anana# (position 2)

4 · Insert nana# (position 3)

5 · Split after ana for ana# (position 4)

6 · Split after na for na# (position 5)

7 · Split after a for a# (position 6)

8 · Insert the terminator suffix # (position 7)

Search edge cases as paths, not just nodes

Compressed edges can contain successful stopping points that are not explicit nodes. These diagrams mark the endpoint conceptually in the edge caption: the path must match every query character, but the query need not end at a branch or leaf.

For a failed path, the stopping point matters just as much:

The naive fresh-list construction compares suffix characters while inserting and can take quadratic character work in the source length. That is a different method from the lecture’s efficient construction bound: the lecture states O(nr) with array nodes, hence O(n) for a fixed alphabet of size r. Do not assign that efficient bound to these insertion viewers. Edge-interval labels and the fixed-alphabet O(n)-node size bound explain how a completed suffix tree can remain linear in space.

Repetition and common-substring decisions

In the completed banana# tree, prefix ana reaches the branch after path a + na; its leaves are positions 2 and 4. Thus ana occurs twice, and it is the longest repeated substring: the next shared character differs (n continues suffix 2 while # ends suffix 4). Prefix na similarly has leaves 3 and 5 but depth 2. Overlapping occurrences count. For “at least m” occurrences, retain branches with at least m descendant leaves; for “more than m,” use m+1. The lecture heading says “more than m” while its test uses ≥m, so state the intended threshold explicitly.

For the lecture’s common-substring example, concatenate carport$airports# with distinct separators. Label each suffix leaf by whether it starts in carport or airports; among branches with at least one leaf from each source, choose the greatest character depth. The result is rport (positions 3 in both source strings). arport is a substring of carport and a subsequence of both strings, but it is not a substring common to both because airports does not contain it contiguously. The slides pose this construction as an exercise; the deepest mixed-source branch criterion is the operational interpretation, not a separately detailed lecture algorithm.

Common mistakes

  • Treating a successful search as requiring arrival at a node. A pattern may finish in the middle of a compressed edge.
  • Treating a matching first character as a full match. Compare every remaining query character and fail at the first absent child or mismatching edge character.
  • Counting graph edges instead of matched characters. The lecture’s char# annotation records character depth along compressed labels.
  • Confusing the simple suffix-list insertion demonstration with the lecture’s O(nr) construction method.
  • Using one terminator that can occur in the source, or reusing the same separator for both source strings in the common-substring construction.
  • Confusing occurrences with distinct paths: one branch path may report several starting positions, and overlapping positions still count.

Exam focus

Know the compressed-trie definition; explain why a unique terminator makes suffix endpoints distinct; prove substring iff prefix of a suffix; trace edge splits at the first mismatch; distinguish a node endpoint from an implicit edge endpoint; report leaf positions; and state which construction and reporting assumptions support each complexity bound. For repeat/common-substring questions, combine branch depth with descendant leaf counts or source labels, and resolve “at least” versus “more than” before selecting a threshold.

Practice

Why does an occur twice in banana, even though its search ends inside an edge?

Check your answer

It matches the path a then the first n on the compressed na edge. The matched edge’s subtree has suffix leaves 2 and 4, so the starts are 2 and 4. Reaching the end of the edge is unnecessary because the query has already ended.

What should the tree do for query anab?

Check your answer

It matches ana to the branch, then fails because that branch continues with n or #, not b. A successful prefix does not rescue a later missing character.

For a substring required to occur more than 2 times, what leaf-count threshold is used?

Check your answer

Use at least 3 descendant leaves. Distinct suffix starts count separately, including overlapping occurrences.
