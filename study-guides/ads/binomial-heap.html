Lazy binomial heap

Add roots cheaply. During removeMin, combine equal-degree trees like carrying digits in binary addition.

Rule and representationOperationsCaveats and exam focusBig pictureFresh construction and destructive meldRemoving a root with childrenMethod decisions and stop conditionsContrasting cases to rememberCommon mistakesExam focusPractice questions

Rule and representation

The course uses a lazy binomial heap: a circular singly linked root list, a min pointer, and node fields key, degree, child and sibling. A binomial tree Bk has 2k nodes and root degree k. Multiple roots of the same degree are allowed between consolidations.

Input list[7, 3, 9, 1]

1 · Empty root list

This is the base case: an empty circular root list has no minimum, so minPtr must be null. Stop the empty-build trace here; the first singleton will become both the only root and the minimum.

2 · Insert 7, then 3

Each insertion splices one isolated degree-0 root into the circle. Equal root degrees are allowed in this lazy variant, and minPtr changes from 7 to 3 because 3 is smaller; stop after both constant-time splices.

3 · Insert 9, then 1

The next two singleton roots remain degree 0 even though the list now has four equal degrees. Compare each new key with the current minimum, so 1 becomes minPtr; stop without consolidation because only removeMin performs it in this course variant.

Arbitrary remove and decreaseKey are not part of this lecture/lab interface. The singly linked representation has no parent field. Do not transfer Fibonacci-heap cut bounds to it. An eager binomial heap consolidates on insert/meld and has different actual bounds.

removeMin and pairwiseCombine

1 · Remove root 1

The removed root 1 is an isolated singleton, so there is no child forest to promote. Unlink it from the root circle; the three degree-0 roots 7, 3, and 9 remain, and the next phase must account for every one of them.

2 · Put 7 in table[0]

The first captured root 7 occupies table[0], whose invariant is at most one root of each degree. Continue to the next captured root: an empty slot ends processing for this root, not for the whole consolidation.

3 · Collision with 3 at degree 0

The next root 3 collides with degree 0. Since 3 is smaller, link 7 beneath 3, raise the winner to degree 1, clear table[0], and carry the new tree to table[1]; continue only if that slot is occupied.

4 · Process 9 and rebuild

Root 9 fills table[0] while the carried B1 rooted at 3 stays in table[1]. Once all snapshot roots are processed, rebuild the root circle from the nonempty slots, clear the temporary table, and scan its roots to set minPtr to 3; the two root-list edges are siblings, not parent-child links.

Caveats and exam focus

If a degree-table collision creates another collision, keep linking. After consolidation, root degrees are distinct and at most ⌊log2n⌋. Before consolidation, the root count can be n. Removing the only root may still leave its children, so capture the list-splicing return value. Snapshot roots before mutation to avoid cycling forever. Update degrees after every link and empty the donor after destructive meld.

Why can a single removeMin take O(n)?

Check your answer

After n lazy inserts there can be n roots. The first removal must inspect and consolidate them. Earlier cheap inserts pay for that deferred work in the amortized analysis.

Big picture

A lazy binomial heap buys constant-time insertion and meld by leaving roots uncombined. Every root is a min-tree root, and the root pointer names a minimum, but root degrees need not be unique until removeMin consolidates them. A degree-table collision behaves like a binary carry: two degree-d trees become one degree-(d+1) tree, with the larger root below the smaller.

For a binomial tree,

|Bk|=2k,deg(root(Bk))=k
. This size invariant explains the maximum degree after consolidation: a degree-k tree needs at least 2k records.

Fresh construction and destructive meld

The eight inserts above are a larger lazy build. All eight keys occur as degree-0 roots; the arrays show insertion history, while the actual root-circle traversal from minPtr is [1, 5, 3, 6, 7, 8, 4, 2]. After building A, meld it with singleton B=[0]. The two circles splice in constant time; because 0<1, A.minPtr becomes B's root. The operation consumes B: its root/min pointers are cleared, so it cannot still claim ownership of those nodes. The combined forest is still nine singletons. Removing 0 leaves the eight roots used in the carry walk.

The carry walk uses the actual root-circle order [5, 3, 6, 7, 8, 4, 2, 1] after removing 0. This order follows Lab 4's splice-after-min-pointer operation; the original input order is not the sibling traversal order. Table entries record one tree per degree; an empty slot stops the carry for that root, while an occupied slot requires a comparison, link, slot clear, and another iteration. At equality, either root can remain parent because heap order permits equal keys; the lab code keeps the first argument. The three child trees of B3 have degrees 0, 1, and 2. Lab 4 inserts each newly linked child after the node's child pointer; for this trace the pointer order is B0, B2, B1. Sibling order is circular-list bookkeeping, not a priority ordering. After the final root, rebuild the circular list from nonempty table slots, clear the temporary table, and scan all resulting roots for minPtr. Here only B3 remains, rooted at 1.

Method decisions and stop conditions

Method Decision and invariant Stop condition and edge cases Actual worst case Amortized
initialize(values) / fresh build Start empty; splice every value as a degree-0 singleton and maintain the minimum pointer. Do not consolidate. Empty input leaves null minPtr; after the last value, stop with one root per input record. O(n) O(n)
getMin() Read the key at minPtr; no root scan is needed because every mutator maintains it. Empty heap has no result (the lab sentinel is -1); otherwise return the pointed-to key. Equal minima are allowed. O(1) O(1)
insert(x) Create an isolated degree-0 root, splice its sibling circle into the root circle, and replace minPtr only if x is strictly smaller. Empty heap initializes minPtr; equality may keep the prior pointer. Stop after one splice and comparison; no linking. O(1) O(1)
meld(other) Splice the two root circles and keep the smaller minimum pointer. This is a destructive ownership transfer in Lab 4. Empty donor is a no-op; empty receiver takes donor roots; equal minima may retain the receiver pointer. Self-meld is outside the lecture contract: one Lab 4 implementation guards it, the later implementation does not. Require distinct heaps or an explicit alias guard. Clear donor pointer/count after transfer. O(1) O(1)
removeMin() Save the minimum key and child-circle pointer, remove the selected root, promote its children, pairwiseCombine the forest, and recompute minPtr. Empty heap fails. If it was the only root, clear the root pointer; if that root had children, those children still form a nonempty heap. Stop only after every captured root is processed and the table is drained. O(n) O(logn)*
pairwiseCombine() Snapshot roots; table by degree; on collision keep the smaller (either on equality), make the other a child, increment degree, clear the old slot, and carry again. Stop a root at its first empty degree slot. When the snapshot is exhausted, rebuild roots from nonempty slots, clear slots, and scan for minPtr. O(s+D), O(n) Part of removeMin*
Equal-degree link (internal) Requires isolated min-tree roots of the same degree. The winner remains a root; the loser joins its child sibling circle; winner.degree increases by one. Continue carrying while the new degree is occupied. Stop when stored or when the table grows to that degree. O(1) each O(1) each
search(x) Walk the root circle and each tree; heap order is not BST order and minPtr only answers the minimum query. Return a matching record when found; otherwise stop after a full forest traversal. With duplicates, any match suffices. O(n) O(n)
Arbitrary remove(x) / decreaseKey(handle) Not supported by this lecture/lab interface. There is no parent field or node handle contract for locating and repairing an arbitrary node. Do not invent a cut rule or import Fibonacci-heap bounds. Use only the supported root deletion or create a separately specified variant. — —

Here s is the number of roots processed and D is the largest degree/table extent. Contrasting cases to remember

  • Singleton and empty: removing the only degree-0 root leaves no roots, so minPtr becomes null. Inserting into empty restores it. An empty removeMin fails.
  • Only root with children: deleting that root does not imply an empty heap. Promote the child sibling circle first, then choose the minimum among those promoted roots.
  • No table collision: a root reaches an empty degree slot and stops; do not link trees of different degrees.
  • Repeated collisions: a carry can cause further collisions at successive degrees. Never stop after the first link; the 8th singleton above carries from degree 0 through degree 3.
  • Equal root keys: either equal root can stay above the other. The lab comparison swaps only when the second key is strictly smaller; minPtr remains valid on equality.
  • Meld ownership: splicing two circles is O(1), but a destructive meld must clear the donor's root pointer (and its size field in Lab 4). Self-meld is not consistently guarded in the two Lab 4 implementations, so require distinct heaps unless the caller checks aliasing.
  • Lecture list deletion versus Lab 4 unlink: slide 11 teaches singly circular-list deletion by copying the successor's record into the selected node and unlinking that successor (or clearing the pointer when there is no next node). The Lab 4 code instead walks to the predecessor and unlinks the selected root directly. Both represent removal from the same circle; whichever form is used, save the selected minimum's child circle before overwriting or detaching its root record.
  • Search versus minimum: a minimum pointer does not make membership search constant-time. The heap order only constrains parent-child keys; root order is not sorted.
  • Lazy versus eager: this page follows the lazy course variant. Eager consolidation on every insert or meld changes when links occur and changes actual operation costs.

Common mistakes

Do not assume distinct root degrees before removeMin, or eager consolidation after insert/meld. Do not treat the root circle as a parent-child tree. Do not lose the removed minimum's child pointer while changing the root list, and do not stop after its first table collision. After linking, increment exactly one degree and clear exactly the consumed table slot. After rebuilding, clear temporary entries and recompute minPtr. A donor heap must be empty after destructive meld.

Exam focus

The key comparison is between lazy and eager variants: lazy insert and meld are O(1) actual, while one removeMin can be O(n) actual because it processes all roots. Pairwise linking is binary carrying over degrees; a consolidated forest has distinct degrees and at most ⌊log2n⌋ degree. Do not confuse worst-case work of one operation with its amortized removeMin bound. General search remains O(n), and arbitrary decreaseKey/remove are outside this singly linked interface.

Practice questions

  1. After inserting n values into an empty lazy heap, what can the root list look like?
Check your answer

It can contain n singleton roots, all of degree 0. Lazy insertion does not consolidate them.

  1. A degree-2 collision creates degree 3, where a table entry is already occupied. What happens?
Check your answer

Compare the two degree-3 roots, link the larger below the smaller, clear degree 3, increment the winner to degree 4, and continue until an empty slot is found.

  1. The removed minimum is the only root and has three child trees. Is the heap now empty?
Check your answer

No. Promote its child roots into the root circle and recompute the minimum over them; the heap is empty only when both the old root list and promoted child list are empty.

  1. Why does meld clear the donor after the root circles are spliced?
Check your answer

The destination now owns the donor's nodes. Clearing the donor prevents two heap objects from claiming the same circular list and later unlinking or freeing it twice.
