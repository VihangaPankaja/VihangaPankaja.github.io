Dictionaries and search trees / Lecture 8

Binary search tree

Keys smaller than a node go left; larger keys go right. All ordered operations follow from that rule.

Rule and fresh build

Every key in the left subtree is smaller than the node key, and every key in the right subtree is larger. Inorder traversal produces sorted order. Duplicate dictionary keys update their values unless a duplicate policy is explicitly chosen.

Build from a fresh list [20, 10, 30, 5, 15]

Input list[20, 10, 30, 5, 15]

1 · Insert 20 into an empty tree

The empty root link is the insertion point, so 20 becomes the root without violating either key range. Stop this insertion as soon as the null root link is replaced.

2 · Insert 10, then 30

Compare each distinct key at the current node: 10 < 20 takes the left link and 30 > 20 takes the right. Both stop at empty links, so the root's two ordered ranges remain disjoint.

3 · Insert 5, then 15

For 5, comparisons 5 < 20 and 5 < 10 end at 10.left; for 15, 15 < 20 then 15 > 10 ends at 10.right. Each null child is replaced once, preserving strict inorder order [5,10,15,20,30].

Operations

Search, insert, remove, minimum, maximum and lowerBound cost O(h), where h is height. A plain BST can have h=n, so each can take O(n). Randomly ordered inserts give expected logarithmic height under that input model. ascend/inorder costs O(n). A range query can cost O(h+k) for k reported records.

Build by repeated insertion costs O(n2) worst case. For a balanced static shape, sort an unsorted list in O(nlogn), then recursively choose medians in O(n). An already sorted list avoids the sorting cost. General meld can inorder both trees, merge the lists, then rebuild in O(n+m). Joining disjoint ordered ranges is a different operation.

Search and the three deletion cases

1 · Search 15

At 20, 15 < 20 selects left; at 10, 15 > 10 selects right; equality at 15 returns its record. Stop on equality, and the visited path is exactly 20 → 10 → 15.

2 · Delete leaf 5

Key 5 is a leaf, so remove only 10.left. No other pointer or key changes, and the remaining inorder keys are [10,15,20,30].

3 · Delete degree-1 node 10

Key 10 has just one child, 15. Replace the incoming link from 20 with that child; this bypasses 10 while retaining every key in the same ordered interval.

4 · Delete degree-2 node 20

Node 20 has two children. Copy the predecessor pair (15,value) from the maximum of its left subtree into the root, then physically unlink the old 15 leaf. The root pointer stays attached to the replacement, and inorder becomes [15,30].

Special methods and caveats

lowerBound(x) records a candidate whenever current.key ≥ x, then tries left for a smaller fit. Otherwise it goes right. findMin follows left links; findMax follows right links. A missing key ends at null. Deleting a root must update the root pointer. Copy the entire key/value pair when using a predecessor, not only the key.

It becomes a right chain of height 5 when height counts nodes. Search for 5 takes five node comparisons.

Twelve-key construction, one insertion per state

This fresh input puts keys on both sides of the root, adds a deeper left-right branch, and fills a second-level right branch. Each state inserts exactly the next list item by ordinary comparisons; a repeated key would update the existing value instead of creating a node.

Search, missing keys, and duplicate policy

Lookup and put on the twelve-key tree

1 · Get key 65

2 · Get missing key 66

3 · Put key 65 with a new value

Lecture 8 distinguishes dictionaries whose keys are distinct from a duplicate-capable dictionary. Therefore “put an existing key” is an API policy: a unique-key map updates the value; a multimap may retain multiple records and needs an ordering/identity rule to make lookup and deletion unambiguous. Do not insert an equal key to either side without a stated rule.

lowerBound: the best-fit query

lowerBound(x) returns the smallest stored key greater than or equal to x. At a node v, if v ≥ x, record v as a candidate and continue left; otherwise every key in the left subtree is too small, so continue right. The candidate is returned only after the search path ends.

Find lowerBound(64), then lowerBound(91)

1 · Start at 50

2 · Candidate 70; inspect 60

3 · Replace candidate with 65

4 · No lower bound for 91

This is the ordered query used by Lecture 8 best fit: among capacities that fit an item, choose the least available capacity. Equal capacities require a tie-break such as bin index; the lecture stores (available capacity, bin index) records and allows duplicate capacities.

Deletion with physical removal and child-link repair

The three cases can be seen in one sequence. The starting shape contains a leaf (20), a one-child node (30), and then a two-child root whose predecessor (40) itself has a left child (35). Every stage identifies the node physically unlinked; copying a replacement key alone is not deletion.

Delete a leaf, a one-child node, then a two-child root

1 · Start before deletion

2 · Physically unlink leaf 20

3 · Splice the sole child while deleting 30

4 · Copy predecessor 40, then physically unlink it

If the requested key is missing, the search reaches null and remove reports absent without changing any link. For an empty tree, search/remove stop immediately. A root leaf deletion makes the root null; a one-child root deletion promotes that child into the root pointer. These are the same splice rules with the incoming link being the root reference.

For a two-child deletion, the predecessor is the maximum of the left subtree, so it has no right child; it may still have a left child, which must be spliced into the predecessor's former position as above. A successor (minimum of the right subtree) is a symmetric alternative, not the particular predecessor choice in the existing page. Both keep inorder order if the entire key/value pair is moved and the physically selected node is removed.

Repeated insertion versus sorted median construction

For already sorted keys 1 through 12, repeated ordinary insertion follows a right link at every comparison. The total comparisons are 1+2+…+11=66, namely n(n−1)/2, so this order takes Θ(n2) time and produces a height-12 chain. For an unsorted worst-case input, repeated insertion is O(n2) as well. The problem is the insertion order, not a failure of the BST ordering rule.

When a static balanced shape is wanted, recursively choose a median of each sorted interval. The following right-heavy median convention picks the upper median: root 7; its intervals [1,6] and [8,12] choose 4 and 10; recurse until intervals are empty. Inorder remains exactly [1,…,12], and the resulting height is 4 nodes. Sorting arbitrary input first costs O(nlogn); when input is already sorted, median construction alone costs O(n). This is a static bulk-build method, not an update guarantee for the ordinary BST.

Methods and decision table

Method Decision rule Stop condition and edge cases Cost for this plain BST
initialize / build by put Insert records one by one using key comparisons. Empty root accepts first key; equal key follows the API's update or duplicate policy. O(nh); O(n2) worst case, O(nlogn) expected only under a random-order model.
Static balanced build Sort if needed, then recursively attach interval medians. Empty interval returns null; decide duplicate handling before building. O(nlogn) including comparison sort, then O(n); O(n) from already sorted distinct keys. Supplemental shape-building method.
get(key) / search Compare with current key; smaller goes left, larger goes right. Equality returns the pair; null means missing; empty root misses immediately. O(h), O(n) worst case; Lecture 8 gives O(logn) expected for an ordinary BST and O(logn) worst case only for a balanced BST.
put(key,value) / insert Follow search path to equality or a null link. Equal key updates in a unique-key map; a multimap must specify duplicate order/identity. Null link creates one leaf. O(h), O(n) worst case.
remove(key) / delete Search; unlink a leaf, splice the sole child, or replace a two-child target with predecessor/successor and unlink that physical node. Missing key changes nothing; root reference must be updated; predecessor may have a left child (successor may have a right child). O(h), O(n) worst case.
findMin / findMax Follow left links / right links. Stop at the last non-null node; empty tree has no minimum or maximum. O(h), O(n) worst case.
lowerBound(x) Track candidate when key ≥ x and go left; otherwise go right. At null return best candidate or none; equality returns x itself. Duplicate keys need tie policy. O(h), O(n) worst case; supports Lecture 8's best-fit query.
ascend() / inorder Recursively emit left subtree, node, right subtree. Empty subtree emits nothing; result is sorted by key. O(n) time and O(h) recursion stack.
Range query [a,b] Prune left when node < a and prune right when node > b; emit in-range keys in inorder. Stop outside the requested interval; handle a>b as empty. O(h+k) with ordered pruning, where k records are reported; worst case O(n).
get(index) / remove(index) These are indexed-BST operations, not operations supplied by this plain node shape. Lecture 8 adds leftSize; compare index with leftSize, then recurse left, return at equality, or recurse right with index−leftSize−1. Check the index is in range. remove(index) selects the key, then uses ordinary BST deletion and repairs metadata. Plain traversal can select in O(n); indexed BST is O(h), O(n) worst if unbalanced. Lecture 8 gives O(logn) for indexed balanced BST.
General meld Inorder both BSTs, merge sorted records, then build a result. Define duplicate resolution and ownership; input ranges may overlap. Ω(n+m) element processing; merge and rebuilding are O(n+m). Lecture 8 states an Ω(n) merge lower bound when both input sizes are n.
Ordered join (special case) If every key in A < separator < every key in B, attach A and B beneath the separator. Preconditions must be checked/guaranteed; this is not general meld. A plain unbalanced BST may still need height-aware insertion to get a useful bound; the lecture does not specify a join algorithm or bound.

The lecture's expected O(logn) for an ordinary BST is an input-model expectation, not a per-tree guarantee. Actual path cost is O(h); a sorted insertion order gives h=n. Balanced BSTs have O(logn) worst-case dictionary operations, but that is a different structure with an extra balancing invariant. Do not call a plain BST's expected bound amortized.

Common mistakes

  • Equality is a successful search. In a unique-key map, updating that record does not add a node; in a duplicate-capable dictionary, use an explicit tie/identity rule.
  • For lower bound, a qualifying node is only a candidate until the left search is exhausted. Returning the first key ≥ x encountered can miss a smaller qualifying ancestor.
  • Deleting a two-child node has two identities to track: the logical target whose pair is replaced and the predecessor/successor node physically unlinked. Reconnect that node's possible child.
  • Copy the full pair, not just the key, or the key can become associated with the wrong element.
  • Inorder sortedness does not imply balance. A sorted right chain is still a valid BST and can have linear operation cost.
  • A median build is static construction. It does not make later ordinary inserts remain balanced.
  • A sorted-list merge lower bound concerns general meld; a join with a supplied separator and a strict key-range precondition is a different operation.

Exam focus

  • State the invariant as strict ordering: every key in left(x) is less than key(x), and every key in right(x) is greater.
  • Derive search, insert, delete, min, max and lowerBound costs from height h; worst-case h=n for a plain BST.
  • Search equality terminates successfully; reaching a null child terminates unsuccessfully.
  • The predecessor is max(left(target)); it has no right child. Its possible left child replaces it when the predecessor is physically removed.
  • Inorder traversal is sorted and costs O(n); range reporting costs O(h+k) with pruning.
  • Repeated sorted insertion has n(n−1)/2 comparisons; sorting plus median recursion is O(nlogn) for arbitrary keys, while median recursion is O(n) on already sorted keys.
  • Lecture 8: ordinary BST get/put/remove are O(n) worst and O(logn) expected; balanced BST gives O(logn) worst and expected. These expectations/bounds belong to different assumptions.
  • Lecture 8 best fit needs the least available capacity ≥ the item size, hence a lower-bound query over (capacity, bin index) pairs.

Practice questions

  1. Insert [8,3,10,1,6]. What is the path for get(6) and the inorder sequence?
Show answer

Path: 8 → 3 → 6, with comparisons <, >, =. Inorder is [1,3,6,8,10].

  1. In the 12-key tree, what does lowerBound(64) return, and why is 70 not the final answer?
Show answer

It returns 65. Node 70 becomes a candidate, but searching left reaches 60 then 65; 65 is a smaller key that still satisfies key ≥ 64.

  1. When deleting a two-child node with its predecessor, what child can the predecessor still have, and where does that child go?
Show answer

The predecessor can have a left child but cannot have a right child. When the predecessor is physically unlinked, its left child takes its former parent link.

  1. Why is building by ordinary insertion on sorted [1,…,12] quadratic, while building from that already sorted list by medians is linear?
Show answer

Ordinary insertion compares each new key against all previous chain nodes, totaling 1+…+11=66=12·11/2 key comparisons. Median recursion attaches each key once to a balanced shape, so it uses O(n) work when sorting is unnecessary.
