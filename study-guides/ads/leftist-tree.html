Leftist tree

Keep the right spine short. Meld walks along right spines and repairs the leftist rule on the way back.

RuleMeld, insert and removalArbitrary removal and caveatsDecisions, stop conditions, and edge casesWorked construction: ten keys with FIFO pairwise meldingArbitrary deletion: the lecture's pointer caseCommon mistakesExam focusPracticeSupplemental implementation detail: either parent link

Rule

s(null)=0 and s(x)=1+min(s(left),s(right)). Every node obeys s(left)≥s(right), so s(x)=s(right)+1. Add min-heap order to obtain a min leftist priority queue. Only the rightmost path is guaranteed O(logn). The whole tree can have linear height.

Fresh build from [7, 3, 9, 1] using a FIFO queue

Input list[7, 3, 9, 1]

1 · Make singleton trees

A singleton has no internal children, so both child s-values are 0 and its own s is 1. Put all four roots in input order; the FIFO contains one tree per key and the construction continues until exactly one root remains.

Meld roots 7 and 3

Remove the two front roots 7 and 3, compare them, and keep 3 as the smaller root. Its right child is empty, so recursive meld returns the whole 7-tree immediately; on unwind, compare s(left)=0 with s(right)=1, swap, and recompute s(3)=1. Enqueue after the untouched roots 9 and 1.

Meld roots 9 and 1

The queue front is now 9 then 1; root 1 wins and its empty right subtree returns 9. On unwind, swap because 0<1, giving 1 a left child of rank 1 and right rank 0, so s(1)=1. Append this result behind the still-waiting 3-tree.

Meld roots 3 and 1

Remove 3 and the merged 1-tree. Root 1 wins, and melding its empty right child with the 3-tree returns that tree; unwind at 1, whose old left child 9 and joined right tree rooted at 3 both have s=1, so equality means no swap. Recompute s(1)=2; one root remains, which is the exact stop condition for FIFO initialization.

Meld, insert and removal

Meld chooses the smaller root a, recursively melds a.right with the other tree, then swaps a's children if s(left)<s(right). Recompute s after the swap. An empty argument returns the other tree.

insert(x) = meld(heap, singleton(x)). removeMin deletes the root and melds its two children. Each costs O(logn), as does meld. Fresh FIFO pairwise construction costs O(n). Repeated insertion costs O(nlogn). getMin is O(1), general search O(n).

Meld [2 with left child 7] and [3 with left child 5]

Input list[2 with left child 7] · [3 with left child 5]

1 · Compare roots

Compare 2 and 3; 2 wins and its empty right subtree is the next recursive argument. Meld therefore returns the entire 3-tree unchanged, preserving its internal heap and leftist invariants; unwind at 2 by attaching this result on the right.

2 · Attach returned tree on the right

After attachment, the left subtree 7 and the joined right subtree rooted at 3 both have s=1. Since s(left) is not less than s(right), keep the child order and set s(2)=1+min(1,1)=2. Equality is a valid no-swap case.

3 · Remove minimum 2

Removing minimum 2 exposes its two child heaps, rooted at 7 and 3. Meld chooses 3 as the new root and recursively joins its empty right child with 7; the returned tree becomes its right child. Its left child 5 has s=1 and its right child 7 has s=1, so no swap is needed and the removal stops with a valid heap.

Arbitrary removal and caveats

Given node x, the lecture detaches x, reconnects its left subtree into the remaining tree, repairs s-values and leftist order toward the root, then melds the remainder with x's right subtree. The lecture prescribes repairing s and leftist order from p to the root but gives no separate runtime bound. Parent links make that path accessible; a naive walk to the root can take O(n), because total height is not bounded. Any logarithmic early-stop bound needs an additional implementation argument.

The empty build returns empty. A singleton has s=1. Do not use “left subtree has more nodes” as the invariant. After a destructive meld, the donor heap must relinquish ownership of its nodes.

Can a valid leftist tree be a long chain?

Check your answer

Yes, a left-only chain. Each node then has an empty right child, s=1, and the right spine is still short.

Decisions, stop conditions, and edge cases

Method Decision and stop condition Edge cases and cost
getMin Read the root; stop immediately. Empty heap has no minimum. Nonempty lookup is Θ(1).
Search for an arbitrary key Traverse nodes until the key is found or every reachable node has been checked. Heap order only rules out descendants of a node whose key is already greater than the target; it does not give BST-style routing. Missing key requires checking the whole heap in the worst case: Θ(n). This is a scan, not a handle operation.
meld(A,B) Return the other tree if either input is empty. Otherwise keep the smaller root, recursively meld its right subtree with the other heap, attach the result on the right, swap children exactly when s(left)<s(right), then recompute s. Stop when one recursive input is empty. Equal roots may choose either root if ties are handled consistently. Inputs must use the same min/max order and compatible ownership; a destructive meld consumes both inputs. Worst-case Θ(logn), because recursion follows right spines.
insert(x) / put(x) Make a singleton of rank 1 and meld it with the heap. Stop at meld's empty-input base case and unwind repairs. Empty heap becomes that singleton. Θ(logn) worst case.
removeMin Save/remove the root and meld its left and right subtrees. Empty heap has nothing to remove; one node returns empty. Θ(logn) worst case.
initialize from n keys Make n singleton heaps in input order; repeatedly dequeue the first two, meld, enqueue the result; stop at one queued tree. n=0 returns empty; n=1 returns the singleton. FIFO pairwise initialization is Θ(n) overall per the lecture; repeated individual insertions instead cost Θ(nlogn).
Arbitrary remove by node handle If the handle is the root, use removeMin. For a nonroot target x with parent p, the lecture's pictured case makes x's left subtree L the right child of p, repairs s and leftist order from p toward the root, then melds that remainder with x's right subtree R. Missing/stale handle is outside the lecture procedure and must be rejected by the caller. Lecture slide 34 draws x on p's right link; it does not spell out the left-child-link case, the supplemental implementation detail below handles either parent link explicitly. Parent pointers are required. Cost is path-dependent; the slide gives no standalone bound.

For every nonempty node, s(x)=1+min(s(left),s(right)); leftist order requires s(left)≥s(right), which makes s(x)=s(right)+1. Thus the rightmost path is shortest and logarithmic, while a left-only chain may have linear total height. Meld and insert/remove-min have logarithmic worst-case bounds from that right-spine guarantee; the whole-tree height is not a valid bound for them. The course gives no separate asymptotic bound for arbitrary removal's upward repair, so do not transfer the meld bound to a parent walk without the implementation's early-stop argument.

The examples use min order. The lecture also defines max-leftist priority queues: reverse the root-priority comparison while keeping the same s-value recurrence and leftist shape invariant.

The final queue has one tree containing all ten keys. Its computed rank is bounded by the node count and is exactly the length measure controlled by the right spine.

Arbitrary deletion: the lecture's pointer case

The arbitrary-remove slides distinguish x=root from x≠root. In the latter pictured case, x is p's right child. Let p's other child be B and x's children be L and R. Reconnect L at p's right link first, repair ranks and child order up the ancestor path, then meld the repaired remainder with R. That order matters: it restores the existing tree before adding the detached right subtree.

Stage Parent p Target x Remaining root-side tree Detached piece
Before p(B, x) x(L, R) ... → p L, R
Reconnect L p(B, L) detached same ancestors R
Repair recompute s and swap at each affected ancestor if left s < right s — stop when the repair has no further effect or reaches the root R
Finish — removed meld(repaired remainder, R) consumed by meld

This handle-based operation assumes x is a live node in this heap and has a parent pointer. A key-only request first needs a search, which can cost Θ(n). The supplemental rule is to replace whichever parent pointer currently refers to x: p.left when x is a left child, otherwise p.right. This extends the pictured case without changing the meld algorithm. For x at the root, remove-min is the source-supported special case. For a one-child target, the absent child is simply the empty tree with s=0, but the parent-link reconnection still follows the implementation's child-side rule.

Common mistakes

  • The invariant compares shortest-path ranks, not subtree sizes. A left subtree may have fewer nodes and still be the correct left child if its s-value is at least the right one's.
  • Meld recurses through the right child of the smaller root. It does not recursively merge both children.
  • The swap test is strict: equal child ranks do not require a swap. Recompute s after the resulting child order is known.
  • The entire tree may be tall. Only the rightmost path has the logarithmic guarantee used in the meld analysis.
  • In FIFO initialization, enqueue each melded result at the back and stop at one queued heap. This is not the same schedule as repeated insertion.
  • A destructive meld transfers ownership. Keeping both input roots as independently mutable heaps would allow shared nodes to be modified twice.

Exam focus

Remember the base cases, smaller-root decision, right-subtree recursion, strict rank comparison, child swap, and rank recomputation in that order. For complexity questions, state the operation and cost model: getMin Θ(1); search Θ(n) worst case; meld, insert, and remove-min Θ(logn) worst case; FIFO build Θ(n); repeated insertion Θ(nlogn). Explain why the right spine is logarithmic from n≥2s(root)−1. Do not claim a whole-tree logarithmic height.

Practice

If a node has s(left)=2 and s(right)=3 after melding, what changes on unwind?

Answer

Swap the children because 2<3. The new left rank is 3 and right rank is 2, so the node's rank becomes 1+2=3. Heap order remains valid because the melded subtree was attached beneath the smaller root.

When does the FIFO initializer stop, and what is its queue for an empty input?

Answer

It stops when one tree remains. For empty input the queue begins empty, so initialization returns empty without attempting to dequeue a pair.

Why can arbitrary key search not use the same logarithmic bound as meld?

Answer

Heap order exposes a global minimum but does not order keys left-to-right. The target may be in either subtree, so a missing-key search may visit all n nodes.

Supplemental implementation detail: either parent link

For a live nonroot handle x, remember its parent p and its children L and R. Replace the same parent link that pointed to x by L: use p.left if x was the left child, otherwise p.right. Set L.parent=p when L exists, detach R as a separate heap, and invalidate x's handle. The remaining parent edge is heap-ordered because p ≤ x ≤ every key in L.

Walk upward from p. At each node, swap children if s(left)<s(right), repair their parent pointers, and recompute s. Stop when that node's s does not change, because its parent observes only that rank; otherwise continue to its parent. Finally meld the repaired root-side heap with R. If x is the root, simply meld its two children. Empty children use rank zero; a stale or foreign handle must be rejected before touching links.

This is an implementation explanation beyond the single pointer case drawn in the lecture. With early stopping, every ancestor whose rank changes had old rank strictly greater than the old rank of the changed child along the propagation path. Such a chain has O(logn) ranks because a rank-s subtree has at least 2s−1 nodes. Therefore the rank repair plus final meld takes O(logn) with a known valid handle. A routine that walks all the way to the root regardless of rank changes may still take O(n), since total height can be linear.
