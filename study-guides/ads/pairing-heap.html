Pairing heap

Keep one heap-ordered tree. Compare-link makes meld simple, while two-pass pairing makes removal efficient over a sequence.

Rule and fresh build

The lecture demonstrates a max pairing heap. Compare roots and make the smaller-root tree the leftmost child of the larger root. Nodes have child and sibling links, with no degree, mark or separate parent field. The first child's left link points to its parent, while later left links point to a sibling.

Build from a fresh list [7, 3, 9, 1]

Input list[7, 3, 9, 1]

1 · Read 7

The empty heap has no root, so the first record 7 becomes the singleton root; there is no comparison and insertion stops with one record.

2 · Read 3

Compare the two roots 7 and 3. Since 7 is larger, it remains root and the entire singleton 3 becomes its leftmost child; no descendant comparisons are needed, and the max-order invariant is restored.

3 · Read 9

Compare roots 7 and 9. The new root 9 wins, so the entire prior 7-tree, including child 3, becomes one child subtree of 9; preserving that subtree avoids changing its valid internal order.

4 · Read 1

Compare roots 9 and 1. Root 9 wins, and singleton 1 is prepended ahead of the existing 7-tree, so the children are [1, 7(3)]. Every child root is at most 9, so this insertion ends.

Operations and complexity

Actual insert, meld and priority improvement are O(1). getMax is O(1). removeMax and remove(handle) can take O(n) actual time. The course's amortized table gives O(logn) for insert, meld, removal and priority improvement. These are the course's conservative amortized charges; do not read a constant actual bound as an independently assignable constant amortized bound for every operation in that table.

For increaseKey in the max version, detach a nonroot subtree and compare-link it with the remaining tree. No parent comparison is needed. General search costs O(n). To delete a nonroot, detach it, combine its children with a good pairing scheme, then meld the result with the original remainder.

removeMax: two-pass pairing of children [8, 6, 4, 2, 1]

Input list[8, 6, 4, 2, 1]

1 · Remove old root 9

Removing root 9 exposes its five child roots in the shown order [8,6,4,2,1]. Keep each complete child subtree intact; empty removal would fail, while no children would yield empty and a single child would be returned directly.

2 · Pass 1: pair left to right

Pass 1 scans left to right and links disjoint original pairs: 8 beats 6, and 4 beats 2. Their losing trees become leftmost children, leaving the original fifth tree rooted at 1 unmatched; do not begin pass 2 yet.

3 · Apply the lecture odd-child rule

The lecture odd-child rule links the unmatched original root 1 with the last generated pass-1 tree rooted at 4. Since 4 wins, 1 is prepended before 2, producing 4(1,2); pass 1 now has two roots, 8 and 4.

4 · Pass 2: combine right to left

Start pass 2 with the rightmost generated tree 4(1,2), then meld the remaining root 8 into it. Root 8 wins and takes the complete 4-tree as its leftmost child before existing child 6; no roots remain, so 8 is the maximum.

Multipass, caveats and exam focus

Multipass puts all child trees into a FIFO queue and repeatedly removes two, melds them, and enqueues the result. Both good schemes obtain the course's logarithmic amortized removal bound. Simply folding every child into a running tree from left to right can lead to Θ(n2) total removal work.

Descending inserts in a max heap can produce degree n−1. Ascending inserts can produce a chain. Low metadata does not mean logarithmic height. Empty removal fails, a singleton removal returns empty, and a one-child removal returns that child directly.

What differs between meld and consolidation?

Check your answer

Pairing-heap meld links any two roots. Binomial/Fibonacci consolidation repeatedly links roots only when their degrees are equal.

Big picture: compare-link and pointer invariants

A max pairing heap stores a max-heap-ordered multiway tree. Every parent key is at least each child key, but siblings have no required ordering and the tree need not be balanced. A compare-link looks at only two roots: the larger stays root and the smaller-rooted whole tree is prepended to its child list. On equal roots, either can stay root if the implementation applies the tie rule consistently.

The node representation has a pointer to its first child and a non-circular doubly linked sibling list. The first child's left link refers to the parent; later siblings' left links refer to the preceding sibling. There is no parent, degree, or child-cut field. A cut must therefore repair the previous/right link and next/left link carefully; if the removed node was first, the new first child's left link must point to the parent.

The original four build states and four two-pass states now explain each comparison, link order, and stop condition. The following fresh build, cut, deletion, even-child, and queue examples are supplemental walkthroughs of the lecture's stated methods; they do not introduce another pairing-heap variant.

Compare-link and removeMax edge cases

1 · Meld an empty heap with the tree rooted at 6

There is no root comparison when one side is empty. The tree rooted at 6 and its child 4 remain intact, so meld stops immediately.

2 · Compare equal roots 8A and 8B

The roots tie, so either is valid as parent. This walkthrough consistently keeps the first argument; equality still satisfies max order, and the link stops after one root decision.

3 · Remove a root with one child

No consolidation link is needed for one child. Preserve that entire child tree unchanged and stop.

4 · Remove a singleton root

There are no child roots to consolidate, so the result is empty. A removeMax request on an already empty heap instead fails without mutation.

Supplemental increase-key trace: cut the known handle, then meld

For a max pairing heap, raising the root key cannot violate heap order, so the root can be updated in place. For a nonroot handle, the lecture avoids a parent-key check: detach the entire subtree rooted at the handle from its sibling list, raise its key, and compare-link that tree with the remaining heap. Do not search by key when a valid handle is available; key-only lookup is linear in the worst case because heap order does not route a search.

Here the middle child 14 is cut from the list 17:[6,14,2,9,12(4)]. Its neighbors 6 and 2 are joined as siblings; the remaining subtree rooted at 17 stays under 20. Raising 14 to 22 then makes it the new root. These are two distinct state changes: first repair sibling links, then compare-link the raised subtree.

Increase key of middle child 14 to 22

1 · Before the cut

The handle is the nonroot node 14. Its old key is below parent 17, so the heap is valid before the update; the cut is needed because the new key may exceed 17.

2 · Detach 14 and repair its sibling list

Set 6.right to 2 and 2.left to 6. Since 14 was neither first nor last, the parent first-child pointer stays 6; the detached subtree is now a separate root.

3 · Raise the detached root to 22

Only the detached root key changes. The remaining tree still satisfies heap order; compare-link is the next required operation.

4 · Meld the raised subtree with the remainder

Compare roots 22 and 20. Root 22 wins and takes the remainder as one child, restoring max order. This uses constant actual pointer/comparison work for a valid handle; the course amortized table still assigns O(logn).

Supplemental handle-delete trace: detach, combine its children, meld

The existing page summarizes nonroot deletion as unlinking the target, combining its children, and melding that result with the original remainder; Lecture 7 lists remove costs but does not specify a separate delete-by-handle trace. This supplemental worked trace makes the page's summary concrete without claiming another course variant. First unlink the target subtree from its sibling list, then consolidate that target's child roots, and finally meld the consolidated result with the original remainder. The example deletes node 12, whose only child is 4. With one child, consolidation returns 4 directly; the final root comparison prepends 4 under 20. Empty child list similarly returns empty, while two or more children use one of the stated good pairing schemes.

Delete handle 12, which has child 4

1 · Locate the supplied handle in the state

A known live handle avoids a key search. To delete by key instead, first scan; missing key means no mutation and the scan may visit every node.

2 · Cut subtree 12 from parent 17

Set 9.right to empty; there is no next sibling to update. Because 12 was last, 17.child is unchanged. Keep detached child 4 for consolidation.

3 · Consolidate the single child of 12

Zero child trees would produce empty. Here the only tree rooted at 4 is the consolidated replacement.

4 · Meld replacement 4 with the remaining heap

Compare 20 with 4; 20 wins and the replacement tree is prepended to its children. The result contains nine keys and preserves heap order; stop after this root link.

Supplemental nonroot deletion with several children

The prior delete example showed the one-child shortcut. This contrasting example deletes handle 17, whose detached subtree has five child trees. It demonstrates that child consolidation happens before the replacement is melded with the remaining heap, and it exercises the odd-child rule inside arbitrary deletion.

Delete nonroot handle 17 with five child trees

1 · Detach the target subtree rooted at 17

Unlink last child 17 from root 20’s sibling list by setting 11.right to empty; there is no next sibling to repair. The untouched remainder is 20(3,11); keep all five child trees in their original order.

Compare the first two original roots; 14 wins. Continue to the next original pair while 2, 9, and 12 remain.

Compare the next disjoint pair; 9 wins. Since the original count was odd, do not begin pass 2: first meld unmatched original 12 with the last generated root 9.

Start with rightmost generated root 12 and link remaining root 14 into it. Root 14 wins; no pass-1 trees remain.

Compare remainder root 20 with replacement root 14. Root 20 wins and prepends the replacement before children 3 and 11. The nine remaining records are heap-ordered, so deletion ends.

FIFO multipass removal and the bad fold contrast

Multipass places child trees in a FIFO queue, repeatedly removes the first two, links them, and appends the result. The queue order is part of the algorithm. The following states use eight singleton child roots so every dequeue, link, and enqueue is inspectable.

An unbalanced left-to-right fold also links each next tree to the accumulated root, but it is the lecture's bad removal scheme: across the stated sequence of n inserts followed by n removals, the removal work sums to 1+2+...+(n−1)=Θ(n²). A single compare-link remains constant actual work; repeatedly paying to inspect/remeld a growing child list causes the bad sequence total. Do not substitute this fold for either good consolidation method.

Method decisions and stop conditions

Method Decision and stop condition Edge cases and cost
getMax Read the root and stop. Empty heap has no maximum; nonempty actual cost Θ(1).
Search by key Traverse reachable nodes until a match or exhaustion; heap order can prune only where a node is already below the sought value. Missing key may require Θ(n); this is distinct from a handle operation.
compareLink(A,B) If either is empty, return the other. Otherwise compare roots and prepend the smaller-rooted whole tree under the larger root; stop after one link. Equal roots allow either winner under a consistent tie policy. Actual cost Θ(1), independent of subtree sizes.
insert(x) Create singleton x and compare-link with the current root; stop after one link. Empty heap becomes x. Duplicate priorities are allowed. Θ(1) actual.
meld(A,B) Compare-link the two roots; stop after one link. Either empty input returns the other. Inputs must use max ordering and must not alias the same live node set. Θ(1) actual.
increaseKey(handle, amount) Root handle: update in place. Nonroot: unlink its whole subtree from siblings, update its root key, then compare-link with remainder; stop after link. First/middle/last child require appropriate neighbor updates. A valid handle is assumed; lookup by key adds Θ(n) worst-case search. Θ(1) actual; course amortized table gives O(logn).
removeMax Fail if empty; otherwise remove root and consolidate its child forest with two-pass or FIFO multipass; stop at one tree. Zero children → empty; one child → that tree. Actual cost can be Θ(n); course good-scheme amortized bound is O(logn).
Two-pass consolidation Pair original roots left-to-right. If odd, meld the last original root with the last newly generated tree. Then start at rightmost generated tree and fold remaining roots right-to-left; stop with one tree. Explicit odd rule matters; pass order is not interchangeable. Good lecture scheme has O(logn) amortized removeMax.
FIFO multipass consolidation Enqueue children in sibling order; dequeue two, compare-link, enqueue result; stop when queue size is one (or zero). Empty and singleton queues need no link. Good lecture scheme; same asymptotic bound as two-pass.
Bad running-tree fold Start from first child and meld each remaining child into the growing tree; stop when input list ends. Simple but lecture gives Θ(n) amortized removal and an n-insert/n-remove sequence with Θ(n2) removal work. Do not claim the good-scheme bound.
remove(handle) for nonroot Unlink target, consolidate its children with a good scheme, then compare-link that result with the original remainder. Root handle is removeMax; a missing/stale handle must be rejected. Empty child forest contributes nothing; a single child returns directly. Actual can be Θ(n); course amortized charge is O(logn).
Build from n records Apply n individual insertions; stop after the last singleton has been compare-linked (the first singleton becomes the root directly). Empty input returns empty, singleton returns itself. The lecture does not define a separate bulk build. The n insertions use O(n) actual work; the course amortized table charges O(logn) per insert.

Complexity and shape distinctions

The course tables distinguish actual and amortized costs. The lecture's actual table gives Θ(1) insert, meld, and increase-key, with Θ(n) possible remove and removeMax. Its conservative amortized table gives O(logn) for insert, meld, remove, removeMax, and priority improvement. Keep that course assignment intact; do not infer a tighter amortized charge from a single operation's actual pointer count. Good two-pass and multipass schemes are the removal choices associated with the logarithmic amortized bound. The naive fold has a separate worse sequence bound.

The heap is not balanced: descending max-heap inserts can produce degree n−1, while ascending inserts can produce height n. Thus key search remains linear worst case even though root access, insert, and meld take constant actual work. Compare-link works on arbitrary root keys; unlike binomial or Fibonacci consolidation, it never requires equal degree because pairing nodes store no degree.

Common mistakes

  • Treating siblings as ordered by key. Only parent-to-child heap order is required.
  • Detaching a nonroot without repairing both sibling directions, or failing to point a new first child's left link back to its parent.
  • Applying increase-key directly to a nonroot and assuming its parent relation remains valid.
  • Reversing the two-pass traversal or forgetting to meld an odd leftover with the last generated tree.
  • Calling multipass a left fold; it is a FIFO queue process.
  • Claiming logarithmic height or logarithmic actual removal. Pairing heaps can be linear in height and degree.
  • Confusing a known handle with key search, or the course's conservative amortized table with an expected bound.

Exam focus

Remember compare-link: larger root wins; smaller-root tree becomes leftmost child. Insert and meld use one compare-link. Increase-key cuts a nonroot subtree and melds it. removeMax removes the root, then uses two-pass or FIFO multipass consolidation. Two-pass first pairs left-to-right, handles an odd original root as specified, then folds generated roots right-to-left. Good schemes have O(logn) course amortized removal; actual removal can be O(n). General search is O(n), and no degree/mark/parent fields are stored.

Practice questions

How does a cut differ when the target is the first child versus a middle sibling?

Check your answer

For the first child, update the parent's child pointer and make the new first child's left link refer to the parent. For a middle sibling, link its previous sibling directly to its next sibling in both directions. In either case detach the entire target subtree before melding.

With four child roots, how many pass-1 trees remain, and does the odd-child rule apply?

Check your answer

Two generated trees remain; the original count is even, so there is no unmatched original child. Pass 2 starts with the rightmost generated tree.

What is the tie rule for equal roots in max compare-link?

Check your answer

Either equal root can remain parent because equality preserves max-heap order. The implementation should choose consistently, and the losing tree becomes the winner's leftmost child.
