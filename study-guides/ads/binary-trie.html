Binary trie

Branch nodes inspect bits; element nodes hold records. A lookup makes at most one full-key comparison at its candidate leaf.

Rule and representation

Fixed-length branch nodes have two child pointers and no record. Element nodes have a whole key/value pair and no children. Unary branch paths are allowed. Branch by one bit at each level. A singleton subtree can point directly to its element node, but a final full-key check is still required.

Fresh build from [0001, 0011, 1000, 1001]

Input list[0001, 0011, 1000, 1001]

1 · First key 0001

At bit 1 the zero pointer is empty, so store 0001 there and stop; a singleton does not need trailing branches. The only stored key is reachable and its leaf still needs a full-key comparison on search.

2 · Insert 0011; expand shared prefix

The existing leaf is 0001. Compare the fixed-width keys to find their first difference at bit 3, then add branch levels 1, 2, and 3; the final branch sends 0001 left and 0011 right. Continue until that first differing bit is represented, then stop with both records at leaves.

3 · Insert 1000

Bits 1–3 of 1000 route to the empty right pointer at the root, so store one singleton leaf directly. Do not add a unary suffix for bits 2–4: there is no collision to separate. The existing 0001/0011 split remains unchanged.

4 · Insert 1001; expand the right prefix

The query reaches singleton 1000 through bit 1 = 1. Its first mismatch with 1001 is bit 4, so expand the common route at bits 2 and 3 and split at bit 4. Stop once the leaves are distinct; all eight shared-prefix branch levels shown in the two subtrees inspect the correct key positions.

Operations

Search follows query bits, then compares the reached element key once. Insert into an empty branch directly; on collision with an element, expand common bits until the keys separate. Delete verifies the leaf, removes it, and collapses the redundant path where the sibling is a single element. Unary paths to a multi-element subtree still encode useful bit positions.

Bit-routing cost is O(W) per operation, with a final O(W) full-key check if W-bit comparison is charged by bit. Build from n keys is O(nW). Uncompressed branch storage can also be O(nW). Meld by inserting the donor keys costs O(mW). Minimum/maximum, prefix listing and order statistics need suitable traversal or augmentation.

Search missing 0010, then delete 1001

1 · Follow the prefix 001

Route 0010 by bit 1 = 0, bit 2 = 0, bit 3 = 1. The leaf is candidate 0011; routing alone has not proved membership. Continue to exactly one whole-key comparison.

2 · Compare once

The candidate and query are both four bits, but differ at bit 4. This single equality check ends the search as absent; do not continue from the leaf or compare against other records.

3 · Delete 1001 after the candidate check

Route to candidate 1001 and compare the full key once before deletion. Remove only that verified leaf; its sibling 1000 is a singleton, so pruning can proceed upward. Continue to the separate bit-4 cut state rather than treating several pointer changes as one transition.

4 · Cut bit-4 branch

The surviving sibling is element 1000, not a multi-key branch, so remove bit 4 and promote 1000 to the bit-3 subtree. Continue because bit 3 now also has just this singleton child.

5 · Cut bit-3 branch

Bit 3 has no second child after promotion, so cut it and attach 1000 at bit 2. The left side remains a two-key subtree; continue pruning only the right-side path.

6 · Cut bit-2 branch and stop

Bit 2 also has only singleton 1000, so cut it and promote the leaf to the root's right pointer. Stop: root bit 1 still separates 1000 from 0001 and 0011. The final leaf set is {0001, 0011, 1000}; only the deleted 1001 is absent.

Variable-length keys and caveats

Lecture 12's variable-length form adds left-pair and right-pair fields, recording a key that terminates on that branch even if a longer key continues below. Supplemental equivalent: use terminal markers at nodes. Deleting a prefix key must not remove its longer descendants. Keep zero-length keys or sentinels distinct from “no record.”

Do not confuse the number of full-key comparisons with the number of bit tests. One full-key comparison can still follow many branch steps.

Eight-key fixed-width construction

Insert the 4-bit keys in order: [0000, 1000, 0100, 0010, 0001, 1110, 1111, 1100]. Each circle is a branch that tests its labeled bit; each leaf stores one whole key. The final pair 1110/1111 forces every common level through bit 3 to be explicit before bit 4 splits them. During that expansion, intermediate states retain the old leaf while the new key is pending.

Leaf deletion: each singleton cut is a state

Starting with only [1110, 1111], the two keys share bits 1–3 and split at bit 4. Delete 1111. The verified leaf is removed first, then bit 4, bit 3, bit 2, and bit 1 are cut in separate states because each remaining subtree is the singleton 1110. This is the course's fixed-length leaf representation; branches above a multi-key sibling must remain.

Delete 1111 from the shared-prefix pair

1 · Route 1111; compare the one candidate

Branch choices at bits 1–4 reach leaf 1111. One full-key comparison succeeds; stop routing, then remove only this verified leaf.

2 · Remove leaf 1111

The equality check authorized removal of exactly 1111. Keep the current branch levels temporarily so the next state can show each singleton-path cut; 1110 is still reachable and no other record exists.

3 · Cut bit-4 branch

The surviving sibling at bit 4 is the element 1110, not a multi-key subtree. Replace that branch by its singleton pointer and continue upward; the subtree still represents exactly {1110}.

4 · Cut bit-3 branch

Bit 3 now has only the singleton child 1110, so cut it as a separate pointer update. Continue upward because bit 2 also leads to no competing record.

5 · Cut bit-2 branch

Bit 2 has only the singleton child 1110, so remove it as a separate pointer update. The root still contains a redundant one-child path; continue pruning.

6 · Cut bit-1 branch and stop

Bit 1 also leads only to singleton 1110, so promote that leaf to the root and stop. It remains searchable with one full-key comparison. If the final key were deleted, the root would instead become empty.

Two different unsuccessful searches

A null pointer and a mismatching singleton are different stop states: the first makes zero full-key comparisons; the second makes exactly one.

Missing branch versus unequal candidate

1 · Null branch: query 1010 in the {1110, 1111} trie

Bit 1 = 1 reaches the shared-prefix subtree; bit 2 = 0 has no child. Stop immediately with no full-key comparison and no mutation. The diagram distinguishes a missing pointer from a leaf mismatch.

2 · Leaf mismatch: query 1101 in the eight-key trie

The query follows 1, 1, 0 to leaf 1100. Since the pointer is nonnull, compare the whole candidate once; bit 4 differs, so report absent. Do not search another leaf.

Lecture 12 fixed-delete cases

Lecture delete: 0111 from the seven-key example

1 · Route 0111 to its leaf

Follow bit 1 = 0 and bit 2 = 1 to leaf 0111, then compare the full key once. Equality permits deleting this record; stop routing and remove only this leaf.

2 · Remove 0111; retain the bit-2 unary route

After removing 0111, bit 2 has one child, but that child is a branch containing 0001 and 0011. Keep the unary path: it still selects their bit-3 decisions. Stop pruning here; collapsing this node would lose a meaningful bit position.

Lecture delete: 1100 from the remaining six-key example

1 · Route 1100 to its leaf

Route using bit choices 1, 1, 0, 0 and compare candidate 1100 once. The keys 1100 and 1101 share the first three bits, so the bit-4 branch distinguishes the target from its sibling.

2 · Remove 1100

Remove exactly the verified 1100 leaf. Keep the bit-4 node for one explicit state; its sibling 1101 is a singleton and is the candidate for promotion.

3 · Cut bit-4 branch

The remaining child at bit 4 is the element 1101, so remove bit 4 and attach that leaf at the bit-3 position. Continue pruning this singleton path; the left side of bit 2 still contains 1000 and 1001.

4 · Cut bit-3 branch and stop

Bit 3 now leads only to singleton 1101, so remove it. Stop at bit 2 because its left child is the multi-element 1000/1001 subtree and its right child is 1101; both routes remain necessary.

Lecture 12 fixed-insert cases

Lecture insertion: 0111 and then 1101

1 · Insert 0111 into the empty pointer

At bit 1 = 0, bit 2 = 1 the pointer is empty, so store 0111 directly. No candidate leaf exists and the lecture's count is zero key comparisons; stop without expanding a singleton.

2 · Route 1101 to candidate 1100

Follow bit 1 = 1 and bit 2 = 1 to the only candidate 1100. Compare once to establish that the keys differ at bit 4; continue to represent their shared bit 3 before splitting.

3 · Expand their shared prefix at bit 3

Both keys have bit 3 = 0, so insert a bit-3 branch and retain 1100 beneath its zero pointer. This is an intermediate state, not completion: the new key is still pending until bit 4 separates the leaves.

4 · Split at bit 4; finish with one comparison

At bit 4, 1100 takes zero and 1101 takes one. Both records now have distinct leaves, so insertion stops. The full-key candidate comparison is exactly one, matching the lecture's slide 16 count.

Search, duplicate, and missing-key checks

Routing inspects only the bit named by each branch. When it reaches a leaf, compare the entire query with that one candidate once; a mismatch is absence. If a chosen pointer is null, absence is known without a full-key comparison. For example, after inserting only 1110 and 1111, query 1010 takes bit 1 = 1 and then the empty bit-2 = 0 pointer, so it stops with no candidate and zero full-key comparisons. In the eight-key tree, query 1101 reaches candidate 1100 and fails its one full-key equality check.

Inserting an existing key such as 1110 reaches that same leaf and updates/replaces its associated value; it must not create a second equal leaf. Deleting a missing key follows the same search rule and changes no pointer: a null branch stops immediately, while a different leaf candidate fails one final comparison. Deleting the final element makes the root empty. For W-bit keys, route depth is at most W; the lecture's “at most one key comparison” counts whole-key comparisons separately from bit tests. If a whole-key equality costs O(W), an unsuccessful candidate check adds O(W) bit work.

Variable-length keys: lecture pair fields

The lecture's representation retains left and right child pointers and a left-pair and right-pair field at each branch. A pair field stores the key that terminates at the root of that branch's corresponding subtree, or the one pair that would otherwise be that subtree; it is null when neither applies. This lets a shorter key coexist with descendants. In the following exact state, key 0 is stored in the root's left-pair field while longer 00 and 001 continue through the left child; similarly 1 terminates in the right-pair field while 10 and 101 continue below it.

For a query, follow bits while remembering the applicable pair candidate; after routing, compare the full variable-length key against the one candidate. A query 00 returns the pair in the prefix-0 branch, while 000 may reach that same prefix candidate but fails the full-key comparison. Deleting 00 clears only that pair field: the child holding 001 stays reachable. A childless branch whose other pair field is also null can be removed; a branch with a descendant must remain. Method decisions and bounds

Method Decision and cost Stop condition and edge cases
Build Insert each fixed-width key into the current root; for n keys and width W, the repeated-insertion bound is O(nW) bit-routing work. Finish after every input key is stored once. Empty input leaves an empty root; duplicate policy must be explicit (update the value rather than add a duplicate key).
Search, fixed width Follow one bit edge per branch and perform at most one full-key equality check at the reached leaf. Routing is O(W); charging a W-bit equality separately gives up to O(W) more bit work. Stop at a null pointer (no candidate, zero full-key comparisons) or after the one leaf comparison (equal = found, unequal = absent).
Insert, fixed width Use an empty pointer directly; if a leaf is reached, find the first differing bit and add every shared-prefix branch level through the split. Worst-case O(W) bit work; no leaf expansion is needed for an empty pointer. Stop when the new leaf has a distinct path. Duplicate full key updates its value. The lecture's fixed-width method allows unary paths.
Delete, fixed width Search to a candidate, compare once, then remove only an equal leaf. Cut upward while the surviving sibling is a singleton element; retain a unary route to a multi-element subtree. O(W) route/update levels, plus at most one full-key check. Stop at a null pointer or unequal leaf without mutation; stop pruning when both sides remain or the sole child is a branch. Deleting the last key makes the root empty.
Variable-length search/insert/delete Lecture representation uses child pointers and left/right pair fields so a key can terminate while longer keys continue (slides 11–12). The slides give at most one key comparison for search, not a separate operation-cost analysis. Check the terminating-pair candidate; deleting a prefix clears its pair but preserves descendant pointers. Null pair is not an empty-string key. Deletion slide 24 is only an exercise, so the cleanup rule here is a direct representation consequence, not a printed trace.
Meld Supplemental: enumerate donor records and insert each into the receiver; O(mW) for m donor keys at width W. Stop when each donor record has been inserted once. Duplicate-key value resolution is application-defined; the lecture does not give a structural meld.
Minimum/maximum No dedicated method is stated. Supplemental traversal can choose 0/1 branches, but must account for absent children and candidate leaves. Return an extreme only after considering the reachable leaves (or a maintained augmentation). No O(1) bound is claimed.
Prefix listing / order statistics No dedicated method or augmentation is stated. Enumerate all descendants under a prefix for listing; rank/select requires counts or another suitable augmentation. A prefix can end at a singleton pointer; variable-length keys also require reporting a terminating pair. No bound is claimed for unaugmented order statistics.

The uncompressed branch count can be O(nW) in the worst case; this is a structural upper bound, not a claim that every input uses that much space. One candidate comparison and O(W) routing are different counts. The lecture does not specify a duplicate-value policy, a general meld, min/max, prefix enumeration, or order-statistics algorithm; those rows are clearly identified as supplemental where applicable.

Common mistakes and exam focus

  • A reached element is a candidate, not proof of membership: perform the single whole-key comparison.
  • Shared prefix bits must appear in branch levels after a leaf collision; a single key can be stored directly without a trailing unary chain.
  • Deletion removes a verified leaf. Cut a branch only when the surviving child is one element; preserve a unary route to a multi-element subtree.
  • Variable-length keys need termination data. In Lecture 12 the data is held in left-pair/right-pair fields; clearing a prefix pair must not delete its longer descendants.
  • “At most one key comparison” does not mean one bit test. Routing can inspect up to W bits, and a full W-bit equality may itself cost O(W).

Exam focus: distinguish branch nodes (two pointers, no record) from element nodes (whole pair, no child pointers); explain first-difference expansion, final candidate equality, leaf deletion/collapse, and how pair fields retain terminating variable-length keys.
