Build from a fresh list

Give records identities, heapify both copies, and connect equal identities. This costs O(n). A record's location in one heap usually differs from its location in the other.

Build from [4, 1, 7]

Input list[4, 1, 7]

1 · Allocate records

Allocate three logical records A:4, B:1, and C:7, then create a distinct min-heap entry and max-heap entry for each identity. Values alone are not keys for correspondence: equal-valued records must still point to their own copies. The record set is complete, so this state stops before heap construction.

2 · Heapify the min copy

Bottom-up min-heap construction yields [B:1, A:4, C:7]. B:1 is no greater than either child, so the root condition is satisfied; A:4 and C:7 are leaves. Heapify stops with every parent key at most its children.

3 · Heapify the max copy

Bottom-up max-heap construction yields [C:7, B:1, A:4]. C:7 is no smaller than either child and both leaves are unconstrained below; heapify stops. Pair pointers by identity (A↔A, B↔B, C↔C), not by array position, because the two heap orders differ.

Operations

Peek either end in O(1). Insert into both heaps in O(logn). To remove the minimum, remove the min root and use its cross-pointer to delete its max-heap copy. Reverse this for removeMax. Arbitrary deletion uses a known record handle and repairs both heaps in O(logn). Search without a handle remains O(n). Concatenating and rebuilding both heaps gives O(n+m) meld.

Remove minimum 1

1 · Find both copies of B

The min root identifies B:1 as the minimum. Follow B’s reciprocal cross-pointer to its max entry at position 2; that lookup is constant time once the min root is known. Equal minimum keys may be returned in either order, but the selected identity’s own counterpart must be removed.

2 · Remove B from both

Remove B from the min root and from max position 2, filling each hole with that heap’s last entry. The temporary min array [C:7, A:4] violates min order at its root, while max [C:7, A:4] is already ordered. Update positions/cross-pointers as entries move; do not leave B in either heap.

3 · Restore heap order

In the min heap, compare replacement C:7 with child A:4 and swap because 7>4; at the new leaf there is no child, so stop. In the max heap, A:4 is now a leaf under C:7 and is already no larger than its parent, so stop immediately. Final heaps are min [A:4,C:7] and max [C:7,A:4]; refresh exact positions A=(min 1,max 2), C=(min 2,max 1).

Caveats and exam focus

Space is about 2n entries plus links. Two equal keys may represent different records, so link identities, not values. Deleting only one copy leaves a stale record at the other end. Bubble up or trickle down according to the replacement's relation with its parent and children.

Why must the underlying heaps support arbitrary removal?

Check your answer

The minimum is normally an interior item in the max heap, so deleting its counterpart is not a root-only removal.

Dual queues: identity, positions, and cost

The lecture's dual single-ended structure stores each logical record twice: once in a min-priority queue and once in a max-priority queue. Every entry points to the other entry for that same record. Heap array positions are independent, so a swap in either heap must refresh the moved entries' positions and both directions of the correspondence. A key is not an identity: if two records have equal keys, retain distinct handles and pair their own copies.

The underlying heaps need arbitrary removal, since removing one endpoint usually targets an interior position in the other heap. A known record handle gives both array positions immediately; searching by key without a handle scans up to n entries. The course's slide 6 shows a 9-record pair of heaps and only five of the nine two-way pointers to avoid clutter; all nine correspondences still exist. This structure is distinct from the lecture's correspondence heaps (which store records once and may use a buffer) and interval heaps (which store endpoint pairs in each node).

Operation Decision and stop condition Cost and edge cases
Build from n records Make both copies, bottom-up heapify each, then connect by identity; stop when both heap orders and all links hold. O(n) worst case for two bottom-up heapifications plus O(n) linking; about 2n heap entries and links. Empty input gives two empty heaps.
Peek min / max Read the corresponding root; do not mutate either heap. O(1); empty heap reports empty/failure. Equal extrema may have multiple valid identities.
Insert record Allocate both entries, append each to its heap, sift each upward while its parent violates order, and refresh links/positions at every swap. O(logn) worst case across two heaps. Equal parent key is a valid stop; insert a new identity even when its key duplicates another.
Change key by handle Supplemental operation: write the new key to both copies, then independently sift up if the parent is violated, otherwise sift down toward the more extreme child. Keep the same identity link throughout. O(logn) worst case. Reject a missing handle before either value changes; equal parent/child keys are valid stops. The lecture names priority-queue operations but does not spell out key-update steps.
Remove min / max Save root identity, remove that root and use its cross-pointer to remove the counterpart from the other heap; repair each hole and update moved entries' positions. O(logn) worst case. Empty: no-op/failure; one record: both arrays become empty. A counterpart of a unique minimum is a leaf in a max heap, and a counterpart of a unique maximum is a leaf in a min heap, so that side can sift up or stop; it cannot need a downward sift from that leaf. Ties can place the chosen extremum at a non-leaf only when equal keys occur, so handle tie policy explicitly.
Delete arbitrary record by handle Read both positions from the handle, replace each removed entry with its own heap's last entry, then sift up if it violates its parent; otherwise sift down toward the more extreme child until ordered. O(logn) worst case. Missing/stale handle must be rejected before either heap changes. The two copies can require opposite repair directions.
Find by key without handle Scan either heap for a matching key and return a matching record handle; value equality alone cannot identify which duplicate was intended. O(n) worst case. Stop at first match only if any equal record is acceptable; otherwise collect/filter all matches.
Meld two queues Concatenate their logical records, allocate/reuse two copies per identity, heapify both arrays, and rebuild all cross-links. O(n+m) worst case. Requires disjoint or explicitly deduplicated identities; do not concatenate old pointers unchanged.

Insertion with duplicate keys, ties, and empty states

The heap order allows equality. Stop sifting when the parent key equals the inserted key; choose either equal child during downward repair as long as the selected child is at least as extreme as the other. Keep identities separate even when their values match. The following insertion starts from the 9-record heaps above and is O(logn) worst case across both queues. Inserting into two empty heaps places the new identity at both roots with no parent test. Peeking/removing an empty queue must return an explicit empty result; deleting the sole record leaves both heaps empty together.

Edge cases and limits

Duplicate keys: If A:5 and B:5 are distinct records, either can be the root minimum, but removing A must use A's handle and remove A from both arrays. Equality satisfies heap order, so no swap is required solely to break a tie.

Missing identity: Validate a handle before mutating either heap. A stale handle must not delete one copy and leave its partner behind. If searching by key, state whether the operation accepts any matching record or requires all matches; key equality is not enough to select an identity.

One child after a deletion: During sift-down, compare the replacement with the sole existing child. Swap only if heap order is violated; if no children remain, stop. Never read a nonexistent right child. For a valid complete binary heap, a node can have a left child without a right child only at the final occupied fringe.

Endpoint counterpart: With distinct keys, the minimum is a leaf in the max heap, and the maximum is a leaf in the min heap. Therefore pop-min's counterpart can only stop or sift upward in the max heap; pop-max's counterpart can only stop or sift upward in the min heap. A downward counterpart repair belongs to arbitrary deletion when the target is internal, as the C example shows. Equal-key tie layouts can require selecting a consistent tied root policy; the general arbitrary-hole rule remains correct.

The slides state that dual queues support insert, remove-min, remove-max, and initialization; they do not provide a specific optimized meld procedure.
