Compressed binary trie

Skip bit positions where all remaining keys agree. Store the next meaningful bit number at each branch.

Rule and fresh build

Every branch has two nonempty children. The bit# field identifies the discriminating bit, counted from 1 here, and increases down every path. For n nonempty keys, there are n−1 branch nodes. Search still validates the candidate's full key because skipped bits were not tested.

Fresh build from [0001, 0011, 1000, 1001]

Input list[0001, 0011, 1000, 1001]

1 · Store 0001 as a singleton

The empty set has no root, so 0001 becomes the sole leaf and insertion stops. A leaf stores the entire key; it is not treated as a branch or as proof that another query is equal.

2 · Add 0011

The candidate 0001 and new key 0011 agree at bits 1–2 and differ first at bit 3 (one-based from the left). Create a bit-3 branch with both leaves; this skips only positions that agree for this pair, and the two nonempty children establish the compressed-branch invariant.

3 · Add 1000

The candidate in the old subtree is 0001; 1000 differs first at bit 1. Since 1 is less than the old root's bit 3, the new branch must replace the root, with the old bit-3 subtree on side 0 and 1000 on side 1. This preserves increasing bit numbers down every path.

4 · Add 1001

At the right child, candidate 1000 and new key 1001 first differ at bit 4. The right subtree is split there, leaving root bit 1, then bit 4 on its right path, and three branches for four leaves (n−1). Stop after the two keys occupy opposite children.

Insert, search and delete

Search follows each stored bit# and compares the final candidate once. For insertion, compare the candidate with the new key to find their first differing bit b. Rewalk until the next branch bit is greater than b, then splice a new branch there. This branch may go above the current root. A duplicate key only updates its record.

Insert 0010, then delete 0011

1 · Find candidate 0011

The bit-3 route for 0010 reaches leaf 0011; compare full keys and find their first difference at bit 4. Bits 1–3 match, so the insertion point is below bit 3; rewalk to the first branch whose number is not less than 4. Equality would instead update the existing record without adding a branch.

2 · Splice a bit-4 branch

Splice bit 4 above leaf 0011: candidate 0011 has bit 4 = 1, while 0010 has bit 4 = 0. The branch has both leaves, and its number 4 is greater than its parent's 3. The pictured left subtree is local context; the right side of the full trie is unchanged.

3 · Delete 0011 and its parent branch

Search for 0011 follows bit 3 = 0 and bit 4 = 1, then confirms the leaf key exactly. Remove that leaf and its parent bit-4 branch together, promoting sibling 0010 into the parent's former link. The ancestor bit-3 node keeps two nonempty children; if this parent had been root, the promoted sibling would become root.

Complexity and edge information

O(W) worst-case key-bit work per search/update, and O(n) structural nodes. Construction by insertion costs O(nW), while melding by donor insertion costs O(mW). Expected height about log₂ n needs assumptions about key distributions; it is not the worst-case bound.

For variable-length keys where one is a prefix of another, append a unique end-of-key character such as #. The higher-order form stores char# and a count of nonnull child pointers. A trie with edge information also keeps a representative element pointer so skipped characters can be checked during descent. That matters for matching a prefix that ends inside a compressed path.

Caveats and exam focus

Compression removes structure, not evidence of exact membership. Repair representative pointers after deletions. A compressed trie does not become a numeric BST. Delete the only key by making the structure empty. When deleting one of two keys, the sibling can become the entire root.

Why can insertion require a second traversal?

Check your answer

The first traversal finds a candidate and the first mismatching bit. The second locates where that bit belongs among the existing increasing branch bit numbers.

Exact membership and the first-difference splice

Use fixed-width 8-bit keys and number positions from 1 at the most-significant end. A branch stores a bit position, not a prefix value. Along each root-to-leaf path the positions strictly increase; a path may skip positions, and every branch has both a 0-child and a 1-child. With n distinct keys, there are n leaves and n−1 branch nodes.

Insertion has two logically different traversals. First, route by existing branch bits to a candidate leaf and compare all W key bits. If equal, update its record and stop. Otherwise find the smallest position b at which the candidate and new key differ. Rewalk from the root while the next branch number is less than b. Splice the new branch before the first branch numbered at least b, or above the root if there is no such ancestor. The old subtree goes to the side selected by its representative key's bit b; the new leaf goes to the opposite side. This placement preserves increasing bit numbers and partitions all keys correctly.

Search follows only stored bit numbers, then compares the complete candidate key. That final check is essential: omitted bit positions were never tested, and a route to a leaf means “candidate,” not “member.” Deletion also verifies the exact leaf. Remove the leaf and its immediate parent, then connect the sibling directly to the deleted parent's former incoming link. This restores the no-unary-branch rule in one cut; if the parent was root, its sibling becomes root, and if the root leaf was deleted the set becomes empty.

Contrasting cases: skipped bits, duplicates, and root cuts

A skipped-bit mismatch still fails exact search

Build a root at bit 7 from 00000000 and 00000010. The query 00000001 chooses the same side as 00000000 at bit 7; bit 8 was skipped, so only the final key comparison can reject it.

The route is: query bit 7 = 0 → candidate 00000000; compare 00000001 with 00000000 → unequal → report absent. Do not add a branch for the unsuccessful query. Inserting an exact duplicate, by contrast, finds an equal candidate and updates its record without changing any branch or leaf count.

Root singleton and two-key deletion

Deleting the sole leaf first verifies equality and then sets root to empty. For exactly two keys, the root is their first-difference branch; deleting either key removes both that leaf and the root branch, so the other leaf becomes the root directly. A missing key leaves every pointer unchanged. These are consequences of the same leaf-plus-parent cut, not special rotations.

Representative pointers for tries with edge information

The lecture's edge-information variant stores at each branch a pointer to any element leaf in that subtree. When a key path skips characters, compare the query's skipped characters with the representative before continuing; this prevents accepting a route that agrees at the explicitly indexed positions but differs in an omitted run. The pointer supplies evidence for those skipped positions; the bit/digit branch still supplies the routing decision. After deletion, if a removed leaf was a representative, repoint that field to any surviving leaf in the same subtree. If the subtree disappears or is promoted, update the incoming links and representative fields along the affected path. A representative is not necessarily the only valid leaf and does not replace the final exact membership check.

The source's NID illustration is variable-length and includes terminal #; it is not an 8-bit binary dictionary. For a fixed-width binary set, the full-key leaf check is the corresponding exact-membership safeguard. For variable-length keys where one key is a prefix of another, reserve a unique end marker (or store termination explicitly) so the shorter key remains a distinct member. Do not compare a variable-length prefix as if it were a complete match.

Method decisions and costs

Method Decision Stop condition Important edge cases
Construct by repeated insertion Insert each distinct key into the compressed trie; each splice uses its first differing position. All input keys are processed. The first key is a leaf; later keys can splice above the root; duplicates do not add structure. Lecture's simple construction is O(nW).
Search / membership Route through each stored bit number, then compare the full candidate key. Return present only on exact equality; otherwise absent. A mismatch may be in a skipped bit; an empty set stops immediately. Worst-case O(W) bit work.
Insert / update Find candidate, calculate first-difference b, rewalk to the first branch bit ≥ b, and splice. Duplicate: update and stop. New key: stop once its bit-b branch has two nonempty children. Splice can be above root or within a subtree. Two traversals remain O(W) for fixed-width keys.
Delete Verify candidate, remove leaf and its parent, and promote sibling. Missing key: no change; exact key: finish after the cut. Empty root after deleting singleton; leaf root after deleting from a two-key set; sibling may be an entire subtree.
Meld / combine No native constant-time meld is stated for this structure; supplemental approach inserts every donor key into the receiver. Every donor key has been checked/inserted. O(mW) for m donor keys with fixed width W; duplicates update rather than increase cardinality. Do not confuse it with pointer concatenation.
Search with edge information Use each branch's representative leaf to check positions skipped by compression while descending. Reject on a skipped-character mismatch; otherwise still validate the final candidate. Repair pointers when their representative leaf is deleted; the lecture specifies the pointer purpose, not a complete update algorithm.
Variable-length membership Append a reserved end-of-key marker or explicitly store termination. The marker/termination matches as part of the whole key. A proper-prefix key and its extension are distinct. Lecture's # is a teaching convention and must not collide with data.

For n distinct keys, the lecture's branch-count fact is exactly n−1; including leaves gives 2n−1 structural nodes. Search/insert/delete have O(W) worst-case bit work, not O(logn) worst-case. A height near log₂n is only an expected-shape statement under assumptions about key distributions. Structural storage is O(n), separate from the O(nW) space required if the full keys are stored explicitly. Insertion construction is O(nW); donor insertion for meld is O(mW).
