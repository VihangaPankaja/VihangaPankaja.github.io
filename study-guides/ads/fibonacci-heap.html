Fibonacci heap

Use a loose forest and marks to make priority improvements cheap over a sequence. Consolidate when removing an extreme.

Rule and fresh build

Each tree obeys heap order. Roots and siblings form circular doubly linked lists. Nodes store parent, child, degree and ChildCut. The mark records whether a nonroot has lost a child since it was linked under its current parent. A new link clears the mark.

Fresh min-heap build from [7, 3, 9, 1]

Input list[7, 3, 9, 1]

1 · Empty heap

No root and no minimum exist in the empty structure. Stop immediately; the first insertion will create a singleton circular list.

2 · Add 7 then 3

Insert 7 and then 3 as separate degree-zero roots. Compare each inserted key with the stored minimum, so 3 becomes the minimum; no linking is needed and the root-list circle is preserved.

3 · Add 9 then 1

Insert 9 and then 1 as two more singleton roots. The minimum changes to 1, but insertion deliberately defers consolidation; all four roots still have degree zero and heap order holds vacuously.

4 · removeMin(1) consolidates

Remove root 1, whose child list is empty, then consolidate the remaining equal-degree roots. Root 3 wins the comparison with 7 and adopts it; root 9 remains a separate root, so the forest has two trees and minimum 3.

Operations

Method Actual worst case Amortized
getMin / insert / meld O(1) O(1)
removeMin O(n) O(logn)
decreaseKey(handle), min version O(n) O(1)
increaseKey(handle), max version O(n) O(1)
remove(handle) O(n) O(logn)
search without handle O(n) O(n)

removeMin promotes children, clears their parent pointers, consolidates equal degrees, and recomputes the minimum. Meld splices root lists and updates the extreme pointer. A worsening key can be handled by delete plus reinsert, not the cheap improvement rule.

Decrease key with cascading cuts

1 · Before the change

The highlighted path is the only part of the lecture tree needed for this cascade: root 1, unmarked child 2, marked descendant 4, marked descendant 7, then target 8. Other siblings remain present but do not affect the path decisions.

2 · Decrease 8 to 6; cut it

Changing 8 to 6 makes it strictly smaller than parent 7. Cut the whole 6-subtree from 7’s child circle, repair 7’s child pointer and degree, and splice 6 into the root circle; clear its mark because it is now a root. Since 7 was already marked, continue upward.

3 · Parent 7 was already marked

Node 7 has already lost a child since it became a child of 4, so cut its entire subtree to the roots and clear its mark. Repair 4’s child pointer and degree, then continue because 4 is marked too.

4 · Cut marked 4; mark unmarked 2

Cut marked nonroot 4 and continue to its parent 2. Node 2 is an unmarked nonroot, so set ChildCut=true and stop: this records its first loss. If the path instead reached root 1, stop there without marking or cutting the root.

Arbitrary remove and max version

For a nonminimum target, the lecture directly detaches it, promotes its children and cascades from its old parent. If it is the minimum, use removeMin. An alternative is decrease to a reserved −∞ then removeMin, provided the sentinel unambiguously selects that record.

Lab 8 uses a max heap. increaseKey can trigger the same cut rule with comparisons reversed. Its hashtag counter maps each tag to a node handle. A top-k query removes k maxima and reinserts them, updating map handles so later increments reach live nodes.

Caveats and exam focus

Repair the parent's child pointer if its selected child is cut, decrement degree, and handle an only child. Save nodes before modifying a circular list. ChildCut does not mean “has children.” Amortized O(1) permits a long actual cascade. Dijkstra's nonnegative-edge algorithm benefits from O(e) decrease-key work plus O(nlogn) removals.

What happens the first time an unmarked nonroot loses a child?

Check your answer

Mark it and stop. A later child loss cuts it and can continue the cascade upward.

Method decisions and stopping conditions

Operation Decision and exact stop condition Cases and cost model
getMin / getMax Read the stored extreme pointer; stop immediately. Empty heap has no extreme. Θ(1).
insert(x) Make a singleton root, splice it into the circular root list, and compare it with the extreme pointer. Stop without linking. Empty heap makes x the extreme; equal keys may retain either tied handle. Actual and amortized O(1) per lecture 7 slide 1.
Build from a list Repeatedly apply the lecture’s insert operation in input order. Stop after the final item; do not pre-consolidate. Empty list returns empty. n inserts take actual O(n) and amortized O(n); a later remove-min consolidates.
meld(A,B) Splice the two circular root lists and choose the smaller root (larger for max variant) as the new extreme. Stop after pointer updates. Either empty input returns the other heap. Roots need not be consolidated. Actual and amortized O(1).
removeMin / max variant removeMax Remove the extreme root, promote each child by clearing its parent and mark, consolidate roots with equal degree, then scan the rebuilt roots for the new extreme. Stop when every degree occurs at most once. Empty heap has no item; a one-node heap becomes empty. Equal roots may link either way if the tie rule is consistent. Lecture 7 gives actual O(n), amortized O(logn).
decreaseKey(handle, amount) in a min heap Subtract a nonnegative amount. If the node is nonroot and its new key is strictly smaller than its parent, cut it; then walk upward, cutting marked nonroots and marking the first unmarked nonroot. Stop at that unmarked node or at a root. Equal parent key needs no cut; a root only needs the extreme pointer updated if it becomes smaller. Amount zero causes no structural change. Reject stale handles; a worsening key needs delete-and-reinsert. Actual O(n), amortized O(1).
increaseKey(handle, amount) in the max-heap lab variant Add the amount and mirror the min-heap comparison: cut when a nonroot becomes strictly larger than its parent; apply the same marked/unmarked cascade using max order. Equal parent key remains valid. A root can become the new maximum without a cut. This is the max-heap counterpart named in the course/lab; lecture 7’s detailed Fibonacci derivation is min-oriented. Actual O(n), amortized O(1) by the slide 1 increase/decrease pairing.
remove(handle) / delete If the handle is the extreme, route to removeMin/removeMax. Otherwise detach that node, promote all its children, repair its former parent’s child pointer and degree, then run the cascading-cut rule from that parent. Reject an empty/stale/foreign handle before mutation. An only child makes the parent’s child pointer null. Root parent means the cascade stops immediately. Actual O(n), amortized O(logn). The lecture shows direct handle deletion; decrease-to-sentinel is only an alternative when the sentinel cannot collide.
Search by key without a handle Traverse reachable nodes until a matching key is found or every tree is exhausted. Heap order does not provide BST routing, so the worst case is O(n); duplicates require a tie policy or a specific handle.
Hashtag update and top-k (lab application) Map each tag to its live node handle for key updates. For top-k, remove k maxima and reinsert those records, replacing each map entry with its new handle. A stale handle after removal must not be reused. Reinserted equal-priority tags need a deterministic tie policy if the application requires stable output.

The heap-order direction is the key course distinction: min heaps cut after a decrease violates parent≤child; max heaps use the reversed comparison after an increase. ChildCut is meaningful only while a node is a nonroot, and a new parent link resets it. A cut removes the whole subtree, not only the node, so all descendants remain reachable beneath the promoted root.

removeMin(1): promote, link equal degrees, rescan

1 · Before removeMin(1)

All eight inserts are still roots, so every degree is zero and the minimum pointer names 1.

2 · Remove the minimum root

Delete node 1. It has no children to promote, so the seven remaining roots keep their keys and degree 0; the next minimum candidate is 3.

3 · Link 17 below 3

The scan finds two degree-0 roots, 17 and 3. Since 3 is smaller, make 17 a child of 3; 3 now has degree 1. Continue scanning the roots.

4 · Link 24 below 7

Roots 24 and 7 collide at degree 0. Root 7 wins; attach 24 under it and continue with 7 at degree 1, where another degree-1 root may already exist.

5 · Link 7 below 3

Root 7 now collides with root 3 at degree 1. Since 3<7, link 7 under 3; 3 becomes degree 2. This second collision is why one root can trigger repeated links.

6 · Link 18 below 12

Roots 18 and 12 collide at degree 0. Root 12 is smaller, so 18 becomes its child and 12 reaches degree 1. No other degree-1 root remains in the table.

7 · Rebuild the root list and stop

The degree table contains one root per degree: 5 at degree 0, 12 at degree 1, and 3 at degree 2. Rebuild the root list from these entries and scan them for the minimum; 3 wins. No degree was inferred from a logarithmic bound.

Count check: 1+2+4 = 7 records; root degrees are 0, 1, and 2, and the minimum pointer is 3.

The final forest contains the trees {5}, {12,18}, and {3,17,7,24}, with sizes 1, 2, and 4: seven records remain after removing 1. The three root degrees are 0, 1, and 2, so no duplicate degree remains. Root-list circular order is an implementation detail; the minimum is 3 regardless of the order used to enumerate the degree table.

Handle-based deletion: repair links before cascading

The source sequence separates removing a nonminimum handle from removing the minimum. This compact state makes the pointer repair visible: the target is its parent’s selected first child and has two children of its own.

Delete a nonminimum node by handle

1 · Before deleting handle 4

Use the live node handle for 4. The min-heap has roots 2 and 5; node 4 is the first child of 2, and 8 is its sibling. Node 4 owns children 9 and 11.

2 · Detach 4 and repair its parent list

Remove 4 from the circular sibling list and change 2.child to 8 because 4 was the selected first child. Decrement degree(2) from 2 to 1. If the deleted node were the only child, set parent.child to null and degree to 0.

3 · Promote 9 and 11; finish

Splice every child of 4 into the root list, set each promoted child’s parent to null, and clear its child-cut flag because it is a root. The old parent 2 is already a root, so cascading repair stops there; minimum remains 2.

For target 4’s parent edge, the cascade reaches root 2 and stops without marking the root. If the handle named the minimum, the course route is removeMin instead.

The lecture’s remove-min branch remains special: when the target is the minimum, remove the root and consolidate its promoted children instead of running arbitrary-node removal. A key-only delete must first search for a matching handle, which can scan all nodes.

Cascade cases side by side

The lecture’s rule has three distinct stopping outcomes. An unmarked nonroot records its first child loss and ends the walk; a marked nonroot is cut and passes the walk to its parent; reaching a root ends the walk without changing the root’s mark. Equality in the initial key comparison is not a violation.

First loss, repeated loss, and root stop

1 · Before the first child loss

Nonroot 2 is unmarked and has children 4 and 6. Node 4 has child 7. The first update will decrease 6 to 0, making it smaller than parent 2 and requiring a cut.

2 · Decrease 6 to 0; the first loss marks parent 2

Change key 6 to 0. Because 0<2, cut that node and make it a root. Its former parent 2 is an unmarked nonroot, so mark 2 and stop this cascade. Node 2 remains under root 1 with child 4. Update the minimum pointer to 0.

3 · Decrease 4 to −1; cut that subtree first

Now change 4 to −1. Since −1<2, cut the whole subtree rooted at −1, keeping child 7 attached. Node 2 has lost its second child and is still marked. The cascade must continue to 2; it has not finished yet. Minimum becomes −1.

4 · Cut marked node 2; stop at root 1

Node 2 was already marked, so cut it from 1 and clear its mark as it becomes a root. Root 1 now has no children. Stop on reaching that root: roots are not marked or cut for child loss. Roots 0 and −1, including child 7 under −1, are unchanged; minimum remains −1.

Source-aligned method notes

  • Lecture 7 slide 1 supplies the actual/amortized operation table. Actual O(n) cascading work can occur even when the amortized decrease/increase cost is O(1); these are different guarantees.
  • Lecture 7 gives remove-min cost but does not include its consolidation pseudocode. The degree-table link sequence here is an explicitly supplemental expansion of the existing page’s removeMin description; the displayed degrees are counted from these exact trees, not inferred from an unstated degree-log bound.
  • Slides 5–7 define the collection of min trees and node fields: degree, child, data, left/right siblings, parent, and ChildCut. ChildCut records a child loss under the current parent; it is not a count of children.
  • Slides 8–11 show arbitrary deletion by node handle: use remove-min for the minimum, otherwise unlink the target and join its children into the top-level list with null parent pointers.
  • Slides 12–19 show the strict decrease-key cut and cascading rule. Slide 14 says to cut marked nonroots upward, stop at the first unmarked node and mark it; root is excluded. Slides 15–19 show the marked-path example and actual O(h)=O(n) cascade bound.
  • Lecture 7 slides 30–33 describe IncreaseKey for pairing heaps, whose nodes omit parent and ChildCut fields. That algorithm is not used here. The max Fibonacci heap name and comparison direction follow slide 1’s “decrease key (or increase)” and “remove min (or max)” notation plus the stated max-heap lab variant.

Common mistakes

  • Inserting does not consolidate. Linking happens during remove-min/remove-max in this course treatment.
  • A link is allowed only between roots of equal degree. Keep the smaller root in a min heap and increase its degree by one.
  • Promoted children become roots: clear their parent pointers and treat their mark as reset/irrelevant.
  • Do not mark a root during cascading cut. Stop there.
  • A child loss from an unmarked nonroot sets its mark and stops. A later loss cuts that marked node and may continue upward.
  • Repair a parent’s selected child pointer and degree when cutting or deleting its only/first child. Save siblings before changing circular links.
  • A handle-based operation names a node even with duplicate keys. Search-by-key is a separate O(n) task.
  • Do not mix actual and amortized costs, or copy the pairing-heap increase-key algorithm into a Fibonacci heap.

Exam focus

State the operation’s direction, handle assumption, strict parent comparison, pointer updates, and cascade stop rule. For delete, branch first on whether the handle is the extreme; otherwise promote children and cascade from the old parent. For remove-min, promote children, consolidate equal degrees, and recompute the minimum. Quote both actual and amortized costs where the question asks for complexity.

Practice

A nonroot with ChildCut=false loses a child during a decrease-key cascade. What happens next?

Answer

Set ChildCut=true and stop. Its first loss is remembered; it is not cut yet.

A marked nonroot loses another child. When does the cascade end?

Answer

Cut the whole node subtree to the roots, clear its mark as a root, then inspect its parent. Continue through marked nonroots; stop at the first unmarked nonroot after marking it, or stop on reaching a root.

During consolidation, what if a degree slot is empty after a link raises the winner’s degree?

Answer

Store the winner in that degree slot and resume scanning. If occupied, compare equal-degree roots, link the larger beneath the smaller, increment the winner’s degree, and check the next slot.

Why must a hashtag map store node handles after each remove-and-reinsert top-k cycle?

Answer

Removal invalidates the old node. Reinsertion creates a different node, so the map must point to the new live handle before a later key update.
