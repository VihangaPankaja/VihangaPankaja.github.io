Digital search tree

Store a whole record at every node, but use successive key bits to choose branches.

RuleOperations and costsCaveats and exam focusFixed-width keys: keep the representation and the bit index

Rule

For fixed-length binary keys, the root can hold any key. Remaining keys use their first bit to choose left 0 or right 1. At the next depth, branch on the second bit, and so on. This is bitwise routing, not numeric BST ordering. Test equality with the current whole key before descending.

Fresh build from [0110, 0010, 1001, 1011, 0000]

Input list[0110, 0010, 1001, 1011, 0000]

1 · Insert 0110 into empty tree

The tree is empty, so 0110 becomes the root without inspecting a routing bit. The root choice is arbitrary in the lecture; once chosen, every later decision uses the bit at the current depth. Stop this insertion as soon as the empty root slot is filled.

2 · Insert 0010

Compare the whole key 0010 with root key 0110 first; they differ, so route by bit 1. Since 0010 begins with 0, follow the left pointer, which is empty, and store it there. Do not use numeric key order to choose this branch.

3 · Insert 1001

The full key 1001 is unequal to 0110, so inspect its bit 1. That bit is 1, selecting the root's right pointer; because it is empty, the key becomes that child. The equality check happens before branch selection at each occupied node.

4 · Insert 1011

At root 0110, 1011 is unequal and bit 1 is 1, so visit 1001. The full-key comparison there also fails; at depth 1 inspect bit 2, which is 0, and fill 1001's left pointer. This is a depth-based bit decision, not a comparison of 1011 and 1001 as integers.

5 · Insert 0000

The key 0000 fails equality at 0110, then bit 1 = 0 selects 0010. It is still unequal there; bit 2 = 0 selects the empty left child, so insert and stop. The resulting paths encode the first differing routing decisions and require no balancing rotations.

Operations and costs

Search, insert and delete use O(W) bit-routing levels for W-bit keys. The lecture treats full-key comparison as a primitive; long strings can make each comparison costly. Build by inserting n keys costs O(nW) in that model. General meld inserts donor records, rather than splicing roots. No native constant-time min/max or rank operation is provided.

Search 1011, then delete internal key 1001

1 · Compare with 0110

Compare all four bits of query 1011 with root 0110; inequality does not itself determine direction. Its bit 1 is 1, so move right to 1001. A missing right pointer would stop here with an unsuccessful search; this branch exists.

2 · Compare with 1001, then 1011

Compare the entire query 1011 with node 1001 and find inequality. The query's bit 2 is 0, so follow the left pointer, then compare the whole key again with 1011. Equality at that node confirms membership; stop without examining later bits.

3 · Delete 1001 using a descendant leaf

For deletion, first locate 1001 by full-key comparison at each visited node, then detach its record while preserving the depth-1 routing slot. The shown replacement copies descendant leaf 1011 into that slot and removes its old leaf pointer; its prefix fits the slot, and any other child subtrees retain their bit-2 decisions. In this example, 1011 occupied the left slot, now empty. This is a supplemental internal-node method, not an algorithm detailed in Lecture 12.

Caveats and exam focus

The ordering of full keys at parent and child does not determine direction. Use the query's bit at the current depth. Supplemental map convention: when insertion reaches a node with the same whole key, replace its associated record in place; do not add another node. A missing branch means unsuccessful search. For variable-length keys, add an explicit end-of-key convention or use a suitable trie. The internal-node deletion walkthrough explains the procedure beyond the lecture's stated complexity.

Why is 1011 a left child of 1001 in the example?

Check your answer

At that level branching uses the second bit. 1011 has second bit 0, even though its numeric value is greater than 1001.

Fixed-width keys: keep the representation and the bit index

In a digital search tree (DST), every occupied node stores a complete dictionary record. The root may contain any key. For an occupied node at depth d (root depth 0), first compare the query's whole key with that node's whole key. If unequal, inspect the query's (d+1)th bit (one-based): 0 takes the left pointer and 1 takes the right pointer. An empty selected pointer proves absence during search and is the insertion slot during insertion. Leading zeros are data: 00000101 is an eight-bit key and must not become 101 or integer 5.

The lecture calls the branch decision the first bit at the root, the second bit one level below, and so on. In zero-based code, branch on key[d].

Search and insertion edge cases

Exact membership, absent branch, and duplicate key

1 · Find existing key 10101100

2 · Search absent key 00001010

3 · Insert duplicate key 10000001

If two distinct fixed-width keys differ, their first differing bit eventually sends insertion down different pointers. If every bit matches, they are the same key: follow the page's update convention (or reject the duplicate if an application specifies set semantics), and do not descend past the full key width. A query that reaches a node but fails full-key equality is not present.

Deletion: leaf removal and internal replacement

The lecture gives the operation's complexity but does not spell out its deletion algorithm. The following are supplemental teaching procedures for fixed-width keys. A leaf can be detached directly. For an internal node, copying a descendant leaf record into the target slot and removing that leaf from its old slot preserves the target's incoming prefix and leaves every other subtree at its original depth. Do not move an internal child pointer up a level: that would change which absolute key bit each child decision represents.

The lecture's internal example is the one-child case: delete 1001 and use descendant leaf 1011 in its place. At the target's depth, both records share the root's right-prefix; its remaining left child is still selected by bit 2 = 0. A node with one child can be handled the same way by choosing any descendant leaf. When the target itself is a leaf, simply clear its incoming pointer. Removing the only root record makes the tree empty. These are supplemental explanations; Lecture 12 does not prescribe this deletion procedure.

Cost model and limits

For W-bit keys, a route has at most W bit positions, so search, insertion, and the described deletion take O(W) routing levels; the number of full-key comparisons is O(height), as Lecture 12 states. Its O(W) operation bound treats a whole-key comparison as a primitive. If comparing two W-bit strings itself costs O(W), a worst-case operation may perform O(W) such comparisons and therefore O(W2) bit work. Inserting n records one at a time is O(nW) in the lecture's comparison model; melding m donor records by insertion is O(mW) in that same model. These are not expected-height claims.

The fixed-width condition matters. For variable-length keys, a terminator or explicit end-of-key representation is required to distinguish a key from a longer key sharing its prefix. Binary tries use branch-only nodes and element leaves, a different representation from this DST; do not transfer their candidate-leaf comparison count or deletion compression rule to a digital search tree.
