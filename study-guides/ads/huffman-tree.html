Huffman tree

Combine the two lightest trees repeatedly. Frequent symbols end up with short codes, and small runs get merged first.

Big pictureMethodsHigher-order construction and caveatsEight-symbol construction: ties, codes, and a complete cost checkTies, singleton alphabets, and higher-order treesMethod decisions and limits

Big picture

Huffman construction minimizes weighted external path length, WEPL = Σ(weight × leaf depth). The same quantity measures encoded bits or total merge work. A min heap helps build the tree, but the finished Huffman tree is a coding tree, not a search tree.

Fresh build from weights [2, 5, 4, 7, 9]

Input list[2, 5, 4, 7, 9]

1 · Start with singleton trees

Create one leaf per symbol and put all five weights in the min-priority queue. The invariant is that the queue contains exactly the current forest roots; stop initializing when every input leaf is present.

2 · Combine 2 and 4

Remove the two minima, 2 and 4, and make them children of a new weight-6 root. The merge preserves all leaves and adds their depths by one; reinsert 6, then continue because four roots remain.

3 · Combine 5 and 6

The queue minima are now 5 and 6, so merge them into 11 with the 5 leaf on the left and the 6 subtree on the right. The forest roots become 7, 9, and 11; continue while more than one root remains.

4 · Combine 7 and 9

The two smallest roots are 7 and 9; combining them produces 16 and leaves roots 11 and 16. Equal weights would permit another deterministic tie choice, but here the minima are distinct, so continue once more.

5 · Combine 11 and 16

Merge the final roots 11 and 16 into 27; one root remains, so construction stops. Its leaf depths give 60, matching merge work 6+11+16+27, which checks both the topology and the WEPL accounting.

Encode and decode with the built tree

1 · Assign codewords

Assign 0 to every left edge and 1 to every right edge, then read root-to-leaf paths. The listed paths are prefix-free because a symbol is emitted only at a leaf; a different left/right convention changes bit strings, not lengths or WEPL.

2 · Encode symbols with weights 5, 9, 2

Look up each requested symbol once: weight-5 symbol gives 00, weight-9 gives 11, and weight-2 gives 010. Concatenation is 0011010; the code table must be shared by sender and receiver, and all source symbols must have entries.

3 · Decode 0011010

Consume bits from the root until reaching a leaf, emit its symbol, then reset to the root. The stream partitions as 00, 11, 010 and decodes to [5,9,2]; a stream ending at an internal node is incomplete rather than another symbol.

Higher-order construction and caveats

For a k-way Huffman tree with r leaves, add the smallest q ≥ 0 zero-weight leaves satisfying (r+q−1) mod (k−1) = 0. Then combine k smallest trees each round. For k=3, weights [3,6,1,9] need one dummy 0. Combine 0+1+3=4, then 4+6+9=19. Cost = 4+19 = 23, rather than the unpadded greedy cost 29.

Ties can produce different optimal codes. No codeword may prefix another. The lab assigns a single-symbol alphabet the code 0, avoiding empty encodings. A two-symbol alphabet uses 0 and 1. Include the code-table storage when comparing compression sizes.

Must the lightest symbol have the longest code in every tie situation?

Check your answer

It may share the longest length with other symbols. The guarantee is optimal total weighted length, not a unique code table.

Eight-symbol construction: ties, codes, and a complete cost check

This fresh example uses named symbols and a stated deterministic tie rule. Keep each current forest root in a min-priority queue ordered by (weight, insertion order); original leaves precede newly created internal nodes on equal weights. This tie rule makes the trace reproducible, while any tie order still gives an optimal binary Huffman tree.

Ties, singleton alphabets, and higher-order trees

Equal frequencies do not make the code unique. With four equal-frequency symbols A, B, C, D, one valid tie order pairs (A,B) and (C,D), while another pairs (A,C) and (B,D). Both trees have four leaves at depth 2, so each has WEPL 4×2 = 8; only the bit assignments differ. The queue must use a consistent tie breaker so a trace can be reproduced. Do not claim a unique code or that one tied symbol must receive a particular longest code.

For one symbol, the course lab convention assigns code 0; this avoids an empty codeword. For two symbols, make them the two children of the root and assign 0 and 1. A zero-frequency dummy added for k-way padding is a structural leaf only: omit it from the symbol table, encoded message, and real-symbol WEPL.

Why a three-way tree needs padding

For k-way merging, each full internal node has exactly k children, so each merge reduces the forest count by k−1. With r real leaves, choose the least q≥0 satisfying (r+q−1) mod (k−1)=0; then repeatedly merge the k minima. If the congruence already holds, q=0. A 2-way tree needs no padding.

For k=3 and weights [3,6,1,9], q=1. Insert a dummy 0, then merge 0+1+3=4 and finally 4+6+9=19. The real leaves have depths 2,1,2,1 respectively, giving real WEPL 3×2 + 6×1 + 1×2 + 9×1 = 23; merge sums are 4+19=23 as well.

The unpadded greedy attempt first combines 1, 3, and 6 into 10, leaving only 10 and 9. Attaching those two beneath 19 makes a 2-child internal node, which is not a full 3-way tree; its cost is 3×2+6×2+1×2+9×1=29. This is why the padding step is required, not an optional optimization.

Method decisions and limits

Construction bounds below are worst-case for a binary min-heap. Code generation, encoding, and decoding are deterministic output-sensitive bounds; they do not rely on an expected- or amortized-time claim.

Method or question Course procedure and decision Stop condition Edge cases and cost
Build a binary Huffman tree Heapify the n singleton leaves, remove the two minimum roots, make them children of a summed root, and reinsert; repeat. Stop at one root; n−1 merges for n≥1. Worst-case heapify O(n), then O(nlogn) heap work in total; lecture also describes n−1 remove-min plus n−1 change-min. A singleton needs no merge.
Generate codes Traverse the finished tree, appending 0 on left edges and 1 on right edges. Emit a code at each symbol leaf. O(n+L), where L is the total emitted code length; a singleton uses the lab's explicit code 0.
Encode Look up each source symbol in the generated code table and concatenate. Stop after the last input symbol. O(numberofoutputbits) with constant-time table lookup; unknown symbols have no code and must be rejected/handled outside this construction. Include code-table storage when assessing compression.
Decode Follow one edge per bit; emit at a leaf and reset to root. Stop exactly at end of input, which should be at root. O(numberofinputbits); an invalid edge or unfinished internal-node path is malformed input, not a decoded symbol.
Search, insert, delete, or meld symbols These are not dictionary operations on a coding tree. Change the frequency set and rebuild the tree/code table. Rebuild ends when one root remains. Rebuild costs O(nlogn) worst case with a binary min heap; no search-tree key ordering or direct meld guarantee applies.
Update a frequency Treat the changed frequencies as a new construction input and rebuild. Complete the same n−1 merge process. Existing codewords may all change; updating one leaf locally is not the lecture's algorithm.
Build a k-way tree Compute q from the congruence, add q zero-weight dummy leaves, then combine k minima per round. Stop at one root; each merge removes k−1 forest roots. q=0 when already congruent; k=2 always has q=0. Exclude dummy leaves from real symbols and their WEPL.
Resolve equal minima Apply one deterministic tie rule for a reproducible trace. Any legal minimum pair is allowed. Continue until one root, regardless of ties. Equal weights can yield different optimal trees/codewords; compare WEPL or code lengths, not literal code strings.

For the eight-symbol example, why does merge work equal WEPL?

Check your answer

Each merge raises every leaf below the new parent by one level. That adds the two child-tree weights, namely the new parent weight, to the sum of frequency × depth. Summing all seven merge weights gives 225, the same as the leaf-depth calculation.

For a ternary tree with r=5 real leaves, how many dummy leaves are needed?

Check your answer

q=(1−5) mod 2 = 0, so no dummy is needed: 5−1 is divisible by 3−1.

Can an encoded stream end halfway down an internal path?

Check your answer

No. A valid complete encoding ends at the root after the final leaf reset; ending at an internal node means the final codeword is incomplete.
