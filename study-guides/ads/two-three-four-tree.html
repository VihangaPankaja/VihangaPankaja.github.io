2-3-4 tree

Allow one more key per node. Red-black trees can represent the same degree-balanced idea using colored binary links.

Rule

This is a B-tree of order 4. A data node holds 1, 2 or 3 keys, with 2, 3 or 4 child ranges. Nonroot nodes keep at least one key. All external leaves have equal depth.

Input list[1, 2, 3, 4, 5]

1 · Empty, then insert 1 and 2

The empty root is a leaf, so insert 1 and then 2 in sorted order to get [1,2]; the node has two of the allowed three keys, so stop without changing height or adding child links.

2 · Insert 3

Insert 3 after 2 to fill the root as [1,2,3]. Three keys are legal for order 4, so this is a full but not overflowing node; stop here and split only after a fourth key arrives.

3 · Insert 4; bottom-up split

Insert 4 to form the temporary ordered overflow [1,2,3,4]. The lecture promotes the 1-based key at position ceil(4/2)=2, namely 2; the next state shows the two children and the new root created by this root split.

4 · Insert 5

After the split, 5 is greater than root key 2, so it enters the right leaf [3,4] and becomes [3,4,5]. That leaf is at its three-key capacity, not over it; stop with both leaves at the same depth.

Delete 1 by borrowing from its sibling

1 · Delete left leaf key 1

The search for 1 ends in left leaf [1] under root separator 2. Deleting it leaves an empty nonroot node, below the one-key minimum; continue to inspect the adjacent right sibling [3,4,5], which has surplus keys.

2 · Transfer through parent

Move separator 2 down into the empty left leaf and move the right sibling minimum 3 up to replace it in the parent. The result is [2] | 3 | [4,5]: both leaves have at least one key, their ranges remain ordered, and repair stops.

Methods, caveats and comparison

Search, insert, remove, lowerBound, min and max are O(logn). Build through n inserts costs O(nlogn). General meld can merge sorted traversals and rebuild. A top-down algorithm may split a full three-key node before descending; the viewer follows bottom-up overflow splitting. Both are valid but can produce different shapes.

Collapsing red children into black parents of a red-black tree produces nodes with 2–4 child ranges. This explains why color flips correspond to changes in the grouped representation. A four-node holds three keys, not four.

Top-down splitting and bottom-up overflow splitting can choose different times or medians for an even-size temporary node. Both must preserve occupancy, ordering and common leaf depth.

Big picture and occupancy

A 2–3–4 tree is an order-4 B-tree: each node stores one to three sorted dictionary keys and, when internal, has one more child range than keys. A four-key node is only a temporary overflow during bottom-up insertion. Nonroot nodes must retain at least one key, and all external leaves stay at the same depth. These rules let search, insertion, and deletion change a bounded number of keys per visited level while keeping the height logarithmic.

For a B-tree of order m, maximum children is m, maximum keys is m−1, and a nonroot node needs at least ceil(m/2)−1 keys. With m=4, a nonroot node therefore has 1–3 keys. The lecture split rule on an overflow of m keys promotes the key at 1-based position ceil(m/2). For four keys this is the second key: one key remains left and two remain right. This asymmetry matters when checking the picture.

Insertion: bottom-up overflow splitting

The course trace inserts into the destination leaf first. If a node then has four keys, promote its second key, keep the first key in the left node, and keep the last two in the right node. Insert that separator and the new child pointer into the parent. A parent with at most three keys ends the repair; a parent with four keys is split by the same rule. If the root overflows, its promoted key becomes a new root and its two pieces become children, increasing height by one.

The course's illustrated method is bottom-up. In a top-down variant, split a full three-key child before descending into it; the target key is inserted only after that split. Deletion: replace internal keys, then repair leaves

The lecture converts an internal-key deletion into a leaf deletion by replacing the key with the maximum key in its left subtree (the predecessor). Physically remove that predecessor from its leaf. If that leaf becomes empty, repair it by borrowing through a parent separator from an adjacent sibling with more than the minimum, or by merging with a minimum-size sibling and the intervening parent key.

Borrow through either adjacent sibling

Borrowing transfers one parent separator down and one boundary key up. If the deficient child is left of its donor, the donor's minimum moves up; if it is right of its donor, the donor's maximum moves up. With internal nodes, the corresponding boundary child pointer moves with the key so that every range remains attached to the correct subtree.

Merge, propagate underflow, and contract the root

If neither adjacent sibling can lend, merge the deficient child, one parent separator, and one sibling. The parent loses that separator and one child link. If this makes a nonroot parent empty, repeat the same repair at its level. An empty root with exactly one child is removed and that child becomes the root, reducing height by one.

Method decisions and edge cases

The table separates the course's core tree operations from useful traversal or combination methods. Node-visit bounds treat order as fixed; the node has at most three keys, so within-node comparisons and shifts are bounded. For a variable order m, account for the work inside each node separately from the number of levels.

Method Decision Stop condition and edge cases
Search / get Compare against the node's sorted keys; equality finds the stored dictionary pair, otherwise choose the unique child gap bounded by adjacent separators. Stop on equality or an external failure child; an empty tree fails immediately. All data keys occur in internal nodes and leaves, so equality does not automatically descend. Worst-case O(logn) node visits for fixed order.
Insert / put (course variant) Descend to a leaf, insert in order, then split each four-key overflow by promoting its second key and carrying the new right-child pointer upward. Stop when the parent has at most three keys; split every overflowing ancestor and create a root after root overflow. A duplicate-key update policy is dictionary-specific; replacing a value does not require a structural insertion. Worst-case O(logn) node visits.
Top-down insert (contrast only) Split any full child before descending into it, then insert into a nonfull child. This is a supplemental alternative; the lecture's illustrated procedure is bottom-up. Stop at the target leaf. Boundary keys can lead to a different shape because the pre-descent split sees three keys while bottom-up splitting sees four. Both must preserve order, occupancy and equal leaf depth.
Delete / remove For an internal match, replace with the predecessor (maximum of the left subtree), then delete its old leaf occurrence. Repair an empty nonroot node by borrowing through a parent or merging with a sibling and separator. Stop when a node regains its minimum or propagation reaches a legal root. A missing key changes nothing. If the root becomes empty with one child, promote that child; a single root leaf may become empty. Worst-case O(logn) node visits.
Borrow / redistribute Use an adjacent sibling with more than one key. Move the parent separator down, the sibling boundary key up, and for internal nodes move its adjacent child pointer too. Stop when the deficient node has one key. A left donor gives its maximum; a right donor gives its minimum. A one-key sibling cannot lend.
Merge When neither adjacent sibling can lend, combine the deficient range, a sibling, and the parent separator; for internal nodes also concatenate child pointers in key order. Parent loses one key and child link. Continue if a nonroot parent becomes empty; contract an empty root with one child.
lowerBound(x) Track the smallest key >= x encountered and descend through the gap that could contain a closer candidate. Stop at an exact match or after reaching an external child; return the candidate or none. This is a general B-tree search extension, not a separate lecture algorithm.
min / max Follow the leftmost / rightmost child at each internal node and select the extreme key in the terminal node. Stop at the leaf; return none for an empty tree. The path has O(logn) node visits.
Inorder / range traversal Emit each child range and intervening key in sorted order. A range scan can skip ranges outside its bounds. Stop when traversal ends or the next key exceeds the upper bound. Full inorder work is O(n); range work includes visited nodes and emitted results.
Build The shown build processes records by repeated bottom-up insertion. The 12-key trace is illustrative, not a bulk-loading algorithm. Stop after each input record is processed. Repeated insertion has worst-case O(nlogn) total node visits; duplicate behavior follows the dictionary's key policy.
Meld The current page's general method is inorder traversal, merge the sorted key streams, then rebuild a legal tree. This is a rebuild, not constant-time root splicing. Stop after every record is represented once and ordering, occupancy and common leaf depth hold. The page does not specify a specialized ordered-join algorithm or its cost.
Red-black correspondence Collapse each red child into its black parent to view a degree-2-to-4 node; color flips correspond to regrouping. This explains a structural relationship, not a 2–3–4 insertion/deletion procedure. Use only as a representation/height argument. Lecture 9's collapse property preserves equal external depth and bounds the collapsed node degrees between two and four.

Common mistakes

  • A three-key node is full but legal. Overflow begins only when insertion creates four keys.
  • In the course's even-size overflow, promote key 2 of four, not the third key. The left split has one key and the right split has two.
  • Insert the promoted separator in sorted parent position and put the new child pointer beside the split child. A leaf split does not change leaf depth.
  • When borrowing, the parent key moves down and the donor's boundary key moves up. Moving only a sibling key would break the separator ranges.
  • Internal deletion removes the predecessor's old leaf copy after replacement. If that leaf empties, repair is still required.
  • Merge includes the parent separator. Removing that separator may underflow the parent and trigger another merge; an empty root with one child contracts.
  • Top-down preemptive splitting and bottom-up overflow splitting are different variants. Do not describe the former as the method shown in Lecture 10.
  • A 2–3–4 node stores three keys at most; “four” refers to its maximum of four children.

Exam focus

  • Order 4 means at most four children and three keys; each nonroot has at least two children and one key.
  • Bottom-up overflow [a,b,c,d] promotes b, leaving [a] and [c,d].
  • Continue insertion splits upward only while the parent overflows; root split adds one level.
  • Internal deletion: predecessor replacement, leaf removal, then occupancy repair.
  • Borrow from a surplus sibling through the parent; merge with a minimum sibling plus the parent separator otherwise.
  • Check key order, child-range order, 1–3 keys in every nonroot node, and a common external-leaf depth after each repair.
  • Worst-case search, insertion and deletion visit O(logn) nodes for fixed order; building by n insertions is O(nlogn).

Practice questions

  1. A bottom-up insertion produces [4,7,9,12]. Which key is promoted, and what are the two resulting nodes?
Answer

Promote the second key, 7, because ceil(4/2)=2. The left node is [4] and the right node is [9,12].

  1. A deficient right child has an empty leaf and its left sibling has [10,14], with parent separator 20. What moves where?
Answer

Move 20 down into the deficient right child and move the left sibling maximum 14 up to replace it. The left sibling becomes [10].

  1. Why does deleting an internal key not always end after copying its predecessor?
Answer

The predecessor still has to be physically removed from its old leaf. If that leaf had one key, it becomes empty and requires borrowing or merging.

  1. A deficient leaf and its sibling each have zero and one key respectively, under a one-key parent. Why merge, and what should be checked next?
Answer

The sibling has only the minimum and cannot lend. Merge the leaf, sibling, and parent separator; then check whether the parent became empty and must be repaired upward. If the root becomes empty with one child, contract it.

  1. How can top-down and bottom-up insertion both be valid yet produce different trees for the same keys?
Answer

Top-down splits a legal three-key node before descent. Bottom-up first inserts the key and splits a four-key overflow, promoting the second of four. The split sees different key sets, so the resulting separators and shape can differ while the B-tree invariants remain true.
