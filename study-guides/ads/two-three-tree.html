2-3 tree

The smallest useful B-tree: every data node holds one or two keys, and all leaf levels agree.

Rule and fresh build

A 2-node has one key and two child ranges. A 3-node has two keys and three ranges. These names count children, not keys. This is a B-tree of order 3.

Fresh order-3 build from [1, 2, 3, 4, 5, 6, 7]

Input list[1, 2, 3, 4, 5, 6, 7]

1 · Insert 1, then 2

Insert 1 and then 2 into the root leaf in sorted order. An order-3 node holds at most two keys, so [1,2] is full but legal; stop without creating children.

2 · Insert 3; split the root

Insert 3 to form the temporary overflow [1,2,3]. Split around the median 2, leaving [1] and [3] on its ordered sides. Since there is no parent to receive 2, create a new root; all leaves remain at one depth and height increases by one.

3 · Insert 4 and 5

Insert 4 into the right leaf [3], then 5 makes [3,4,5] overflow. Promote 4 between parent key 2 and the right range. The parent becomes [2,4], within its two-key capacity, so the bottom-up repair stops.

4 · Insert 6

The search path for 6 ends in [5]. Adding 6 gives [5,6], exactly the capacity, so no split or promotion occurs and the leaf-depth invariant is unchanged.

5 · Insert 7; split the leaf

Insert 7 into [5,6] to form [5,6,7]; promote median 6 into parent [2,4]. The split creates ordered ranges [1], [3], [5], [7], but parent [2,4,6] now overflows, so continue upward.

6 · Split the parent and create root

Split the overflowing internal node [2,4,6] around 4. Make 4 the new root; its children [2] and [6] retain the correctly ordered leaf ranges. Every nonroot has one or two keys and every leaf is at the same depth, so stop.

Operations and caveats

Search, insert and delete take O(logn) worst-case time. Insert into a leaf. A temporary three-key overflow splits into one-key children and promotes the median. Deletion borrows through a parent from a two-key sibling or combines a deficient node with its one-key sibling and the parent separator. Repairs may propagate to the root.

Borrow, then merge in an order-3 B-tree

1 · Start

The root separator 10 divides the leaves [5] and [15,20]. Each nonroot leaf has the required one key; the right sibling has one surplus key, so it can lend if the left leaf becomes deficient.

2 · Delete 5; left leaf is deficient

Delete 5 from the left leaf. The resulting empty node is below the nonroot minimum, so inspect an adjacent sibling and its parent separator rather than stopping. [15,20] can lend one key and still retain one.

3 · Borrow via the parent

Rotate through the parent: move separator 10 down to the left leaf and move the right sibling minimum 15 up. The result [10] | 15 | [20] has valid key ranges and both leaves meet minimum occupancy, so stop repairing.

4 · Delete 10; sibling cannot lend

Delete 10 from the left leaf, leaving it empty. Sibling [20] is at minimum and cannot lend, so combine the empty child range, parent separator 15, and sibling key 20. The root loses its only key and must be handled next.

5 · Contract the empty root

The empty internal root has just one remaining child [15,20]. Replace the root pointer with that child; the tree is now a legal one-node leaf and height decreases by one.

Other methods and exam focus

Initialize an unsorted list by repeated insertion in O(nlogn). A legal bulk build from sorted records can take O(n). Inorder produces the sorted list in O(n). lowerBound, min and max cost O(logn). General meld needs ordered merging/rebuilding rather than a heap-style constant-time root link. Two-child logical deletion first reduces to a leaf deletion.

Can an ordinary 2-3-tree node hold three permanent keys?

Check your answer

No. Three keys are a temporary overflow requiring a split. A 3-node holds two keys.

How to choose the operation

An order-3 tree is a B-tree with at most three children and two keys per node. A 2-node has one key and (when internal) two child ranges; a 3-node has two keys and (when internal) three child ranges. Nonroot nodes must retain at least one key, and every leaf stays at the same depth. In this lecture's variant, insertion first descends to a leaf and repairs overflow on the way back up; deletion replaces an internal key with its predecessor before physically deleting from a leaf.

Method Decision Stop condition and edge cases
Search / get Compare keys in order; equality identifies a stored record. Otherwise descend through the unique child range between adjacent keys. Stop on equality or a missing external child. Empty-tree search fails immediately. Unlike B+, equality at an internal key succeeds because the record is stored there.
Insert / put Descend to a leaf and insert in sorted order. A three-key temporary overflow splits into one-key nodes and promotes its median; insert the promoted key and new child link into the parent. Stop when a parent has room. If it overflows, split it and continue upward. If the root overflows, make a new root. A duplicate key updates its value and does not create another key or split.
Build For unsorted input, apply the lecture insertion procedure once per record. Stop after every input record is handled. Repeated insertion is O(nlogn) worst case for fixed order. A separate sorted bulk builder can be linear; it is not the procedure traced below.
Delete / remove Find the record. For an internal key, copy its predecessor (largest key in its left subtree) into that position, then remove the predecessor from its leaf. Stop when the leaf still has a key or repair restores occupancy. A missing key changes nothing. Empty leaf root is a valid empty tree; empty internal root contracts to its only child.
Borrow / redistribute If a neighboring sibling has two keys, rotate one boundary key through the parent: parent separator goes to deficient node, sibling boundary key replaces it. For internal nodes, move the corresponding child pointer with the keys. Stop once the deficient node has one key. Check either side; a one-key sibling cannot lend. Left and right rotations are mirror cases, but the parent separator direction must match the child ranges.
Merge / combine When neither adjacent sibling can lend, combine the deficient child, one parent separator, and a one-key sibling; concatenate child pointers in key order for internal nodes. The parent loses one key and one child. If it becomes empty and is nonroot, continue upward. If the root becomes empty, replace it by its sole child; a root leaf may simply become empty.
lowerBound(x) Track the least key at least x encountered, then descend into the only range that could contain a closer candidate. Stop at equality or after reaching a leaf. Return the retained candidate, or none when no key is at least x.
min / max Follow the leftmost / rightmost child at each internal node, then take the first / last key in the leaf. Stop at a leaf; return none for an empty tree.
Inorder / range traversal Emit child, key, child in ascending order; for a range, skip subtrees outside the requested bounds. Inorder visits all nodes and records in O(n). A range traversal stops when the next key exceeds its upper bound or traversal is exhausted.
Meld There is no general constant-time root-link operation for 2-3 trees. For arbitrary inputs, traverse in order, merge sorted records, then rebuild a legal tree. Stop after each distinct key is represented once and occupancy/order/equal-leaf-depth invariants hold. A specialized ordered join is a different operation and is not detailed by this lecture.

Equality, duplicates, and absence

  • Duplicate insertion: equality at either an internal node or leaf is found before descending past it. For dictionary semantics, replace the associated value and preserve one key occurrence; do not split.
  • Missing search: descend through the range selected by comparisons. Reaching an external child means failure; no node changes.
  • Missing deletion: perform the same search first. If the key is absent, return without changing occupancy, so there is no underflow repair.
  • Empty tree and root leaf: an empty search or lowerBound returns no result. First insertion creates a root leaf. Deleting its sole key leaves an empty tree; it is not an internal-root contraction.
  • Internal equality: a 2-3 tree stores dictionary records in internal nodes as well as leaves, so a matching separator is a successful search result. B+ trees instead store records only in leaves and must continue through an equal separator to a data leaf.

Cost and invariant checks

Search, insertion, and deletion take O(logn) worst-case node visits for fixed order 3; there is no expected or amortized bound being claimed here. Inorder traversal takes O(n), and repeated insertion of n records takes O(nlogn) worst case. These costs count key comparisons up to a constant per node because an order-3 node contains at most two keys. A sorted bulk build is a separate method and is not the lecture's bottom-up insertion procedure.

After each insertion or deletion, check: keys within each node are strictly increasing; each child occupies the interval bounded by neighboring keys; an internal node with t keys has t+1 children; every nonroot has one or two keys; all leaves share a depth; and inorder traversal contains each distinct key once. During insertion only the current split path may temporarily contain three keys. During deletion only the path from the physically removed leaf may be deficient, and repair continues until legal or the empty root is contracted.
