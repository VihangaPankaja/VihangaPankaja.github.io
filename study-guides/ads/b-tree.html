B-tree

Store many ordered keys in one node to reduce disk or cache accesses. Split overfull nodes; repair underfull ones by borrowing or merging.

Rule and order convention

Order m means at most m children and m−1 keys, not a minimum degree. Each nonroot data node has at least ceil(m/2)−1 keys. An internal root has at least two real children; a one-node root can be a leaf. All external failure nodes are at the same depth. The lecture's extended-tree definition counts external children even under data leaves.

Each internal node with t keys has t+1 child ranges. Equality finds the pair in that node, unlike B+ search, which must reach a leaf.

Fresh order-3 build from [1, 2, 3, 4, 5, 6, 7]

Input list[1, 2, 3, 4, 5, 6, 7]

1 · Insert 1, then 2

The first two distinct pairs fit in the root leaf because an order-3 node holds at most two keys. Insert each key in sorted position; there is no child range to descend into, and stop while occupancy remains within the limit.

2 · Insert 3; split the root

The third key creates the temporary overflow [1,2,3]. Promote the 1-based middle key 2, leaving [1] and [3] as children so their ranges stay below and above the separator; because the overflowing node was the root, create a root and stop when both leaves have one key.

3 · Insert 4 and 5

Insert 4 into the rightmost leaf [3], then 5 makes [3,4,5] overflow. Promoting 4 inserts it between parent key 2 and the right child range; the parent now has legal keys [2,4], so the split repair stops here.

4 · Insert 6

The search path for 6 ends at the rightmost leaf [5]. Adding 6 gives [5,6], exactly the two-key capacity, so no promotion is needed and the equal leaf depth/order invariant is unchanged.

5 · Insert 7; split the leaf

Key 7 makes the right leaf [5,6,7] overflow; promote median 6 into parent [2,4]. The child split preserves the three ordered ranges, but [2,4,6] is now a temporary parent overflow, so continue the split upward rather than stopping.

6 · Split the parent and create root

Split the overflowing internal node [2,4,6] around 4: the new root is [4], and its children [2] and [6] retain their corresponding leaf ranges. Every leaf is still at depth two, each nonroot node meets minimum occupancy, and the root split is the only step that increases height.

Operations

Search the ordered keys within each visited node and descend into the appropriate gap. With binary search inside a node, comparisons cost O(logm) per level. Height is O(logmn) for meaningful m≥3, so comparisons are O(logn), while block reads are O(logmn). Array shifts and split work can cost O(m) per affected node.

Insert into a leaf; when it has m keys, promote the key at 1-based position ceil(m/2), creating two legal nodes. Continue upward until a parent has space or a new root is made. Build from an unsorted list by repeated insertion, O(nlogn) for fixed m. Bulk loading sorted data is a separate construction method.

For delete, an internal pair can be replaced by its predecessor. Physically delete at a leaf, then repair an underflow. Borrow from an adjacent sibling with surplus, moving a separator through the parent. Otherwise merge with a sibling and the separating parent pair. A root with zero keys contracts to its only child.

Borrow, then merge in an order-3 B-tree

1 · Start

Start with root separator 10 and leaves [5] and [15,20]. Each nonroot leaf meets the one-key minimum; note that the right sibling has one surplus key, which determines the repair if the left leaf becomes empty.

2 · Delete 5; left leaf is deficient

Delete 5 from the left leaf. The empty leaf violates the nonroot minimum, so do not stop: inspect an adjacent sibling and the intervening parent separator; the right sibling [15,20] can lend because it will retain one key.

3 · Borrow via the parent

Rotate through the parent: move separator 10 down to the deficient left leaf and move the right sibling minimum 15 up to replace it. The result [10] | 15 | [20] has sorted ranges and both leaves satisfy minimum occupancy, so repair stops.

4 · Delete 10; sibling cannot lend

Delete 10 from the now-one-key left leaf, leaving it empty. The right sibling [20] has only the minimum and cannot lend, so merge the empty range, parent separator 15, and sibling key 20; remove the consumed parent separator and continue upward because the root is now empty.

5 · Contract the empty root

An empty internal root has exactly one remaining child after the merge. Replace the root pointer with that child [15,20]; this removes one level, leaves the only node as a legal root leaf, and ends the underflow repair.

Special cases and exam focus

The 2-3 tree is order 3, the 2-3-4 tree order 4, and an order-5 tree permits 3, 4 or 5 children below the root. The order-2 case is degenerate and does not give the usual useful logarithmic occupancy bound.

The lecture's insertion I/O count assumes all h nodes on the descent remain cached: h reads plus 2s+1 writes for s splits, at most 3h+1 accesses. Bigger m lowers height but increases transfer and within-node work. The timing examples in the slides illustrate a disk model, not current hardware benchmarks.

General meld is not pointer splicing. Inorder merge plus a legal rebuild is linear once the sorted sequences are available. Ordered joins can use specialized methods. Min/max follow extreme child pointers; range output costs height plus visited output blocks.

When does B-tree insertion increase height?

Check your answer

Only when the root splits and a new root is created. Splitting a lower node alone does not change the tree height.

Method decisions

For an order-m B-tree, max children is m, max keys is m−1, and every nonroot node has at least ceil(m/2)−1 keys. Search the keys inside a node, then follow the unique child gap. The tree's failure leaves all occur at the same depth.

Method Decision Stop condition and edge cases
Search / get Compare within each visited node; equality succeeds in that node, otherwise descend through the matching gap. Stop on equality or at an external failure child. An empty tree fails immediately. Equality does not descend as it does in B+.
Insert / put Route to a leaf and insert in sorted order; an existing dictionary key updates its value. Split an m-key overflow at 1-based position ceil(m/2), then carry the promoted pair and new child pointer upward. Stop when a parent has room. Continue through each overflowing ancestor; split the root by creating a new root. Duplicate update does not change key count or split.
Build For an unsorted list, repeated insertion applies the same duplicate policy and split rules. Stop after all records have been processed; fixed-m repeated insertion is O(nlogn) in a balanced B-tree. Sorted bulk loading is a separate algorithm, not the trace below.
Delete / remove If the match is internal, copy the complete predecessor pair from the maximum key in its left subtree, then physically remove that predecessor from a leaf. Repair any underflow by borrowing through a parent or merging with a sibling and separator. Stop when occupancy is restored or the root is handled. Missing key changes nothing. An empty root with one child contracts; a root leaf may become empty.
Borrow / redistribute Prefer an adjacent sibling with more than the minimum occupancy. Rotate the parent separator down and the sibling boundary pair up; for internal nodes, transfer the corresponding child pointer too. Stop once the deficient node reaches its minimum. Check both left and right siblings; never borrow from a sibling at minimum.
Merge If no adjacent sibling can lend, combine the deficient node, one parent separator, and one sibling; concatenate child pointers in key-range order for internal nodes. The parent loses one key and one child link; if it underflows, continue upward. If the root becomes empty, replace it by its only child.
lowerBound(x) At each node retain the smallest key ≥ x seen so far, then descend into the range that could contain a closer candidate. Stop at an exact match or external leaf; return the candidate, or none if no key ≥ x exists.
min / max Follow the leftmost / rightmost child at each internal node, then take the extreme key in the leaf. Stop at a leaf; empty tree returns none. Cost is proportional to height in node visits.
Range / inorder Range search finds the first qualifying key and visits only in-range keys and child ranges; inorder recursively emits child, key, child in sorted order. Stop when the next key exceeds the upper bound or traversal is exhausted. Inorder costs O(n); range cost is height plus visited output blocks/records.
Meld / ordered join General meld is inorder traversal, merge sorted key sequences, then a legal rebuild. An ordered join can use a specialized height-aware algorithm when the key ranges are disjoint. Stop after all records are represented once and occupancy/order/leaf-depth invariants hold. It is not constant-time root-pointer splicing.

Contrasting query and key-update cases

  • Missing search/delete: at each node choose the child gap for the query. Reaching an external child proves absence; return failure and leave the tree untouched. Do not try to repair an underflow when no key was removed.
  • Duplicate insertion: if equality is found in an internal node or leaf, update the associated value in a dictionary. Keep one key occurrence, do not descend past the match, and do not split.
  • Internal equality versus B+: ordinary B-tree lookup may stop at an internal separator because that node stores the record. B+ lookup must continue to a leaf because internal separators are routing copies.
  • Empty and root cases: empty search/min/max return no record; first insertion creates a root leaf. A root may have fewer keys than other nodes; a nonempty internal root has at least two children. Only an empty internal root contracts to its sole child.

Invariant checks to apply after every edit

Check (1) keys increase strictly within every node, (2) each child subtree stays within its adjacent separator bounds, (3) nonroot occupancy is between ceil(m/2)−1 and m−1 keys, (4) an internal node with t keys has t+1 children, (5) all leaves have equal depth, and (6) inorder traversal contains every distinct dictionary key exactly once. During insertion, only an m-key node is temporarily overfull; during deletion, only the path from the physically changed leaf may be underfull. Repair must continue upward until every affected node is legal or the root is contracted.

Cost and I/O interpretation

With binary search within nodes, search uses O(logm) comparisons per level and O(logmn) levels, giving O(logn) key comparisons under the standard meaningful-order assumptions. Block reads are O(logmn). Shifting keys/child pointers and splitting a node can cost O(m) per affected level. The lecture's insertion I/O count is conditional: if all h descent nodes stay cached, count h reads and 2s+1 writes for s splits (at most 3h+1). It is a disk model, not a current hardware timing claim. The order-2 case is a degenerate full binary tree and lacks the useful occupancy bound of m≥3.
