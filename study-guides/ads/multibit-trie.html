Multibit trie and routing

Rule and longest-prefix search

A node with stride s indexes 2^s child choices and prefix fields. Fixed stride means all nodes at one level use the same stride; variable stride permits different choices at different nodes. A lookup tracks the best matching original prefix seen so far, continuing until bits or branches run out.

Fresh build from routing prefixes P=00*, Q=000*, R=1*; root stride 3

1 · Empty table with eight slots

With stride 3, the root chooses exactly one of eight 3-bit cells; the empty markers mean no route has matched yet. Continue by filling the rule table, and stop at this node only for a route whose original prefix ends here.

2 · Add P=00*

P=00* agrees with the first two bits of 000 and 001, so those two cells carry P as a fallback. Both cells still record specificity 2; continue looking for longer routes and stop expansion at the next stride boundary.

3 · Add Q=000*

Q=000* matches only cell 000 and has original length 3, so it replaces P there while P remains in 001. The update is a longest-prefix comparison, not a last-write rule; keep the more specific Q and continue with other slots.

4 · Add R=1*

R=1* matches all four cells 100 through 111, but its stored specificity remains 1. It fills only cells without a longer route, so the existing P and Q choices remain; stop after all four matching cells are covered.

Lookup and delete must preserve fallback rules

1 · Lookup destination 000101

The first three destination bits index slot 000, whose best stored match is Q=000*. Remember Q as the current candidate and stop only if no deeper matching prefix can exist or all address bits are consumed.

2 · Delete Q=000*

Deleting Q removes the exact rule, then recomputes slot 000 from remaining original rules; P=00* is next most specific. Keep P rather than leaving the cell empty, and continue this restoration for every expanded cell affected by a deleted prefix.

3 · Lookup 000101 again

The same destination again reaches slot 000, but Q is gone and P is now the best candidate. Return P when traversal ends or the next branch is absent; a failed deeper lookup must not discard this saved fallback.

Operations and costs

A 1-bit trie takes O(W) per routing operation for W address bits. With fixed stride s, a lookup takes O(⌈W/s⌉) node visits when indexing each node is constant time. Variable-stride height is the number of nodes on the chosen path, with consumed strides totaling at most W.

Do not give expanded insertion/deletion the same cost as lookup. A prefix ending t bits before a stride boundary can populate 2^t slots, and deletion may need fallback restoration. Building inserts each rule with this expansion work. A stride of 32 makes one IPv4 level but requires 2³² choices at that node. Smaller strides trade levels for memory.

Routing distinctions and two-dimensional filters

An address/mask rule matches where all mask-1 bits agree. A prefix mask has contiguous 1s followed by 0s. In six bits, 101100/110000 is 10*, covering [32,47]. First match, highest priority, most specific range and longest prefix are different policies. Overlapping ranges [4,14] and [6,16] have no containment ordering.

Two-dimensional destination/source matching

1 · Build two rule entries

Store A=(0,11,cost 4) and B=(00,1,cost 2) as separate destination-prefix entries, each associated with a source-prefix search. Insertion records a pair, not a single prefix; stop after both dimensions and the cost are represented.

2 · Query packet (0010,1100)

Destination 0010 follows both 0* and 00* entries. The packet source 1100 also matches both 11* and 1*, so retain both complete rule matches; stop when each matching source search has been checked.

3 · Apply least-cost tie breaker

Both rules matched, so apply the stated least-cost tie breaker: B costs 2 and A costs 4, therefore choose B. Do not choose by destination prefix length alone; stop after the required policy has ranked the complete matches.

Caveats and exam focus

The lecture's destination 100000000 matches 1, 10, 1000, 100000 and 1000000. The last is the longest match. A missing deep branch must fall back to the best earlier prefix. TCAM compares ternary 0/1/ entries in hardware and uses a priority encoder, but capacity, power and cost are constraints.

Fixed-stride expansion: keep the original prefix length

An expanded cell is a storage address for a set of destinations, not a rewritten routing rule. Keep each rule's original prefix length (or its explicit priority under a different policy) beside every expansion. For an s-bit boundary, a prefix that stops t bits early covers 2^t cells at that boundary. A later, more-specific rule overrides only its overlapping cells; deleting it means recomputing those cells from the remaining original rules.

It uses a teaching fixed-stride layout with boundaries at /3, /6, and /9; the lecture supplies the rules and prefix-expansion principle, while this explicit multi-level expansion is a supplemental worked example. In the /3 root, each cell represents one three-bit string. In a /6 child, suffixes are appended to that cell's three bits. In a /9 child, append three more bits. Text such as P4(len 1) names the winning original rule and preserves its true specificity.

Lookup, update, and policy edge cases

For lookup, compare a destination against each stride's selected prefix field and retain the best original prefix seen. Stop when all address bits are consumed or the selected branch is missing; return the saved candidate, or no route if none matched. A /0 default is a valid fallback for every address. A rule ending exactly on a stride boundary occupies one corresponding prefix field; it is not expanded at that boundary. At the maximum address width, stop without reading beyond the address.

For insertion, first identify the prefix cells it covers at the chosen boundary, then compare against each cell's existing candidate by original specificity. A duplicate prefix replaces that same rule's next-hop/value; it does not create a second equal-length match. When an update crosses a stride boundary, split the affected region into the exact child cells and continue. For deletion, remove the original rule and restore the next-longest surviving rule in every affected cell. If the target is missing, make no changes. These update steps describe the table expansion in this teaching model; the lecture does not prescribe a universal production router update algorithm.

Expansion work versus lookup work

With fixed stride s, a lookup reads at most ceil(W/s) nodes for W address bits, assuming direct array indexing is constant time; each visit also checks the candidate stored for that cell. This is a worst-case node-visit bound. A variable-stride path can consume different numbers of bits at each node: its lookup visits one node per selected stride and stops after the total consumed stride reaches W or a branch is absent. It is not generally the same number of visits as fixed stride.

An update is not one lookup. If a rule ends t bits before the next selected stride boundary, it may write 2^t expansion cells. Replacing or deleting a longer rule can touch each affected cell, and deletion may search the surviving rules to restore a fallback. Thus the concrete work is proportional to the cells expanded or repaired, plus the traversed path; lookup's O(⌈W/s⌉) must not be quoted as the insertion/deletion cost. Building n rules by repeated insertion sums this per-rule expansion work. Large strides reduce path visits but require 2^s fields at that node; for example, stride 32 has 2^32 choices. The lecture's 1-bit trie states O(W)/operation; that bound does not imply a multibit update is independent of expansion size.

Routing policy and representations

Longest prefix compares the number of original leading bits. First-match uses rule order, and highest-priority uses a configured priority; neither can be substituted for longest prefix without an explicit policy. “Most specific range” is also different: overlapping ranges [4,14] and [6,16] are not nested, so there is no longest-prefix-style ordering. An address/mask rule matches when every mask-1 bit agrees; only a mask of leading ones followed by zeros is a prefix. The lecture's 101100/110000 is 10*, the six-bit interval [32,47].

The lecture's 2D filters associate a destination prefix with a source-prefix trie. A packet is a match only when both dimensions match; enumerate the complete matching rules and then apply the stated tie-breaker. For example, (0,11,4) and (00,1,2) both match destination 0010 and source 1100, then least cost chooses the second rule. Longer destination prefix alone does not define least-cost policy. This follows the lecture's slide 56; the explicit nested topology is shown on slides 57–58.

TCAM is a hardware alternative that compares ternary 0/1/* entries in parallel and uses a priority encoder; it can implement longest-prefix or priority selection when entries are ordered accordingly. Lecture 13 names capacity, cost, power, board space, IPv6 scalability, ranges, and multidimensional filters as limitations. It does not provide a TCAM insertion/deletion algorithm or a numeric complexity claim, so none is assumed here. Likewise, fixed-stride selection is posed as an optimization problem—least memory subject to height at most k—but no solving algorithm is given in the lecture.

Compact method decision table

Method / operation Decision Stop condition Edge cases and cost boundary
1-bit trie lookup Inspect one bit per branch; retain longest matching prefix. Address ends or next branch is absent. Return earlier candidate on missing deep branch. Lecture states O(W) per operation.
Fixed-stride lookup Index one 2^s-way table using the next s bits; retain the longest original prefix. W bits consumed or selected branch absent. At most ceil(W/s) node visits with O(1) indexing; large s costs 2^s fields.
Variable-stride lookup Use each visited node's own stride and retain the candidate. W bits consumed or branch absent. Path height varies; sum of consumed strides is at most W.
Prefix insertion / expansion Fill each covered cell at its next stride boundary, preferring the more-specific original rule. All matching cells are filled at the represented boundary. Up to 2^t cells when t bits remain before boundary; duplicate prefix updates that rule.
Prefix deletion / fallback repair Remove the rule, then select the next-longest surviving rule in every affected cell. All affected expansions are recomputed. Missing rule changes nothing; default /0 may be restored. Work includes each repaired cell.
Longest-prefix policy Rank matching prefixes by original length. All possible matching levels checked or no deeper branch exists. Expanded strings do not gain specificity.
Address/mask or range filtering Test all mask-1 positions; prefix masks are only the contiguous-leading-one case. Rule match is decided for each candidate. Non-prefix masks and crossing ranges do not form an LPM ordering.
2D destination/source trie Require both destination and source match; apply the requested tie-breaker to full rules. All relevant pairs are checked. Least cost can select a rule whose destination prefix is not uniquely decisive.
TCAM lookup Parallel ternary comparison followed by priority encoding. Priority encoder chooses the highest-ranked matching entry. Hardware design; lecture lists capacity/cost/power and multidimensional limits, not update mechanics.
Fixed-stride memory optimization Choose strides to minimize memory under height bound k. Optimization constraints are satisfied. Lecture states the problem but gives no solving procedure.

Contrasting diagrams and boundary checks

The lecture's small stride-three tree on slide 33 shows why node-local strides matter: after root stride 1, the zero child uses stride 2 while the one child uses stride 1. The same address can therefore consume a different number of bits at each level. A missing child ends that path and returns the best earlier prefix, not an empty result when a candidate exists. The eight-prefix example above uses a fixed 3-bit teaching layout to make expansion arithmetic visible; it is not a claim that the lecture's router example uses stride 3.

On slide 43, destination 100000000 matches P4=1, P1=10, P6=1000, P7=100000, and P8=1000000*. The longest original prefix is P8. On slide 46, TCAM can instead apply its priority ordering among ternary entries; that ordering must be configured to implement LPM. A range rule and a two-field destination/source rule require their own match and ranking policies. These representations solve related packet classification tasks but are not interchangeable algorithms.
