Winner tree

Treat records as players. Each internal match remembers its winner, so the root identifies the next record to output.

Rule and build

A tournament has n player leaves and n−1 match nodes. A min winner tree lets the smaller key win. Store player identities with keys so equal values remain distinguishable. The lecture gives the left player the tie.

Fresh build from players [4, 3, 1, 5]

Input list[4, 3, 1, 5]

1 · Place players

P1–P4 stay in their fixed left-to-right leaf slots; the leaves are inputs, not values moved during play. There is no comparison yet, so stop placing and begin the first round only after all four identities and keys are present.

2 · Play the first round

Compare the two disjoint first-round pairs: P1(4) loses to P2(3), and P4(5) loses to P3(1). Each winner summarizes its own subtree; continue with those two winners because neither has yet met the other.

3 · Play the final

The final compares P2(3) against P3(1), so P3 wins and is stored at the root. The root now summarizes all four leaves; construction stops after n−1=3 matches, with player identity preserved alongside the key.

Operations

Build bottom up in O(n). Read the winner in O(1). Replace a player and replay only matches on that player's path to the root in O(logn). Searching for an arbitrary key is O(n). Fixed player slots have no cheap general insert, delete or meld. An exhausted run can use an explicit inactive flag, ordered after every live player.

Replace the winner and replay

1 · Replace P3: 1 becomes 6

Replace P3 in its original leaf with 6; the old summaries above that leaf are now stale, while the sibling leaf P4 still holds 5. No other leaf changed, so only P3’s ancestors can be affected; start replay at its first match.

2 · Replay P3 against P4

At P3’s leaf match, compare new key 6 with P4’s 5. P4 wins and replaces the stale summary at this node; now continue to the parent because that parent previously summarized the old winner P3.

3 · Replay the final

Compare the updated right-subtree winner P4(5) with left-subtree winner P2(3). P2 wins, so the root is valid again and replay stops; the untouched left subtree needed no comparisons.

Special use: first-fit bin packing

Store remaining bin capacities in a max winner tree. First check the root: if its maximum is smaller than item size s, open a new bin (or reject an item larger than bin capacity). Otherwise go left if the left subtree maximum is ≥ s, and right if it is not. This finds the leftmost bin that fits, rather than merely the bin with maximum capacity. Subtract s from that leaf and replay. An item of size 7 among capacities [4,3,6,8] goes to bin 4, whose new capacity is 1.

Common mistakes and exam focus

Replay is not heap trickle down. Players stay in their slots, while summaries change above them. If n is not a power of two, use a complete tournament layout or inactive padding. Use the same tie rule during construction and replay.

How many comparisons build an n-player binary tournament?

Check your answer

n−1. Every match eliminates one candidate.

A complete eight-player tournament, ties, and exhaustion

This supplemental construction uses eight fixed players so every round and every replay level is visible. A match node stores the winning identity and key. Equal keys go to the player in the left child, exactly as in the lecture.

Build an eight-player min winner tree from [12, 7, 7, 15, 4, 9, 4, 11]

Input list[12, 7, 7, 15, 4, 9, 4, 11]

1 · Place the eight fixed players

The ordered leaves are P1=12, P2=7, P3=7, P4=15, P5=4, P6=9, P7=4, and P8=11. The tree has 8 external leaves and 7 match nodes.

2 · Round one: four independent matches

P1(12) vs P2(7) → P2(7). P3(7) vs P4(15) → P3(7). P5(4) vs P6(9) → P5(4). P7(4) vs P8(11) → P7(4). Each winner replaces only its local match summary. Continue because four candidates remain.

3 · Round two: tie comparisons go left

P2(7) vs P3(7) ties, so the left player P2 advances. P5(4) vs P7(4) ties, so P5 advances. The four first-round matches remain unchanged; continue because two subtree winners still need the final match.

4 · Final: root winner

Compare P2(7) with P5(4); P5 wins and becomes the overall winner. Construction stops with 7 comparisons for 8 players. The root is the minimum and all internal summaries agree with their child matches.

Winner replacement and replay cases

The following table gives every internal summary in heap order root, level 2, level 3 (the diagrams label branches L and R). It is a compact exact-state check: leaves never move, and only ancestors of the replaced leaf are replayed.

Replay three ancestors, then test a tie and an exhausted player

1 · Replace P5=4 with P5=14

The changed path is P5 → node 6 → node 3 → root. Keep all other player leaves and off-path match summaries.

2 · Replay P5 against P6

Continue upward: node 3 still incorrectly says P5=4, so it must be recomputed using its updated left winner.

3 · Replay P6 against P7

The parent summary changes from P5 to P7. Continue to the root because its right child summary changed; the root cannot be assumed correct yet.

4 · Replay the final match and stop

P7 wins, making the root correct. Stop here: no ancestor remains. Exactly three match nodes were replayed, while the four matches outside P5’s path were untouched.

5 · Equal replacement preserves the left tie rule

Replay P2 with its unchanged key 7 to check that the tie rule is consistent. At node 4, P2=7 beats its actual opponent P1=12. At node 2 P2 ties P3 again and wins by the same rule; at the root P7=4 still beats P2=7. Replay ends at the root; do not treat equal keys as interchangeable identities.

6 · Mark an exhausted player inactive

After P2’s run is exhausted, retain its slot and set an explicit inactive status that loses to every live player; do not encode exhaustion as a numeric key. P1=12 replaces it at node 4, then P3=7 beats P1 at node 2 and advances to the root. P7=4 still wins the final match. Stop once the root has been recomputed. If every leaf is inactive, report no winner instead of returning the sentinel as a real player.

First Fit with a max winner tree

In bin packing, each leaf stores a bin’s remaining capacity, not its original capacity. First Fit preserves the bins’ left-to-right opening order. At a node, go left whenever the left subtree maximum is at least the item size; otherwise go right. This finds the leftmost feasible bin even when another bin has more free space.

Pack item sizes 7, 9, and 11 into bins of capacity 10

1 · Initial eight-bin capacity tree

Each node stores the largest remaining capacity below it. For item size 7, root max 8 proves a fit exists; descend left if that child can fit 7.

2 · Follow the leftmost feasible path for size 7

At the root, left max 8≥7, so choose bins B1–B4. Their left child max 4<7, so choose B3–B4. There left max 6<7, so choose B4. Subtract 7: B4 changes from 8 to 1. A capacity exactly equal to the item size also fits and leaves zero.

3 · Replay maxima after packing size 7

Only the ancestors of B4 need recomputation: max(B3=6,B4=1)=6; max(B1–B2=4,B3–B4=6)=6; max(B5–B8)=7; root max is 7. Stop at the root. The max tree has restored the invariant that every internal value is the maximum of its descendants.

4 · No current bin fits item size 9

Because max 7<9, there is no feasible leaf and First Fit opens the next bin in the sequence. With capacity 10, place the item there and record remainder 1. Adding leaves may require the chosen implementation to rebuild or grow its complete tournament layout; the lecture does not prescribe that layout-maintenance procedure.

5 · Reject an item larger than bin capacity

Check size 11 against capacity 10 first and reject or report invalid input; opening a new capacity-10 bin cannot make this item feasible. For a valid item of size at most 10, root max below its size means open a new bin. Equality at root or at a child is a fit (≥), not a no-fit case.

Method decision table

Method Decision Stop condition Edge cases and course boundary
Build a winner tree Compare each pair bottom-up; store the winning player identity and key at the match node. Stop after all n−1 matches have been computed; O(n) time. Left player wins equal-key ties. For non-power-of-two n, pad with inactive leaves or use a complete layout; lecture specifies complete binary layout but not a unique padding implementation.
Read overall winner Return the root summary. O(1); stop at the root. If every player is inactive, return “no live player,” not the inactive marker.
Replace winner and replay Change the winner’s fixed leaf, then recompute each match on its leaf-to-root path. Stop at the root; Θ(logn) matches for a balanced complete tree. Preserve identity on equal keys; exhausted streams can be explicitly inactive and sort after live players. This update assumes the current winner’s leaf is known.
Search for arbitrary key Inspect player records because the tournament summarizes only winners. Stop when found or all n leaves have been checked; O(n). The root cannot establish whether a nonwinner key exists.
General insert/delete/meld No cheap general operation is supplied for fixed player slots. No course algorithm or bound is stated. A new or removed player changes the leaf layout; do not claim path replay alone handles it. Inactive marking is the stated practical representation for an exhausted run.
Loser tree Store the loser at each match node; the overall winner is maintained separately. Lecture introduces the representation and says the opponent is the player who lost the last match at that node. Replay the replaced champion against its remembered opponents, storing each loser and carrying the winner upward. This procedure assumes the changed player was the champion; do not use it unchanged for arbitrary nonwinner updates.
First Fit bin packing Keep remaining capacities in a max winner tree and descend left whenever left maximum ≥ item size. Stop at the first fitting leaf; subtract the size and replay its path. If root max < size, open the next bin. Bins retain opening order. Item equal to capacity fits; item greater than fixed bin capacity is invalid. Bin-count quality bound in the lecture: at most (17/10)·OPT+2.
First Fit Decreasing (FFD) Sort the items in non-increasing size, then run First Fit. Finish after all sorted items are packed or a too-large item is rejected. Sorting changes input order; it is not plain First Fit. Lecture bound: at most (11/9)·OPT+4.
Best Fit For each item, consider all bins that fit and choose the one with least remaining capacity; open a bin when none fits. Stop after choosing the minimum-remainder feasible bin or establishing the feasible set is empty. Lecture describes the heuristic, not a winner-tree traversal for finding its minimum remainder. Bound: at most (17/10)·OPT+2.
Best Fit Decreasing (BFD) Sort non-increasing first, then use Best Fit. Finish after all sorted items are assigned or an oversized item is rejected. Do not substitute First Fit’s leftmost-feasible descent for the least-remainder decision. Lecture bound: at most (11/9)·OPT+4.

The OPT bounds are approximation guarantees for the number of bins, not runtime bounds or claims that the heuristic is optimal. The lecture states build O(n), winner lookup O(1), winner replacement Θ(logn), and arbitrary-key search O(n); it gives no update-cost claim for general insertion, deletion, meld, or for the Best Fit implementations.

Tournament sort: repeatedly remove the champion

The winner tree can sort a fresh, unsorted list by selection. Build once, emit the root winner, mark that winner's fixed leaf inactive, and replay only its ancestor matches. Repeat until every real leaf is inactive. This is tournament sort: it repeatedly selects from the original list. It is different from replacement selection, where new input records refill leaves and may be frozen for a later run. For sorted runs, see the k-way merge walkthrough; the loser-tree page explains the alternative node storage.

Tournament sort a fresh list; deactivate each fixed player

1 · Build once from [6, 2, 5, 2, 9]

The input order is fixed to leaves P1–P5; the remaining leaves are padding and explicitly inactive. Build a min winner tree, keeping player identities so the two 2s remain distinct. The root is the next output.

The four comparisons are P1(6) vs P2(2), P3(5) vs P4(2), the subtree winners P2(2) vs P4(2) (left P2 wins the tie), and P2(2) vs P5(9). The root winner is P2=2.

2 · Output P2=2, deactivate leaf 2, replay its path

Replay node 4: P1(6) beats inactive P2. Replay node 2: P4(2) beats P1(6). Replay root: P4(2) beats P5(9). The output prefix is [2]; the duplicate 2 remains available in P4’s distinct leaf.

3 · Output P4=2, deactivate leaf 4, replay its path

Node 5 has only P3=5 active, so no key comparison is needed there. Node 2 compares P1(6) with P3(5), and the root compares P3(5) with P5(9). The output prefix is [2,2]. Key 5 is the next champion, not an output yet.

4 · Output P3=5, deactivate leaf 3, replay its path

At node 5 both leaves are inactive, so it has no winner and needs no key comparison. Node 2 carries P1=6 upward; the root compares P1(6) with P5(9). Prefix: [2,2,5]. Key 6 is the next champion, not an output yet.

5 · Output P1=6, replay against the last player

The updated path has no active comparison: node 4 has no live child, node 2 has no live child, and the root carries P5 upward. Prefix: [2,2,5,6].

6 · Output P5=9; all real leaves are inactive

The sorted result is [2,2,5,6,9]. Duplicate values are preserved because deactivation applies to a player identity, not to every leaf whose numeric key equals the champion.

For n players, construction uses n−1 key comparisons. Each of the next n−1 updates replays at most the tree height, so the complete sort takes O(nlogn) comparisons and O(n) storage; the final remaining item needs no competitor comparison. This example uses a padded 8-leaf layout, but padding leaves are inactive states, never a made-up “very large” key. If only one live player remains in a subtree, it advances without a numeric comparison.
