Binary heap

A compact priority queue. The smallest value stays at the root, while the array stays complete.

Big picture

A min heap guarantees only that each parent is no larger than its children. Siblings and separate subtrees need not be sorted. A max heap reverses the comparisons.

Build from a list

Repeated insertion is easy to trace and costs O(nlogn) in the worst case. Bottom-up heapify is the faster bulk build: copy the list into the array, then sift down from the last parent to the root. It costs O(n), because most nodes are close to the leaves.

Build from a fresh list [7, 3, 9, 1, 5]

Input list[7, 3, 9, 1, 5]

Start empty

The empty heap has no root to compare, so construction begins with no records and stops here; the next insertion creates the first complete-tree slot.

Append 7

Append at the next complete-tree slot. Now compare upward.

Appending 7 creates the root at index 1. There is no parent, so sift-up stops immediately and the one-node heap invariant holds.

Insertion of 7 complete

The item has reached the root or an ordered parent. Heap order is restored.

The root is 7 and has no children, so the parent-order condition is vacuous. Insertion stops at the root.

Append 3

Append at the next complete-tree slot. Now compare upward.

Appending 3 at index 2 preserves the complete-tree shape. Since 3 is below parent 7, shape is valid but order is not yet; sift-up must continue.

Bubble 3 above 7

Swap with the parent. Continue only if the next parent is larger.

Compare 3 with its parent 7 and swap because the child is smaller. It reaches the root, which has no parent, so sift-up stops with order restored.

Insertion of 3 complete

The item has reached the root or an ordered parent. Heap order is restored.

The new 3 is now the root; no parent remains to test. The min-heap property holds and this insertion stops.

Append 9

Append at the next complete-tree slot. Now compare upward.

Appending 9 at index 3 fills the next breadth-first slot. Its parent 3 is smaller, so no swap is needed and sift-up stops.

Insertion of 9 complete

The item has reached the root or an ordered parent. Heap order is restored.

Both children are at least 3, so the new leaf needs no repair. Stop at the first parent comparison.

Append 1

Append at the next complete-tree slot. Now compare upward.

Appending 1 at index 4 preserves completeness. Parent 7 is larger, so the local order violation requires an upward swap.

Bubble 1 above 7

Swap with the parent. Continue only if the next parent is larger.

Swap 1 with parent 7 because 1 is smaller. The replacement parent is 3, still larger than 1, so continue upward.

Bubble 1 above 3

Swap with the parent. Continue only if the next parent is larger.

Swap 1 with parent 3. The item reaches the root; there is no further parent, so stop and retain heap order.

Insertion of 1 complete

The item has reached the root or an ordered parent. Heap order is restored.

The root 1 has children 3 and 9, both no smaller than it. The insertion is complete; equality would also be a valid stop.

Append 5

Append at the next complete-tree slot. Now compare upward.

Appending 5 at index 5 gives it parent 3. Since 5 ≥ 3, the appended node already satisfies order and no sift-up swap is required.

Insertion of 5 complete

The item has reached the root or an ordered parent. Heap order is restored.

The final parent comparison is ordered, so stop. The complete shape and every parent-child order relation are valid.

Bottom-up build from [7, 3, 9, 1, 5]

Input list[7, 3, 9, 1, 5]

1 · Copy the unsorted list

With 1-based indexes, the last parent is floor(5/2) = 2.

Copy all 5 values in input order; this preserves the complete-tree shape but not necessarily heap order. With 1-based positions the final parent is floor(5/2)=2, so later leaves need no sift-down.

2 · Sift down at index 2

Compare children 1 and 5. Swap 3 with the smaller child, 1.

At index 2, value 3 has children 1 and 5. Select the smaller child 1 (if children tie, the implementation may choose either); 3>1, so swap. The value 3 moves to index 4, which is a leaf, and this sift stops.

3 · Sift down at index 1

Swap 7 with 1. The displaced 7 still has children.

At the root, compare children 1 and 9 and select 1. Swap 7 with 1 because 7>1; the displaced 7 now has children 3 and 5, so continue rather than stopping.

4 · Finish the repair

Swap 7 with 3. Every parent is now ≤ its children.

Compare displaced 7 with children 3 and 5; choose 3 and swap because 7>3. Index 2 now has children 7 and 5, and 3≤both; the sift stops. All ancestors already processed remain ordered.

Remove the minimum, then insert 0

1 · Original heap

Return 1. Remove the last value 5 from its array slot.

The original heap has minimum 1 at the root. Returning it is the read decision; removing the last leaf 5 creates a hole to fill, and no repair occurs until the last value is moved to the root.

2 · Replace root

Compare children 3 and 9. Choose 3.

Move last value 5 to the root after shrinking the active size to 4. Its children are 3 and 9, so select 3; because 5>3, downward repair must continue. A missing right child would leave the left child as the only candidate.

3 · Trickle down

Swap 5 and 3. Now 5 ≤ 7, so stop.

Swap 5 with the smaller child 3. At its new position, 5 has only child 7; since 5≤7, stop. If the parent equaled its only child, it would also stop because equality satisfies heap order.

4 · Append 0

The new item starts at index 5.

Append 0 at the next complete-tree slot (index 5). It is less than parent 5, so shape is valid but order is not; sift-up continues.

5 · Bubble above 5

0 swaps with its parent 5. It is still smaller than new parent 3.

Swap 0 with parent 5. The new parent is 3 and is still larger, so continue upward; equal parent would be a valid stopping condition.

6 · Bubble above 3

0 swaps with 3 and reaches the root. The min heap is restored.

Swap 0 with parent 3 and reach the root. There is no parent above it, so stop; all descendants are at least 0 and the min heap is restored.

Caveats and exam focus

An empty heap has no minimum. A one-item removal leaves an empty heap. General search is linear even though the height is logarithmic. With duplicate priorities, add a sequence number if stable removal order matters. Handles or index maps must follow items when swaps move them.

Why is bottom-up heapify O(n), rather than O(nlogn)?

Check your answer

Only a few nodes can move many levels. Summing work by node height gives n/4 × 1 + n/8 × 2 + … = O(n).

Method boundary and decisions

This page explains a single-ended binary min heap as the basic priority-queue component. Lecture 3 uses single-ended priority queues inside its double-ended structures, and gives a more specific interval-heap representation and d-ary heap variant. The repair rules below are the binary foundation; the interval-heap operations are not interchangeable with these procedures. Lecture 3 does not specify meld, arbitrary key search, or decrease-key for its interval heap, so those rows are standard supplemental binary-heap methods.

Method Decision and repair direction Stop condition Edge cases and cost
getMin / peek Read root; do not change the heap. Return the root immediately. Empty heap has no minimum. Actual and worst case are O(1).
insert / push Append at the next breadth-first slot; compare with parent and swap upward while the new key is smaller. Root reached or parent key ≤ inserted key. Equal keys need not swap. One comparison per level; worst-case O(logn).
removeMin / extractMin / pop Save root, move last item to root, shrink size, then repeatedly swap with the smaller existing child. No children, or replacement ≤ smaller child. Empty: report failure/no result. One item: becomes empty. With one child compare only that child. Worst-case O(logn).
search(key) Scan the array; heap order can prune a subtree only after finding a node greater than the target in a min heap. Key found, or all unpruned nodes exhausted. Duplicates may yield any matching record unless identity is specified. Worst-case O(n), not O(logn).
delete(handle) With a valid item location, replace it by the last item and shrink. If it is below its parent sift up; otherwise sift down using the smaller child. Upward: root or parent ≤ replacement. Downward: leaf or replacement ≤ chosen child. Deleting the last item requires no repair; deleting the root is removeMin. A handle/index map must track swaps. Worst-case O(logn) after location is known; finding by key alone remains O(n).
decreaseKey(handle) Lowering a key can violate only its parent edge, so sift upward. Root reached or parent ≤ new key. Key must not increase in this operation; equal keys stop. Worst-case O(logn) after handle lookup.
increaseKey(handle) Supplemental counterpart: raising a key can violate child edges, so sift down by the smaller child. Leaf reached or new key ≤ smaller existing child. Not listed on the original page, but stated here to make update direction explicit. Worst-case O(logn) after handle lookup.
meld(A, B) Supplemental array-based meld: concatenate records and bottom-up heapify the combined array. Every internal node has been sifted down to a leaf or ordered child relation. Distinct handles/ownership must be reconciled; duplicates are allowed. O(n+m) heapify, plus concatenation. Lecture 3 does not give a meld procedure for interval heaps.
Bottom-up build Copy list into breadth-first array; sift down each parent from last parent to root. Each sift stops at a leaf or when parent ≤ selected child. Empty and one-element inputs need no comparisons. O(n) for a binary heap; repeated insertion is worst-case O(nlogn).

For equal children, this guide's deterministic trace chooses the left child; choosing the right child is also correct. Swap only when the parent is strictly larger than the chosen child, so equal parent-child keys stop. Always test child existence before reading it: at the last internal position a node can have only a left child. Without a sequence-number tie-break, equal priorities are not stable.

Lecture 3's interval heap is a different double-ended structure: each node stores an interval [a,b] with a ≤ b, every child interval lies inside its parent interval, the root exposes both extremes, and the final node may contain just one element. Its insert and endpoint-removal rules (including the one-/two-element edge cases) are part of that structure; initialization repairs intervals bottom-up. The d-ary lecture variant uses 1-based indexing with parent(i)=ceil((i−1)/d) and children d(i−1)+2 through min(di+1,n). Its remove-min scans up to d children per level, then moves the replacement down. The binary formulas here are the d=2 specialization, not the interval-heap algorithm. For the interval-heap methods actually stated in lecture 3, use this boundary table. It records the course variant without substituting the single-ended routines above:

Lecture-3 interval-heap method Course decision / stop point Stated cost or edge case
Peek minimum / maximum Read the left / right endpoint at the root interval. O(1).
Insert A new key becomes a left or right endpoint depending on the final node; repair the corresponding min or max endpoint heap. If it completes a pair, keep that node's endpoints ordered. O(logn).
Remove minimum / maximum Remove the matching endpoint at the root, take an endpoint from the last node, delete that node if empty, then reinsert/repair from the root; swap a node's endpoints if needed and preserve interval containment and endpoint heap order. Maximum is the symmetric endpoint case. For n=0 fail; n=1 becomes empty; n=2 has one node and removing minimum takes its left endpoint.
Initialize Examine nodes bottom-up; order the root endpoints if needed, then reinsert its left endpoint into the min endpoint heap and its right endpoint into the max endpoint heap. Bottom-up endpoint repairs.
Remove a point by location Given its structural location, remove and repair the interval heap. O(logn). This is location-based, not search-by-key.
Report points outside [a,b] Traverse/report only points outside the requested interval, producing k results. O(k+1), including an empty result; the lecture writes O(k) for output-sensitive reporting.

Deletion chooses its repair direction

A known handle identifies a location in O(1) (or through a maintained index map). Replacing it with the last key can violate the parent edge or child edges, but not both when the heap was valid: compare with the parent first; if it is smaller, move up, otherwise move down.

Key updates and meld

For a min heap, a lower key can only need upward repair; a higher key can only need downward repair. “Decrease” and “increase” describe the numerical key, not the array index. A stable handle or index map must follow the record during every swap.

Array meld is a supplemental rebuild operation, not a lecture-3 interval-heap procedure. The receiver copies both input arrays, then bottom-up heapifies. Neither input is assumed to remain a valid independent heap if its storage is reused as the output buffer.

Complexity and course comparison

A binary heap has height ⌊log2n⌋. Insertion and handle-based single-key repair follow one root-to-leaf path, so their worst-case cost is O(logn). Bottom-up heapify is O(n), while repeated insertion has O(nlogn) worst case. In a d-ary heap, height is O(logdn); insert examines one parent per level, while removal selects the smallest of up to d children per level and therefore uses up to O(dlogdn) comparisons. Lecture 3 notes the 4-ary tradeoff: about half the height of a binary heap but more child comparisons at each removal level. These are worst-case operation bounds, not average or amortized bounds.

Common mistakes

  • Do not assume the entire array is sorted; only parent-child order is guaranteed.
  • During sift-down, choose the smaller child first. Swapping with the larger child could leave a smaller child below the replacement.
  • Do not compare a nonexistent right child. A final internal node can have just a left child.
  • Do not keep bubbling on equality. Equal parent-child keys already satisfy min-heap order.
  • Do not choose repair direction by the deleted key's old value. Compare the last-item replacement with its new parent; if it is not smaller, inspect children.
  • A handle-aware O(logn) deletion does not make searching by value O(logn); an array scan is still O(n).
  • Do not apply single-ended sift rules to an interval heap: its nodes hold two endpoints and its child intervals must remain contained by their parents.

Exam focus

  • 1-based binary heap: parent ⌊i2⌋; children 2i and 2i+1. Displayed positions are 1-based. In a separate zero-based implementation, parent of index j>0 is ⌊j−12⌋.
  • Insert: append, swap upward only while child < parent; stop at root or child ≥ parent.
  • Remove minimum: move last item to root, shrink, repeatedly swap with the smaller existing child while the replacement is larger.
  • Build: sift down from floor(n/2) through 1; include every swap; total O(n).
  • Delete known handle: replace with last item, sift up if it is smaller than parent; otherwise sift down. Update the handle map after each swap.
  • Interval heap distinction from lecture 3: node interval [a,b], a≤b, child interval contained in parent; min and max are both at root. Its initialization and removals are separate algorithms.
  • d-ary distinction: parent and child index formulas change with d; remove-min must choose among up to d children.

Practice

What happens if both children equal 8 while the replacement is 9? The trace chooses the left child, swaps 9 with 8, then continues. Choosing the right child is also correct. If the replacement were 8, it would stop immediately because equality preserves order.

What happens when a node has only a left child? Compare against that child only. Swap if the replacement is larger; otherwise stop. Never form or dereference a right-child index before checking it is below the active heap size.

How does the interval heap expose both extrema? Its root stores [a,b] with a≤b; the left endpoints obey min-heap order and right endpoints obey max-heap order, while each child interval is contained in its parent (lecture 3). Do not simulate this by maintaining only a binary min heap.
