Self-Supervised Learning for Vision

Learn how vision models manufacture training targets from images, shape contrastive or masked objectives, and test whether the retained representation transfers.

Big picture1. The learning signal comes from the image2. Early vision pretext tasks3. Contrastive learning and SimCLR4. Masked image modelling: BEiT and MAE5. Test the representation downstreamCommon mistakesExam focusPractice questions

Big picture

Self-supervised learning (SSL) turns unlabelled images into training examples with targets manufactured from the images themselves. A network still predicts a target and receives a loss, but people do not annotate those targets. The aim is not a high score on an artificial puzzle; it is an encoder whose representation remains useful for real vision tasks.

This page follows the vision material only: early image puzzles, contrastive views and SimCLR, masked-image prediction, then downstream evaluation. The separate text self-supervision page covers the remaining slides.

1. The learning signal comes from the image

Supervised learning starts with human-provided labels. Unsupervised learning looks for structure in unlabelled data. Self-supervised learning also uses unlabelled data, but constructs a prediction target from it, so training resembles supervised learning after the target has been manufactured.

In the general pattern, hide or transform some information and ask a network to predict the hidden content or the transformation. This prediction problem is the pretext task. The encoder is the part we hope to reuse; its features can support downstream tasks such as classification or object detection.

The pretext task must make useful structure matter. If a network can solve it with a cheap visual artefact, its pretext accuracy can improve without producing a strong general-purpose representation. Evaluate the retained representation on downstream work rather than treating the pretext score as the end goal.

Worked example: distinguish a manufactured target from a human label

Take an unlabelled image and rotate it by one of the four angles used by RotNet.

  1. The image pixels are the original input; no object category is supplied.
  2. The transformation itself supplies the target: which of zero, ninety, one hundred eighty, or two hundred seventy degrees was applied.
  3. The network learns a representation while predicting this known transformation.
  4. For a real task, retain the encoder and test or adapt it using the target task’s labels.

Check: the rotation label is free because it is recorded by the transformation. It does not prove that the encoder learned features useful for every downstream task.

Two prerequisites

Review machine-learning foundations for training objectives and labelled versus unlabelled data, and deep-learning foundations for the encoder and representation language used here.

2. Early vision pretext tasks

The first vision methods asked networks to solve deliberately designed image puzzles. Each puzzle supplies a different target, and each can encourage useful structure while also opening a route to shortcuts.

Task What the network receives Manufactured target Main caution
Context prediction Two patches from one image; one is the anchor Which of the eight neighboring positions contains the other patch Chromatic aberration can leak position; the original method added gaps and jitter between patches
Context encoder / inpainting Image with a large central region removed Missing pixels, predicted from surrounding content Pixel reconstruction can reward local texture even when semantic understanding is weak
Colourisation Lightness channel Colour channels Plausible colour depends on scene content, but the task is still hand-designed
Jigsaw Tiles from a shuffled three-by-three image grid Which permutation was applied Tile boundaries or low-level cues may reveal arrangement
RotNet Image rotated by a quarter-, half-, or three-quarter-turn, or left upright Applied rotation class Correct rotation can sometimes be detected from simple orientation cues

These are a bounded set of historical task families, not a survey of every method on the lecture timeline. Their shared lesson is that a target can be generated without annotation, but its design determines what shortcuts are available.

Worked example: trace the context-prediction target

Source-aligned schematic. An anchor patch is surrounded by eight possible relative locations.

  1. Choose an image and an anchor patch.
  2. Select a second patch from one of the eight neighboring positions.
  3. Remove the absolute location cue and separate patches with gaps and jitter, as in the lecture’s account of the shortcut correction.
  4. Predict the relative-position class from the two patches.
  5. Check whether solving the task requires recognizing how object parts fit together, rather than exploiting colour fringes around patch boundaries.

The target is the known relative position. The source reports that chromatic aberration was a low-level shortcut and that gaps and jitter were used to reduce it.

3. Contrastive learning and SimCLR

Contrastive learning uses a broad relation instead of a separate puzzle for every task: two augmented views of the same image should agree, while views from other images serve as alternatives to distinguish from. The source introduces Contrastive Predictive Coding (CPC) and InfoNCE as an objective connected to a lower bound on mutual information between related views. It also describes instance discrimination, where each image is treated as its own class and negative features are stored in a memory bank. SimCLR is a distinct, simpler design that uses other views in the current batch as negatives and does not require a memory bank.

For SimCLR, the image is augmented twice. Both views pass through the same encoder parameters f to produce h, then through the same nonlinear projection-head parameters g to produce z. The loss is applied to z; after pretraining, h from the encoder is kept for downstream tasks and g is discarded. The figure is a teaching illustration of this source pipeline.

InfoNCE: the positive is one of the candidates

Cosine similarity measures the dot product after vector-length normalization. It is defined here for nonzero vectors. The positive temperature τ is a scaling parameter inside the softmax: a smaller τ makes similarity differences affect the distribution more sharply.

For anchor view i and its positive view j, the InfoNCE loss is:

ℓ(i,j)=−log(exp(sim(zi,zj)/τ)∑k=12N1[k≠i]exp(sim(zi,zk)/τ)),sim(u,v)=uTv‖u‖‖v‖,τ>0

Here N is the number of original images in the minibatch. Each has two views, giving 2N embeddings. For each anchor, the denominator excludes that anchor itself and includes every other view: one positive and 2N−2 views of other images. In an unlabelled dataset, “other image” does not mean “different semantic class”; a negative can share the anchor’s class.

The training loss averages both anchor directions for each positive pair across the batch. The softmax encourages the positive to be more similar relative to the candidate views. It does not guarantee that all semantic false negatives disappear.

1. Make two views of each unlabelled image

Teaching illustration. Start with two distinct source images, A and B. Sample two independent augmentations for each image. This tiny batch is for counting roles only; no pixel values or similarity scores are supplied by the lecture.

{A,B}⟶(A1,A2),(B1,B2)

For SimCLR with N original images, the batch contains 2N augmented views.

2. Pass both views through shared networks

Each view goes through the same encoder parameters f to make h, then through the same nonlinear projection-head parameters g to make z. The two branches are copies of a data path, not separately learned networks.

hA1=f(A1),hA2=f(A2),zA1=g(hA1),zA2=g(hA2)

The training loss is applied to z. After pretraining, the encoder output h is retained for evaluation; the projection head g is discarded.

3. Name the anchor, positive, and negatives

Choose zA₁ as the anchor. Its positive is zA₂, the other view of the same original image. The two B views, zB₁ and zB₂, are negative candidates because they come from another image.

  • Anchor: zA₁, the reference.
  • Positive: zA₂, pulled toward the anchor.
  • Negatives: zB₁ and zB₂, pushed away relative to the positive.

Different source images need not belong to different semantic classes. Unlabelled data therefore does not guarantee the absence of false negatives.

4. Form the candidate softmax and check its count

Cosine similarity compares nonzero vectors after length normalization. With positive temperature τ, the anchor’s denominator includes every other view, including the positive:

ℓ(A1,A2)=−logexp(sim(zA1,zA2)/τ)exp(sim(zA1,zA2)/τ)+exp(sim(zA1,zB1)/τ)+exp(sim(zA1,zB2)/τ)

Count check. With N=2 there are 2N=4 views. Excluding the anchor leaves three candidates: one positive plus 2N−2=2 other-image negatives. The positive numerator is one of those three denominator terms.

5. Optimise on z, then cross the evaluation boundary

Repeat the loss with the roles reversed for the positive pair, and over the batch. Updating f and g lowers the normalized contrastive loss; the positive should receive a larger relative softmax probability than negatives.

Independent check. The fraction inside the logarithm is a probability in (0,1], because the denominator contains the positive numerator and only adds positive exponential terms. Thus its negative logarithm cannot be negative.

For a downstream linear probe, freeze f, use h, and fit a linear classifier with labelled target data. Do not evaluate the representation by reusing the pretext loss.

What makes the SimCLR recipe work

The lecture emphasizes the augmentation choice. Random cropping with resize and strong colour distortion is important; the primary paper also uses random horizontal flip and Gaussian blur in its default policy. The paired views should differ enough to make the task informative while preserving the image identity needed for a positive pair. The paper finds that a small learnable nonlinear projection between h and the loss improves the quality of the retained representation. Larger batches provide more other-image negatives, and longer training also helps the contrastive setting.

Published result correction: the lecture slide assigns 69.3% to supervised ResNet-50 and places it beside SimCLR’s 76.5%. In the original paper’s Table 6, 69.3% is standard-width SimCLR ResNet-50 linear evaluation; 76.5% is SimCLR ResNet-50 (4×) linear evaluation. The paper abstract says the latter matches a supervised ResNet-50, but these are different model configurations and should not be treated as architecture-equivalent. These are historical published results, not measurements made for this guide. See the original SimCLR paper, abstract and Table 6.

4. Masked image modelling: BEiT and MAE

Masked-image methods hide patches and train a model to predict information at those locations. Their targets differ: BEiT predicts discrete visual-token codes from a pretrained tokenizer, while MAE reconstructs raw pixels. The two diagrams below are teaching schematics that preserve this target distinction and the lecture’s encoder/decoder roles.

Method Masking in the lecture Prediction target Model path
BEiT About 40% of patches, in blocks Discrete codes from a pretrained visual tokenizer with 8,192 “visual words” Vision Transformer predicts the tokenizer codes at masked positions
MAE About 75% of patches, selected randomly Raw pixel values Large encoder sees visible patches only; a lightweight decoder adds mask tokens and reconstructs hidden patches

MAE is asymmetric by design: expensive encoding is limited to visible patches and a lighter decoder restores the missing content. The high mask ratio makes a simple local-copy solution harder in a redundant image. The lecture reports that a ViT-Huge pretrained with MAE reached 87.8% after ImageNet-1K fine-tuning; this is a historical reported result, not a comparison produced here.

Worked example: count visible patches from the MAE mask ratio

Supplemental calculation. Let an image be divided into P patches. Use the lecture’s approximate MAE mask ratio of 75%.

  1. About three quarters are masked:
    Pmasked≈0.75P
  2. The remaining quarter is visible:
    Pvisible=P−0.75P=0.25P
  3. The large encoder processes only those visible patches.
  4. The lightweight decoder receives their encoded features together with mask tokens, then predicts raw pixels for the masked locations.

Check: 0.25+0.75=1. The ratio is approximate and this algebra is a teaching calculation, not an additional measurement.

5. Test the representation downstream

Pretext loss answers whether the model solved its manufactured task. Downstream evaluation asks whether the retained encoder helps with a real labelled task. The protocols differ in what they train, so their scores do not automatically rank representations against each other.

Evaluation What is fitted or updated What the result probes
Linear probe Freeze the pretrained encoder; fit a linear classifier on its features Whether the features are already linearly separable for the target labels
k-nearest neighbours (kNN) Fit no classifier; label a test image using nearby training-image features Whether local feature-space neighbourhoods align with labels
Fine-tuning Update the pretrained model’s weights using labelled target data How useful the representation is as an adaptable starting point
Transfer learning Apply or adapt the encoder on a new dataset or task, such as object detection Whether learned features generalize beyond the pretraining task

Keep the evaluation boundary visible: linear probing freezes f and fits only a linear readout; kNN fits no classifier; fine-tuning changes the pretrained weights; transfer changes the dataset or task being tested. A score from one protocol is not automatically comparable to a score from another.

Worked example: choose the method that matches the question

A lab wants to know whether a frozen encoder’s features already separate a new labelled set of image classes.

  1. Freeze the encoder so its features cannot adapt.
  2. Train only a linear classifier on the labelled training split.
  3. Evaluate that classifier on held-out target examples.
  4. Interpret the result as a linear-probe test of feature separability.
  5. If instead every pretrained weight were updated, the experiment would be fine-tuning and would answer a different question.

No numerical performance is assumed. The correct choice follows from the evaluation question and which parameters are allowed to change.

Common mistakes

  • Treating a self-supervised target as a human label. The target is manufactured by masking, transforming, or pairing data.
  • Treating pretext-task accuracy as the final measure of representation quality. A shortcut can solve the puzzle without learning transferable features.
  • Assuming context prediction requires semantics by itself. Chromatic aberration can leak patch location; gaps and jitter address the shortcut described in the lecture.
  • Calling every contrastive method a memory-bank method. The lecture’s instance-discrimination example uses a memory bank; SimCLR uses current-batch negatives.
  • Omitting the positive from the InfoNCE denominator. The anchor is excluded; the positive stays in the candidate softmax with the negatives.
  • Assuming different images have different semantic classes. False negatives are possible in unlabelled data.
  • Applying the SimCLR loss to the encoder representation or using the projection output for downstream evaluation. The lecture pipeline applies loss after the projection head and retains the encoder representation.
  • Confusing BEiT’s tokenizer codes with MAE’s raw-pixel target, or saying the MAE encoder sees masked patches. It sees visible patches only; its light decoder handles mask tokens.
  • Comparing linear-probe, kNN, fine-tuning, or transfer results as if their protocols were identical.
  • Repeating the lecture’s 69.3% SimCLR comparison as a supervised score. The original Table 6 labels it standard-width SimCLR; 76.5% is the 4× SimCLR model’s linear evaluation.

Exam focus

  • SSL uses unlabelled inputs with targets manufactured from those inputs; the pretext objective is a means to learn a useful encoder.
  • Context prediction: anchor plus one of eight neighbor positions; gaps and jitter reduce the chromatic-aberration shortcut.
  • Context encoders predict a missing central region; colourisation predicts colour from lightness; jigsaw predicts a shuffled three-by-three permutation; RotNet predicts one of four rotations.
  • Contrastive learning attracts augmented views of the same image and distinguishes them from other-image views.
  • SimCLR: two stochastic augmentations → shared encoder → representation → shared nonlinear projection head → projection; loss on the projection, downstream representation from the encoder.
  • InfoNCE: positive in numerator and denominator; denominator excludes anchor only. With N original images and 2N views, each anchor has one positive and 2N−2 other-image negatives.
  • BEiT: about 40% block masking; predict one of 8,192 discrete tokenizer codes. MAE: about 75% random masking; visible-only large encoder, light decoder, raw-pixel reconstruction.
  • Linear probe freezes encoder; kNN fits no classifier; fine-tuning updates pretrained weights; transfer tests a new dataset/task. These protocols have different meanings.
  • Correct SimCLR historical values: 69.3% standard-width ResNet-50 SimCLR and 76.5% ResNet-50 (4×) SimCLR, both linear-evaluation top-1 in Table 6; these are not newly measured values.

Practice questions

1. What creates the supervisory signal in a self-supervised vision task?

Check your answer

A transformation or withheld part of the unlabelled input creates the target automatically, such as an applied rotation or a masked patch.

2. Why can a high pretext score still produce a weak representation?

Check your answer

The model may exploit a low-level shortcut that solves the pretext task without learning features useful for downstream tasks.

3. For context prediction, how many relative-position classes surround an anchor patch, and what shortcut correction is named in the lecture?

Check your answer

There are eight neighboring positions. Gaps and jitter between patches were added to reduce the chromatic-aberration cue.

4. A SimCLR batch contains N original images, each with two augmented views. For one anchor, how many positives and other-image negatives enter its denominator?

Check your answer

There is one positive and 2N−2 other-image negative views. The denominator excludes the anchor itself but includes the positive and every negative.

5. What does SimCLR keep for downstream tasks: the encoder representation or projection output, and where is the contrastive loss applied?

Check your answer

It keeps the encoder representation for downstream tasks. The contrastive loss is applied to the projection output after the projection head.

6. Do SimCLR negatives guarantee different semantic classes?

Check your answer

No. They are views from other images in the batch. Unlabelled data does not guarantee that another image belongs to a different semantic class.

7. What target separates BEiT from MAE?

Check your answer

BEiT predicts discrete visual-token codes from a pretrained tokenizer. MAE reconstructs raw pixel values for masked patches.

8. Which evaluation method freezes the encoder and fits a linear classifier?

Check your answer

Linear probing.

9. Which evaluation method uses feature neighbours without fitting a classifier?

Check your answer

k-nearest neighbours (kNN).

10. Correct the 69.3% and 76.5% values shown on the lecture’s SimCLR slide.

Check your answer

In the original paper’s Table 6, 69.3% is standard-width SimCLR ResNet-50 linear evaluation; 76.5% is SimCLR ResNet-50 (4×) linear evaluation. Both are historical published results, not guide measurements. The 69.3% figure is not the supervised comparator.
