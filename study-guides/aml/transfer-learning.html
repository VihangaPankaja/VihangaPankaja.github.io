Transfer Learning, Multitask Learning, and Fine-Tuning

Reuse learned representations across related tasks and domains, then choose carefully which target parameters to adapt.

Big picture

Training a deep model from scratch can require many examples, while a new target task may have only a small labeled dataset. Transfer learning reuses a model or learned representation from a source problem as a starting point for a target problem. The key questions are what the source and target share, which labels are available, and which copied parameters should remain fixed or adapt.

The lecture opens with a pastry-classification story illustrating how a representation learned for one visual distinction can be useful beyond its original labels. Another motivation slide says deep learning may need more than 50,000 data items. That is the lecture’s motivating claim, not a universal threshold.

First separate domain from task

For this guide, use a domain to mean the input feature space together with the distribution of inputs. Use a task to mean the output or label space together with the predictive objective. This is a teaching convention for reading the lecture’s examples; transfer-learning terminology is not identical across all literature.

Ask two questions independently: How do the inputs differ? and What prediction is required? A new camera, speaker, or visual style can change the domain even when the target labels and prediction remain the same. Changing dog/cat labels to elephant/tiger changes the task even when the data are still animal photographs.

These examples ask whether useful input patterns can be reused; they do not imply that source and target tasks or distributions are identical.

Transfer labels: report facts before taxonomy names

Slides 4 and 7–8 present related but non-identical taxonomy views. Slide 4 organizes examples by label availability: target labels lead to its inductive branch; labels only in the source lead to its transductive branch; and no labels in either domain lead to its unsupervised branch. Slides 7–8 reorganize families by task/domain relationship and explicitly warn that terminology differs across literature. Slide 8 describes inductive transfer by labeled target-domain data and transductive transfer by the absence of labeled target-domain data; the slide 7 drawing also marks unlabeled source and target domains on its transductive branches.

Keep those statements as the lecture’s separate framings rather than forcing them into one mutually exclusive tree. In particular, do not infer that “transductive” universally means an unlabeled source: the source’s own slides do not agree on that point. State the source/target task relationship, domain relationship, and label availability before using a family name.

One more wording needs care: the motivation slide says source and target distributions “must be the same,” but later slides explicitly discuss transfer across different domains. Read the former as a challenge about the usual same-distribution training assumption, not as a requirement that every transfer-learning case have identical source and target distributions.

Why representations can transfer

A model’s internal layers map raw input into increasingly useful features. Some features may serve more than one target prediction, so a new model can start from learned parameters rather than discovering every useful pattern from scratch. Reuse is a starting point, not a guarantee: source-specific features can be a poor match, and a small target dataset can overfit if too many parameters are changed.

The dog/cat slide separates two useful relationships. The elephant/tiger photograph case illustrates similar domains with different tasks: both are animal photos, while the class labels differ. The photographic dog/cat versus cartoon dog/cat case illustrates different domains with the same task: visual style changes while the dog/cat prediction stays the same. The cases help identify what is shared before choosing a transfer method.

Fine-tuning: adapt a source model with target labels

The lecture’s supervised speaker-adaptation example starts with a large set of audio and transcripts from many speakers, then adapts to a very small labeled set from a specific speaker. “One-shot” is the lecture’s wording for having only a few target examples; do not read it here as a guarantee that the set has exactly one example.

The source model is trained first. Its parameters initialize a target model, which is then trained using the target speaker’s audio and transcripts. The lecture calls for conservative adaptation because very little target data can make overfitting a concern. The next viewer is a teaching parameter-state example that makes the update choices visible; its head replacement, block labels, and validation decisions explain a common implementation, rather than add numerical results or a new optimization method.

4. Optionally unfreeze an upper block

Decision: only consider this optional stage when there are enough labeled target examples and target validation supports the added flexibility. Unfreeze an upper backbone block and continue target-task training; keep the lower block fixed.

The target labels are essential to this supervised speaker-adaptation example. If target labels are unavailable, this exact target-loss update cannot be performed as shown. A held-out target validation set is used here as teaching guidance for deciding whether to retain a more flexible stage.

The separate conservative-training illustration on slides 11–16 shows a target model initialized from the source model, with outputs close and then parameters close. It conveys a cautious start near the source model.

For the backpropagation and optimization details used inside a training stage, continue to Backpropagation and Multilayer Networks, Gradient Descent, and Training Practice.

Which layers should be transferred?

Slides 17–19 show copying selected parameters, training the remaining layers first, and optionally fine-tuning the whole network when enough data are available. Slides 20–22 give lecture heuristics: images usually copy the first few layers; speech usually copies the last few layers. Treat these as course-level rules of thumb, not architectural laws. The useful layer depends on the model and on which source features match the target task.

What the ImageNet transfer plots show

Slides 23–24 reproduce experiments by Yosinski and colleagues using 500 source classes and another 500 target classes from ImageNet. On slide 23, the horizontal axis is the layer depth at which the network is cut and retrained; the vertical axis is top-1 accuracy, with higher values better. The lecture labels three effects: fragile co-adaptation can make a split hurt; fine-tuning can recover co-adapted interactions; and representation specificity can reduce performance when transferred features become too specialized. The slide headline summarizes its comparison as transfer plus fine-tuning improving generalization.

Slide 24 keeps the same cut-depth question and plots relative top-1 accuracy (higher is better). Its legend distinguishes the reference, mean A/B random splits, mean A/B m/n split, and random features. Read the plotted trends and labels as a comparison of these transfer effects.

Yosinski et al.’s primary paper describes both costs behind the slide’s story: higher-layer specialization and optimization difficulty when splitting co-adapted units. It also reports a general-to-specific trend across layers. The lecture plot remains the evidence for its particular cut-depth picture; the paper provides context, not a replacement dataset.

Multitask learning: share features, keep task outputs distinct

In multitask learning, related tasks are trained together. A shared internal representation can receive useful signals from more than one task, while each task retains its own output layer and labels. Slide 26 contrasts task-specific paths with a shared representation feeding distinct task outputs. Sharing can help when the tasks use relevant common structure, but it does not guarantee that every task will improve; check each task on its own validation data.

The lecture’s multilingual speech example shares acoustic features across French, German, Spanish, Italian, and Mandarin, then uses language-specific output states. The stated motivation is that human languages share some characteristics. The accompanying plot compares character error rate against the hours of Mandarin training data for “Mandarin only” and “With European Languages.” Both curves trend downward as Mandarin data increases, and the multilingual curve is lower over the shown range. This is a qualitative reading of the lecture figure, not a table of exact measurements or a promise that adding tasks always helps.

Progressive neural networks add task columns over time

Slides 29–31 show a sequence: first a column for Task 1; then a Task 2 column with forward lateral activation links from Task 1; then a Task 3 column with links from both earlier columns. The arrows describe information flowing forward into the new task column. They are not optimizer-update arrows.

The cited Rusu et al. primary paper supplies the progressive-network parameter convention: previously learned columns are frozen while a new column is trained, with lateral connections providing access to earlier features. In the diagrams, labels state which column is previous versus new, so that parameter status does not depend on color.

Progressive network: add one task column at a time

1. Task 1 — fit the first column

Input: Task 1 examples. Train a column for Task 1; its arrows show activations moving from input through hidden layers to its output.

2. Task 2 — add a column and lateral links

Input: Task 2 examples plus forward activations from the Task 1 column. Add the Task 2 column and connect earlier Task 1 features to the next Task 2 layer in the forward computation. The primary paper confirms the earlier column is frozen; the new Task 2 column learns. Lateral arrows carry activations, not optimizer updates.

3. Task 3 — reuse both earlier columns

Input: Task 3 examples plus activations from Task 1 and Task 2. Add the Task 3 column and lateral activation links from both existing columns. Keep earlier learned columns frozen and train the new column. This preserves the sequence and direction of the lecture’s three-column drawing.

PathNet: a separate routing example

Slide 32 names PathNet and shows changing channel pathways alongside a Pong-to-Alien score display. It is distinct from the progressive columns above: PathNet is presented as an evolutionary routing approach in a super-network.

Common mistakes

  • A domain describes input features and their distribution; a task describes the output/label space and predictive objective. State both relations.
  • Do not collapse the distinct slide 4 and slide 7–8 taxonomies into one universal tree. Their source-label depictions differ, and the lecture explicitly warns that terminology varies.
  • Do not claim that transductive transfer always requires an unlabeled source. Slide 8 focuses on target-label availability; the other slide framings differ about source labels.
  • The lecture’s “one-shot” phrase means a few target examples in this example, not exactly one.
  • The layer-transfer speech/image statements are heuristics, not fixed rules for every architecture.
  • A frozen backbone does not receive parameter updates during head-only target training. In progressive networks, cross-column arrows show activations; they do not mean old columns are being updated.
  • A source trend or plot is not a source of exact data points when no table is supplied. Do not turn the ImageNet or multilingual plots into invented numeric examples.
  • More shared tasks or transferred parameters do not guarantee improvement on every target; use task-specific validation evidence.

Exam focus

  • Transfer learning reuses a source model or learned representation to initialize learning for a target task/domain.
  • Read domain and task as separate axes; compare feature space/distribution, label/output space, objective, and label availability.
  • In the lecture’s supervised speaker adaptation: fit on many speakers’ audio/transcripts, initialize from the source model, adapt with the small labeled target set, and limit updates when data are scarce.
  • Layer transfer copies selected parameters; first train remaining layers, then consider broader fine-tuning only with sufficient data. Speech/image layer choices are lecture heuristics.
  • In multitask learning, shared representations feed separate task outputs and each task supplies its own labels.
  • In a progressive network, add columns successively and direct earlier-column activations forward to each new column; previous learned columns stay fixed under the cited method.
  • PathNet is a separate evolutionary-routing approach through a super-network.

Practice questions

1. A target set contains dog and cat photographs, while the source set contains elephant and tiger photographs. Which axis is similar and which differs?

Check your answer

The image domain is similar because both sets contain animal photographs. The classification task differs because the label/output sets differ: dog/cat versus elephant/tiger.

2. A model sees photographic dog/cat images at source and cartoon dog/cat images at target. What changes?

Check your answer

The visual domain changes (photographs versus cartoons), while the dog/cat label space and classification objective remain the same task.

3. In the speaker-adaptation example, what data enter source fitting and target fine-tuning?

Check your answer

Source fitting uses a large amount of audio and transcripts from many speakers. Target adaptation uses a very small labeled set of audio and transcripts from a specific speaker.

4. During head-only adaptation, which parameters change and which remain invariant?

Check your answer

The target head receives updates from target labeled examples and target loss. The frozen backbone is unchanged: θbafter=θbbefore.

5. What are the axes and three effects called out in the ImageNet transfer figure?

Check your answer

The slide 23 horizontal axis is the cut/retraining layer depth; its vertical axis is top-1 accuracy, higher is better. The named effects are fragile co-adaptation, recovery of co-adapted interactions by fine-tuning, and representation specificity. The source uses 500 source and 500 different target ImageNet classes.

6. How does the lecture’s multilingual speech example share knowledge?

Check your answer

It shares acoustic features across French, German, Spanish, Italian, and Mandarin while keeping language-specific output states. The chart qualitatively compares Mandarin-only training with training that includes European languages as Mandarin training hours vary.

7. In a progressive network, what does a lateral arrow from an earlier task column to a new one represent?

Check your answer

It represents forward activation information reused by the new column. Under the cited progressive-network method, earlier columns are frozen; the arrow is not an optimizer update to the old column.

8. Why should the taxonomy name be accompanied by source/target facts?

Check your answer

The lecture warns that terminology differs across literature, and its own slide 4 and slides 7–8 do not present identical source-label availability for transductive transfer. State task relation, domain relation, and source/target labels explicitly before using the family name.
