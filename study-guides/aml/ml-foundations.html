Machine learning foundations and learning paradigms

Machine learning is useful when examples can teach a system a pattern that is hard to specify by hand. This page connects the learning problem, its data and performance goal, and the main ways a learner can receive feedback.

Big picture

Many useful tasks have no complete, stable set of hand-written rules. A system can instead use experience to build a model: a compact approximation that maps relevant inputs to useful outputs. The central design question is not simply “Which algorithm?” It is: what task should improve, what experience will teach it, and what evidence will count as success?

Machine learning fits tasks where patterns are difficult to program explicitly, human expertise is hard to describe, conditions change, or personalization and large datasets matter. It is unnecessary for a fully specified calculation such as payroll. Learning combines prior assumptions or model structure with empirical examples; different methods make different choices about that balance.

What a learner is trying to approximate

Learning builds a useful approximation from particular examples. Think of each candidate mapping from inputs to outputs as a hypothesis. The learner searches a hypothesis space—the functions its representation can express—for one that fits the observed experience well enough to be useful on new cases. A narrow space can rule out useful patterns; a very flexible one can fit accidental details. The representation and search method therefore shape what can be learned.

Mitchell’s framing makes a learning problem explicit: experience E is useful when it improves performance P on a task T. The measure P must reflect the real objective. In spam filtering, for example, catching unwanted mail matters, but filtering legitimate mail by mistake matters too; a single vague “accuracy” goal can hide that trade-off.

The lecture frames machine learning as part of artificial intelligence and places deep learning within machine learning, while showing data science and analytics as overlapping areas rather than exact, non-overlapping boxes. Statistics and machine learning share probability, calculus, linear algebra, and many algorithms. The slides contrast statistics’ emphasis on inference and interpretable conclusions with machine learning’s emphasis on predictive performance, scale, and autonomous systems; this is a broad teaching distinction, not a hard boundary between fields. In the same framing, statistics draws inference from samples, while computer science contributes efficient algorithms and model representation/evaluation.

Traditional programming supplies data and an explicitly written program to produce an output. In the learning view, examples and desired outputs help a computer infer a program or model. This is useful when software rules are the bottleneck and data is more available than detailed, reliable human knowledge. Prior knowledge and empirical examples are two ends of a design spectrum; practical systems can combine both.

Spam: define the goal before choosing the learner

The lecture defines spam as email the user does not want and did not ask to receive. Its task is to identify spam emails. Its experience is a database of emails labeled by users. Its performance measures include the percentage of spam filtered and the percentage of legitimate (“ham”) emails incorrectly filtered out. These are two separate operating concerns: a filter that catches almost all spam could still be unusable if it also removes too much legitimate mail.

The learning pipeline starts from the real world. Sensors or databases provide observations; preprocessing filters noise, extracts features, and normalizes values. Feature selection or projection can then prepare a representation. A learner may perform classification, regression, clustering, or description; cross-validation or bootstrap can support model testing, followed by analysis. In the spam example, possible features include recipient count, message size, attachment count, and the number of “re” occurrences in the subject. These are measurements used to represent a message, not rules that by themselves define spam.

Frame tasks with T, P, and E

For each problem, state the task, its performance measure, and the experience separately. This prevents a common design mistake: collecting convenient data before deciding what improvement the system is meant to make.

Example Task T Performance P Experience E
Checkers Play checkers Percentage of games won against an arbitrary opponent Practice games played against itself
Handwritten words Recognize handwritten words Percentage of words correctly classified Human-labeled images of handwritten words
Highway driving Drive on four-lane highways using vision sensors Average distance traveled before a human-judged error Images and steering commands recorded while observing a human driver
Email Categorize messages as spam or legitimate Percentage correctly classified; the motivating spam example also tracks caught spam and ham filtered by mistake Emails, some with human-given labels

The same three-part frame applies even when the experience is not a static labeled table. Checkers uses self-play; driving uses paired image and steering-command sequences; the spam example uses user labels. Changing any one part changes the learning problem.

Teaching example: a strict-threshold credit rule

The lecture’s credit-scoring illustration uses this rule: income>θ1∧savings>θ2 Classify the customer as low-risk only when both comparisons hold; otherwise classify as high-risk. Both comparisons are strict.

For a concrete Teaching example, choose θ₁ = $60,000 and θ₂ = $10,000 (these values are illustrative, not source values):

  • Income $70,000, savings $12,000: both are greater than their thresholds, so the rule predicts low-risk.
  • Income $70,000, savings $10,000: savings equals its threshold, so the second strict comparison is false; the rule predicts high-risk.
  • Income $55,000, savings $20,000: income fails its threshold, so the rule predicts high-risk even though savings passes.

These illustrative thresholds define a hand-written classifier. Learning the thresholds from training data would be a separate step.

From training to use

During training, a learner uses its chosen experience to construct or adjust a hypothesis. During evaluation, it is checked on examples not used to fit it. During deployment (practical use), the selected model receives a new case represented in the same feature format and returns a prediction or decision. A deployed model does not automatically learn from every prediction; that requires a later update process and suitable new experience.

The lecture sketches a loss loop: input example → model hypothesis → predicted example → loss evaluation → calculated loss → update. Loss expresses how poor a prediction is under a chosen rule; the update uses that signal to change the model. A particular learning algorithm specifies the loss and update rule for this loop.

Standard evaluation assumes training and test examples are independently drawn from the same underlying distribution (i.i.d.: independent and identically distributed). This assumption supports using held-out performance as evidence about future cases. The lecture points to collective classification when examples are dependent and transfer learning when test data comes from a different distribution; these are directions for handling changed assumptions, not guarantees that the issue is solved automatically. No Free Lunch is a separate idea: without assumptions or prior knowledge, there is no learner that is best for every possible problem. I.i.d. describes how samples relate; No Free Lunch describes the limits of universal algorithm rankings.

As a Teaching example, suppose a spam filter is trained and tested on randomly sampled mail from the same period and user population. If the deployed mail later shifts toward a new language or a new kind of phishing message, the deployment distribution may differ. The old test score then need not describe current performance. This example illustrates distribution shift; detailed evaluation and generalization are covered in Evaluation, generalization and model choice.

Three ways to reason from information

The lecture distinguishes learning by whether it generalizes a rule, applies an existing rule, or predicts particular cases directly.

Reasoning style Direction and role Lecture example
Induction Bottom-up: use observations to propose a general pattern or rule. The conclusion is plausible, not logically guaranteed. After repeated peanut/cough observations, infer a possible peanut allergy; from Jennifer’s usual 7 a.m. departure and punctuality, expect she may be on time today.
Deduction Top-down: apply accepted facts or rules to reach a conclusion that follows if the premises are true. All numbers ending in 0 or 5 are divisible by 5; 35 ends in 5; therefore 35 is divisible by 5.
Transduction Use observed examples directly to predict particular queried examples, without first requiring one global function approximation. k-nearest neighbors can compare a new case with stored cases at prediction time.

An inductive pattern can be useful while still admitting exceptions. Deduction preserves the truth of valid premises through a valid rule. Transduction focuses computation on particular predictions rather than insisting on a general rule for every possible input.

Learning families: what feedback is available?

The available feedback determines which problem formulation makes sense. Supervised learning receives desired outputs; unsupervised learning looks for structure without those target labels; reinforcement learning receives rewards through action sequences. Semi-supervised and self-supervised setups use different sources of learning signal.

Family Signal and typical goal Cases emphasized in the lecture
Supervised Examples pair inputs X with desired outputs F(X); predict output for a new X. Categorical outputs lead to classification, real-valued outputs to regression, and probability outputs to probability estimation. Cancer attributes such as clump thickness and cell uniformity; credit-risk classification from income and savings; used-car attributes predicting price.
Unsupervised Inputs arrive without desired outputs; find useful structure or representation. The lecture lists clustering, association, probability-distribution estimation, and dimensionality reduction. Clustering groups similar observations; anomaly detection looks for departures from established normal behavior; association describes co-occurrence. The slide gives P(chips∣beer)=0.7 as an association example.
Semi-supervised A small number of labeled examples are combined with many unlabeled examples. Classification when labeling all cases is difficult but unlabeled cases are available.
Self-supervised A model predicts one part of an input from another part of the input (also called predictive or pretext learning in the slide). Learn a signal from the structure of the input itself rather than a human-provided target label.
Reinforcement An agent observes states, chooses actions, and receives delayed, occasional scalar rewards; it learns a policy, a mapping from states to actions. Games, robot navigation, and balancing a pole. The goal is to maximize expected future reward.

Supervised settings also vary in their outputs and labels: multiclass classification chooses among more than two classes; multilabel classification can assign several labels to one case; one-class classification is given examples from only one class; multi-instance learning labels bags or groups while individual members are unlabeled. Regression can predict quantities such as used-car price, a car’s steering angle, or robot-arm kinematics. Supervised models may also support future prediction, knowledge extraction, compression, or outlier detection, depending on the task and representation.

Across applications, the lecture groups tasks into recognizing patterns (faces, handwriting, speech, medical images), generating patterns (images or motion), detecting anomalies (unusual transactions or sensor readings), and predicting future values or preferences. It also points to retail, finance, programming, medicine, telecommunications, bioinformatics, web mining, robotics, and knowledge engineering. These are examples of where learning may help; the application label alone does not determine which learning family is suitable.

In reinforcement learning, time matters: at step t, the agent observes state st, chooses action at, then receives reward rt+1 and next state st+1. Delayed rewards make it difficult to identify which earlier action helped or hurt, and a scalar reward carries less detail than a direct target label. The lecture notes that a discount factor can reduce the weight placed on rewards far in the future. The policy is learned from this sequence, not from a supplied correct action for every state.

Additional paradigms and task settings

The lecture’s list extends beyond the main feedback families. These terms describe where experience comes from, how tasks relate, what outputs matter, or how data behaves; they are not all mutually exclusive categories.

Paradigm or setting Practical meaning
Multi-task learning Learn related tasks together so shared structure can be useful across them.
Transfer learning Reuse a model developed for one task or domain as a starting point for another. In the lecture’s taxonomy, inductive transfer has labeled target-domain data but no labeled source data; transductive transfer has labeled source data only; unsupervised transfer has no labels in either domain.
Active learning The learner chooses which examples should receive labels from an oracle. Unlike reinforcement learning, it asks for labels rather than learning from action/reward interaction; unlike passive learning, it controls which labels to request rather than receiving examples chosen outside its control. Membership-query synthesis creates a new query; stream-based selective sampling considers examples one at a time; pool-based sampling ranks a pool and chooses a high-value query.
Ensemble learning Combine multiple models in the hope of improving prediction over a constituent model. Boosting builds models incrementally, emphasizing examples earlier models misclassified. The lecture’s committee analogy highlights that diversity or disagreement can matter; merely repeating identical judgments adds little.
Online / incremental learning Learn one instance at a time as examples arrive.
Ranking / preference learning Learn to order items or represent preferences rather than only assigning a class.
Sequence labeling Predict a label for each part of an ordered sequence, where neighboring positions may matter.
Cost-sensitive learning Account for different costs of different outcomes or errors.
Concept drift Account for a changing relationship between inputs and the target over time.
Collective classification Use relationships among dependent instances; independent case-by-case assumptions may miss useful information.

Choosing a learning system

The lecture makes four choices explicit. First choose the training experience: what cases, labels, interactions, or feedback will be available? Then choose exactly what is to be learned—the target function. Next choose how to represent that target; the representation determines which hypotheses can be expressed. Finally choose a learning algorithm to infer it from the experience. A mismatch at any stage can limit the result: the wrong data may not reveal the pattern, the wrong target may optimize an irrelevant outcome, and an unsuitable representation may not express the needed relationship.

Common mistakes

  • Treating data collection as the task definition. State T, P, and E separately; the chosen metric should reflect the cost of both useful and harmful outcomes.
  • Calling every observed pattern a proven rule. Induction proposes a generalization; examples alone do not guarantee it.
  • Confusing unsupervised learning with “no learning signal.” There may be no human target label, but structure in the input supplies the objective or representation signal.
  • Calling deployment the same thing as training. Inference applies the current model to new input; model updates require a later learning process.
  • Conflating i.i.d. with No Free Lunch. One is a sampling assumption; the other rules out universal superiority without assumptions.
  • Assuming paradigm labels are exclusive. A task may combine, for example, transfer with supervised learning or online updates with cost-sensitive decisions.
  • Treating the algorithm infographic as a universal ranking. Its descriptions are rough orientation; suitability depends on the task, data, assumptions, and costs.

Revision reminders

  • Define learning through improvement on task T, measured by P, from experience E.
  • A hypothesis is a candidate mapping; the hypothesis space is the set of mappings the representation can express.
  • Preserve the distinction between labels, hidden structure, and rewards when identifying the learning family.
  • Keep the training, held-out evaluation, and deployment stages distinct.
  • I.i.d. evaluation assumptions and No Free Lunch answer different questions.
  • Choose experience, target function, representation, and learner as connected design decisions.

1. A checkers program practices against itself. State T, P, and E.

Check your answer

T: playing checkers. P: percentage of games won against an arbitrary opponent. E: practice games against itself.

2. A handwritten-word recognizer is trained on human-labeled images. What are its task, performance measure, and experience?

Check your answer

T: recognize handwritten words. P: percentage of words correctly classified. E: a database of human-labeled handwritten-word images.

3. A customer has income $70,000 and savings $10,000 under the labeled teaching thresholds $60,000 and $10,000. What does the lecture’s strict-threshold rule predict?

Check your answer

High-risk. Income passes, but savings is equal to its threshold, not greater than it. Because both conditions must be true, the conjunction fails.

4. A researcher infers that a new medicine may help after observing improvement in several patients. Is this induction or deduction, and why?

Check your answer

Induction: specific observations are being used to propose a broader pattern. The inference can guide a hypothesis, but the observations alone do not logically prove that the medicine caused the improvement.

5. Which learning family fits each signal: (a) many labeled examples, (b) mostly unlabeled examples plus a few labels, (c) reward after action sequences?

Check your answer

(a) Supervised learning; (b) semi-supervised learning; (c) reinforcement learning.

6. A learner chooses whether to ask an expert to label a case. Which paradigm is this? How does pool-based querying differ from stream-based selective sampling?

Check your answer

This is active learning. Stream-based sampling decides one incoming example at a time; pool-based sampling ranks examples from a larger unlabeled pool and selects a query from that group.

7. Give one sentence distinguishing the i.i.d. assumption from No Free Lunch.

Check your answer

I.i.d. assumes training and test examples are independently drawn from the same distribution; No Free Lunch says there is no universally best learner across all possible problems without assumptions or prior knowledge.
