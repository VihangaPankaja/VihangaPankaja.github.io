Naive Bayes Classification (Supplemental Lecture Material)

A compact probabilistic classifier that combines class priors with feature likelihoods under a class-conditional independence assumption.

Supplemental lecture material · Not covered in class. This block is presented as an optional extension.

Big picture

Naive Bayes classifies a case by asking how plausible its observed feature values would be under each possible class. It begins with each class's prior frequency, multiplies by the class-conditional likelihood of each observed feature, and selects the largest score. The calculation is efficient because it treats features as conditionally independent once the class is known. That assumption is the “naive” part: it makes the product possible, but it may be a poor model of strongly related features.

The lecture uses categorical attributes and a small ten-row training set. We will count its probabilities directly, classify the same query, and then see how smoothing and missing query features change the calculation.

Bayes rule: from prior to posterior

Let C be the class and A1,…,Ak be attributes. For a query with observed values a1,…,ak, the posterior probability of class cj is

Pr(C=cj∣A1=a1,…,Ak=ak)=Pr(A1=a1,…,Ak=ak∣C=cj)Pr(C=cj)Pr(A1=a1,…,Ak=ak)

The prior Pr(C=cj) is the class probability before observing this query. The likelihood is the probability of seeing these features if the class were cj. The evidence in the denominator is the probability of seeing the query under all classes; it is the same for every candidate class. Dividing by evidence normalizes the values into posterior probabilities that sum to one.

A posterior is defined by this ratio when the evidence is positive. If every class gives the observed query zero probability, the denominator is zero and this model cannot produce a posterior without changing its probability estimates. For a decision alone, compare the unnormalized numerator; use the evidence when actual normalized model posteriors are wanted.

The naive assumption and classifier

The chain rule expands a joint feature likelihood into conditional factors. Naive Bayes makes one specific simplifying assumption: features are conditionally independent given the class. In other words, after fixing the class, learning one feature value does not change the probability assigned to another feature value. It does not say that features are independent in the whole population.

Pr(A1=a1,…,Ak=ak∣C=cj)=∏i=1kPr(Ai=ai∣C=cj)

For a categorical query, the classifier therefore uses a product of one prior and one likelihood for every observed attribute. A factor that is common to every candidate class can be omitted while choosing the largest score. A tie means more than one class attains the maximum; the lecture specifies no tie-breaking convention, so report the tied maximum classes or state an explicit implementation policy.

c^=argmaxcjPr(C=cj)∏i=1kPr(Ai=ai∣C=cj)
Worked example: estimating a categorical likelihood

Suppose class t appears in 5 training rows, and among those rows A=m appears 2 times. The maximum-likelihood estimates are

  • Prior: Pr(C=t)=5/10=1/2.
  • Likelihood: Pr(A=m∣C=t)=2/5.

The denominator of the likelihood is the number of training rows in class t, not all ten rows. Check: across the possible A values for this class, their counts total 5, so the estimated categorical probabilities sum to 1.

1. Read the query and class totals

Given: ten labeled rows, with five t and five f; query A=m, B=q. Estimate each prior from its class count: Pr(t)=5/10=1/2 and Pr(f)=5/10=1/2. Check: priors sum to 1.

2. Count the A likelihood for each class

Among the five t rows, A=m occurs twice, so Pr(A=m|t)=2/5. Among the five f rows, it occurs once, so Pr(A=m|f)=1/5. Check the numerators against rows 1, 2, and 10.

3. Count the B likelihood for each class

Among the five t rows, B=q occurs twice (rows 3 and 5), so Pr(B=q|t)=2/5. Among the five f rows, B=q occurs twice (rows 6 and 9), so Pr(B=q|f)=2/5. The feature counts use within-class denominators of five.

4. Multiply prior and likelihood factors

Under the naive conditional-independence assumption, score(t)=(1/2)(2/5)(2/5)=2/25=0.08. score(f)=(1/2)(1/5)(2/5)=1/25=0.04. These are unnormalized scores: the common evidence denominator has not yet been applied.

5. Compare and normalize

The evidence represented by these two class scores is 2/25+1/25=3/25, which is positive. Thus the normalized model posterior is Pr(t|A=m,B=q)=(2/25)/(3/25)=2/3; Pr(f|A=m,B=q)=(1/25)/(3/25)=1/3. Check: they sum to 1, and t is the larger score, so predict t.

6. Interpret what the posterior means

The values 23 and 13 are normalized posteriors under the naive model. They are not empirical joint frequencies or a guarantee of calibration. No training row has both A=m and B=q: the query combination is unobserved. The model assigns it likelihood by multiplying separate within-class feature likelihoods. The source slide gives the same class t decision; its conditional for A=h once prints C=n, but the table has only t and f, and the corresponding count is for class f.

Zero counts, smoothing, and missing query features

A zero count gives a zero maximum-likelihood likelihood. Since Naive Bayes multiplies likelihoods, one zero can erase a class score even when the other observed features support that class. The lecture gives the categorical smoothing rule below. Here nij is the count of category ai for feature i among examples in class cj; nj is the number of training examples in class cj; ni is the number of categories of feature i; and λ is a positive smoothing amount. In particular, ni counts categories of that feature, not the number of features.

Pr(Ai=ai∣C=cj)=nij+λnj+λni
Supplemental calculation: smooth a zero count and check the category sum

Teaching example. For one feature with three allowed categories red, blue, green, suppose class yes has 4 examples with counts 2, 2, 0. Use λ=1.

  • Denominator: 4+1·3=7.
  • Smoothed probabilities: red =(2+1)/7=3/7; blue =(2+1)/7=3/7; green =(0+1)/7=1/7.
  • Check: 3/7+3/7+1/7=1 and the unseen green category now has positive likelihood.

Without smoothing, green has likelihood 0/4=0, so any class score containing that factor becomes zero. This example illustrates the stated formula; it is not an additional count from the lecture table.

The lecture treats missing query values as ignored: omit the missing feature's likelihood factor and use the factors for features that are observed. Do not replace a missing value with a category count of zero. This is a prediction-time rule; it does not specify a policy for missing values in training data.

The supplied categorical method discretizes numeric attributes into categories before counting. Other Naive Bayes variants can model numeric features with different likelihood distributions, so discretization is not required by every method called Naive Bayes.

Benefits and limits

Naive Bayes is easy to implement and very efficient: training stores class and feature-category counts, and prediction multiplies a small set of probabilities for each class. It can produce good results across many applications. Its central limitation is the conditional-independence assumption. When features remain strongly related even after conditioning on the class, multiplying their separate likelihoods can overstate or understate the joint evidence and reduce accuracy. Smoothing addresses unseen categorical values; it does not repair dependence between features.

Common mistakes

  • Confusing likelihood and posterior: Pr(Ai=ai∣C=cj) asks how likely a feature value is within a class; Pr(C=cj∣Ai=ai) reverses the condition.
  • Using the wrong denominator: conditional counts are divided by the number of training rows in that class, not by all rows.
  • Calling the features unconditionally independent: independence is assumed only after fixing the class.
  • Treating a score as a posterior: multiply prior and likelihoods for an unnormalized score; divide by positive evidence to get normalized posteriors.
  • Reading a zero score as proof the class is impossible: it may be an unseen category; smoothing can assign it a positive probability.
  • Multiplying a missing feature as zero: omit that query factor under the source's missing-query convention.
  • Assuming numeric features always need bins: this lecture's categorical method needs discretization; other variants model numeric likelihoods directly.
  • Inventing a tie rule: if maximum scores tie, report the tie or clearly state the chosen policy.

Exam focus

  • Bayes rule: posterior is likelihood times prior divided by evidence.
  • Categorical estimates: prior = class count / total count; likelihood = feature-category count within class / class count.
  • Naive assumption: features are conditionally independent given the class.
  • Classification: compare Pr(C=cj)∏iPr(Ai=ai∣C=cj) across classes.
  • Normalization: divide each class score by the sum of class scores when evidence is positive; normalized posteriors sum to one.
  • Smoothing: add λ to a category count and λni to its class denominator; ni is the number of categories for that feature.
  • Missing query feature: omit its factor. Categorical numeric values may be discretized. Know the conditional-independence limitation.

Practice questions

1. In one class, a feature category occurs 3 times among 8 rows. What likelihood does the unsmoothed categorical estimate assign?

Check your answer

Pr(Ai=ai∣C=cj)=3/8. The denominator is the number of examples in the class.

2. If a query has three observed attributes and one missing attribute, what factors enter the source method’s class score?

Check your answer

Use the prior and the three observed feature likelihoods. Omit the missing attribute's factor; do not substitute zero.

3. Why can two class scores be compared without calculating the evidence denominator?

Check your answer

Evidence depends on the query but is identical for every candidate class. Dividing each numerator by the same positive number preserves their ordering.

4. A feature has four categories and a class has 6 rows. One category occurs zero times. With λ=1, what smoothed probability does it receive, and what do all four probabilities sum to?

Check your answer

The denominator is 6+1·4=10. The unseen category gets (0+1)/10=1/10. For any category counts totaling 6, the four smoothed numerators total 6+4=10, so the probabilities sum to 1.

5. What independence assumption does Naive Bayes make, and what is a consequence if it is badly violated?

Check your answer

It assumes attributes are conditionally independent given the class. Strong residual feature dependence can make the product likelihood a poor approximation to the joint likelihood and reduce accuracy.
