Domain Adaptation, Shift, and Negative Transfer

Compare what transfers across domains, what labels remain available, and when transferred knowledge can hurt.

Transfer is useful when one collection of data does not fully match the task we care about. The lecture groups several approaches under transfer learning, while warning that the names and boundaries vary across sources. The most reliable way to compare them is to ask what stays the same, what changes, and which labels are actually available.

Big picture

Domain adaptation keeps the task but changes the domain: labeled source examples teach the task, and unlabeled target examples help shape a representation that works across both domains. Zero-shot learning addresses a different gap: the target class may have no labeled training examples, but it has a semantic description such as attributes or a word vector. Covariate shift describes a particular distribution change. Self-taught and unsupervised transfer use unlabeled auxiliary data in different ways. Negative transfer is the failure case in which transfer makes target performance worse.

This page continues the earlier transfer-learning foundations, which cover task/domain terminology and other transfer approaches.

Domain adaptation: same task, different domain

In the lecture's domain-adaptation setup, the source and target share the task but differ in domain. The source data has examples and task labels, (xs,ys). The target collection supplies inputs xt without task labels during adaptation. The domain-origin label is a separate piece of information: each source example is known to be from the source domain and each target example from the target domain. It is not a task label.

The slide examples make the distinction concrete: labeled MNIST digits can be the source for unlabeled MNIST-M images; synthetic digits can be paired with SVHN; SVHN can be paired with MNIST; and synthetic signs can be paired with GTSRB. In each pair, the visual input distribution changes while the intended classification task remains the same.

Worked setup: what labels enter a domain-adaptation minibatch?

Suppose a source minibatch contains images and digit labels, while a target minibatch contains images only.

Example Task label available to adaptation? Domain-origin ID available?
Source image xs Yes: ys Yes: source
Target image xt No Yes: target

The label predictor learns the task from source pairs (xs,ys). The domain predictor uses the source/target origin IDs for both batches. Feeding a target task label into this training step would change the stated unsupervised-target setup.

Domain-adversarial training (DANN)

The feature extractor maps both domains into a shared representation. A task-label head should predict source labels well. A second head tries to identify whether a feature came from the source or target. If the domain head can easily tell them apart, the representation still carries domain clues. The feature extractor is therefore trained to support the task while making domain origin harder to identify. This resembles an adversarial objective, but its purpose is a transferable representation rather than generated samples.

The gradient reversal layer is the identity during the forward pass: it passes features through unchanged. During backpropagation, it multiplies the domain-loss gradient entering the feature extractor by the negative scaling factor. The task head minimizes task loss, and the domain head minimizes domain loss. The following objective is a supplemental formalization of these goals.

minθf,θymaxθdLy(θf,θy)−λLd(θf,θd)

With this objective, the feature extractor descends the task gradient and ascends the domain loss, giving a gradient proportional to ∇θfLy−λ∇θfLd. The task head descends Ly. The domain head descends Ld; equivalently, its descent step absorbs the objective's λ scaling into its step size. The lecture does not specify a numeric λ, optimizer, learning rate, batch size, or schedule.

DANN: forward pass, three parameter updates, and target check

Visible givens: source minibatch (xs,ys); target minibatch xt; symbolic initial parameters θf(0),θy(0),θd(0); teaching values λ=0.5, η=0.1, and illustrative gradients shown in the relevant update steps. Target task labels are withheld. All gradients use this same pre-update snapshot; the three parameter updates are applied together.

1. Start from parameters and minibatches

Keep symbolic initial parameters θf(0), θy(0), and θd(0). The course slide does not give trained parameter values. For this supplemental sign calculation only, set λ=0.5 and learning rate η=0.1. The source minibatch has (xs,ys); the target minibatch has xt but no task label. Both carry a domain-origin ID.

2. Compute losses and gradients from one snapshot

Pass both inputs through the shared extractor and compute Ly using only source task labels. Compute Ld using source/target origin IDs. The GRL passes features unchanged in this forward pass. No target task label enters either loss.

Compute all gradients using the same old parameter snapshot θf(0),θy(0),θd(0). The next three states explain which parameter group receives each update; apply those updates together after computing the gradients. Do not recompute a later gradient using an already updated feature extractor.

3. Update the feature extractor

Assume a tiny illustrative minibatch yields ∇θfLy=(2,−1) and ∇θfLd=(1,4). These are invented teaching gradients, not source measurements. The reversed, scaled feature gradient is (2,−1)−0.5(1,4)=(1.5,−3). Thus θf(1)=θf(0)−0.1(1.5,−3)=θf(0)+(−0.15,0.30).

4. Update the task head

For the same illustrative example, let ∇θyLy=(0.6,−0.2). The task head descends its task loss: θy(1)=θy(0)−0.1(0.6,−0.2)=θy(0)+(−0.06,0.02). Only source task labels contributed to this gradient.

5. Update the domain head

Let ∇θdLd=(0.4,−0.8). To match the displayed saddle objective, use the domain-head step scaled by λ (or equivalently absorb that scale into its learning rate): θd(1)=θd(0)−0.1(0.5)(0.4,−0.8)=θd(0)+(−0.02,0.04). The domain head still moves downhill on Ld; it is not reversed.

6. Infer and check separately

At inference, map a target input through the feature extractor and task head to get a task prediction. There is no target label in this inference step, so it cannot produce target task accuracy by itself. Check source task performance and whether the domain head struggles separately. Chance-level domain prediction is only a conceptual reference for balanced domains; it is not proof that adaptation succeeded. Evaluate target task performance only with a separately labeled target evaluation set, if one exists.

Zero-shot learning: descriptions for unseen classes

Some tasks cannot include every possible class in labeled training data. The lecture uses speech recognition, where every possible word cannot be present, and then shows image classes. Zero-shot learning can still consider a class when labeled examples of that class were absent from training, provided a semantic description is available at prediction time. A class description is not a labeled target training image.

Attribute vectors and a nearest-description decision

The lecture represents classes by attributes in the order (furry,4 legs,tail). A network predicts attributes from the input image, then the result is compared with the class database. The source asks for the most similar attribute vector. The following Hamming-distance calculation makes that decision explicit as a supplemental calculation.

Compare the predicted attributes with each class

1. Record the input and attribute order

Input prediction: (0,0,1). Positions mean furry, four legs, and tail, in that order.

2. Compare Dog: (1, 1, 1)

Bitwise differences: 0≠1, 0≠1, 1=1. Distance: 1+1+0=2.

3. Compare Fish: (0, 0, 1)

All three bits match: 0+0+0=0.

4. Compare Chimp: (1, 0, 0)

First and third bits differ; the middle bit matches: 1+0+1=2.

5. Select and check

The unique minimum is Fish with distance 0. Dog and Chimp tie at distance 2. The lecture says “most similar”; Hamming distance is the clearly labeled calculation used here to complete that comparison. If two class descriptions tie for the minimum, this rule cannot choose uniquely. Attributes must distinguish the candidate classes.

Shared embeddings and a margin

Instead of hand-designed attribute tables, the lecture maps an input and a class description into a shared embedding space: f(x) for the input and g(y) for the class. The paired image/class should be compatible, while a mismatched class should score lower. If the attribute database is unavailable, the slides suggest word-vector descriptions such as V(chimp), V(dog), and V(alpaca).

Simply making every positive pair close can collapse all representations to the same point. The lecture's margin-ranking objective uses a positive pair (xn,yn) and the hardest wrong class description among candidates m≠n. Here n identifies the paired example/class, while m ranges over wrong candidate classes; a different sample index with the same class label is not automatically a negative class.

∑nmax(0,k−f(xn)·g(yn)+maxm≠nf(xn)·g(ym))

The hinge becomes zero when the positive compatibility exceeds the hardest wrong-class compatibility by at least the margin. Rearranging the source equation gives:

f(xn)·g(yn)−maxm≠nf(xn)·g(ym)≥k
Worked algebra: when is the hinge loss zero?

For one paired example, call the positive score s+=f(xn)·g(yn) and the hardest wrong-class score s−=maxm≠nf(xn)·g(ym). The hinge is max(0,k−s++s−).

For zero loss, its inside must be nonpositive:

  1. k−s++s−≤0
  2. Move the positive score to the other side: s+−s−≥k.

Thus the positive score needs a margin of at least k over the hardest wrong class. This derives the condition; it does not assume any embedding coordinates or training outcome.

The lecture's example is about semantic transfer across languages, not a new performance claim.

Covariate shift: the input mix changes

Covariate shift is the lecture's case where source and target have the same input space X, output space Y, and conditional label rule, but different input marginals. In plain language, the kinds of inputs become more or less common while the assumed mapping from an input to its label remains stable.

PS(y∣x)=PT(y∣x),PS(x)≠PT(x)

The formal equality is about P(y∣x), not the marginal P(y). If the mix of inputs changes, the overall frequency of output labels can change too. Do not infer that the label marginal must remain fixed.

The source examples are a lighting change in image categorization, missing age or ethnic groups in facial-recognition training data, and speech recorded from different accents or dialects. These fit the covariate-shift description only while the conditional task rule is treated as stable. The lecture does not provide an importance-weighting procedure or data for a numeric correction.

Unsupervised transfer: cluster target data with auxiliary help

In the lecture's terminology, unsupervised transfer aims to cluster a small unlabeled target collection with help from a much larger unlabeled auxiliary collection. Their topic distributions may differ. They are clustered simultaneously so that the auxiliary data's representation can influence target examples through shared features. The lecture explicitly warns that the term is used differently across literature, so keep these defining data conditions attached to the name.

Negative transfer and ways to limit it

Negative transfer occurs when a transfer method decreases target-task performance. The reference point is learning the target task without transfer. The lecture describes three strategies: reject harmful source-task knowledge; choose a source task that is at least a reasonable match; or model task relationships explicitly so the transfer method can use similarity information.

These are risk-reduction strategies, not guarantees. A practical check is to compare transfer and a target-only baseline using the same held-out target evaluation protocol. If labeled target evaluation data are unavailable, this comparison cannot honestly report target-task accuracy.

Pretraining examples in vision and language

Computer vision

The lecture presents ImageNet-pretrained models as an influential and standard practice in computer vision at the time of the slides. Its feature montage moves from edge and texture patterns toward parts and object-level features across layers. Treat this as the lecture's explanation of why learned visual representations can transfer; it is not a current survey or a universal performance claim.

Natural language processing: static word embeddings

The lecture describes pretrained static word embeddings as an important component in deep-learning systems. It also lists limitations of this shallow approach: it is efficient but less expressive; a word's representation is not context-sensitive; senses are not distinguished; only the embedding/first layer is pretrained; and the rest of the model must be trained from scratch. These are properties of the static embedding approach discussed in the slides.

Common mistakes

  • Mixing up labels: source task labels, target task labels, and source/target domain IDs have different roles. Unlabeled target data still have a known domain origin.
  • Reversing every DANN gradient: reverse only the domain-loss signal entering the feature extractor. The domain head minimizes its own domain loss.
  • Calling domain confusion proof of task success: domain confusion and task performance are separate checks. Target task evaluation needs separately labeled target examples.
  • Confusing zero-shot with missing class descriptions: labeled target-class training images can be absent while semantic class descriptors are still available.
  • Assuming every attribute set identifies a class uniquely: repeated descriptors or equal nearest distances create ambiguity.
  • Confusing the marginal label frequency with the conditional task rule: covariate shift preserves P(y∣x); it does not require P(y) to stay fixed.
  • Assuming transfer always helps: negative transfer is defined by worse target performance than the no-transfer baseline.
  • Reading entropy as an accuracy score: the lecture labels its table entropy and does not add a legend specifying the preferred direction.

Revision checklist

  • Domain adaptation: same task, different domain; source task labels available, target task labels withheld during adaptation.
  • DANN: source task loss trains task prediction; source/target origin loss trains the domain head; only its feature-extractor gradient is reversed.
  • Zero-shot: unseen labeled training classes can be considered through available semantic descriptions.
  • Covariate shift: same X, Y, and P(y∣x); changed P(x).
  • Self-taught: learn a representation from unlabeled auxiliary data, then use labeled target data for the task.
  • Unsupervised transfer as defined here: jointly cluster small unlabeled target data with larger unlabeled auxiliary data using shared features.
  • Negative transfer: transfer reduces target performance relative to a target-only baseline.
  • Pretraining examples: ImageNet features in CV and static word embeddings in NLP, with the limitations stated in the lecture.

Practice questions

1. A labeled source set and unlabeled target set share a digit task but differ in image appearance. Which labels can the DANN task head use during adaptation?

Check your answer

Only the source task labels. Both source and target examples can carry domain-origin IDs, because their origin is known. Target task labels remain unavailable in the stated adaptation training setup.

2. Which DANN parameter group receives the reversed domain gradient, and what is the sign in its feature update?

Check your answer

The feature extractor θf receives the reversed signal. For the objective Ly−λLd, its descent direction is based on ∇θfLy−λ∇θfLd. The domain head still minimizes Ld.

3. For the source attribute table, what are the Hamming distances from query (0,0,1) to Dog (1,1,1), Fish (0,0,1), and Chimp (1,0,0)?

Check your answer

Dog: two differing bits, distance 2. Fish: zero differing bits, distance 0. Chimp: first and third bits differ, distance 2. Fish is the unique nearest class under this supplemental Hamming calculation.

4. What does zero loss require in the lecture’s margin-ranking objective?

Check your answer

The positive image/class compatibility must exceed the hardest wrong-class compatibility by at least the margin: f(xn)·g(yn)−maxm≠nf(xn)·g(ym)≥k.

5. Under covariate shift, can the marginal output-label distribution change?

Check your answer

Yes. The stable condition is PS(y∣x)=PT(y∣x), while the input marginal changes. A changed mix of inputs can also change the overall marginal P(y).

6. In the source’s self-taught examples, is the auxiliary source data labeled for the representation-learning step?

Check your answer

No. The representation is learned from unlabeled auxiliary source data; labeled target examples support the target task afterward.

7. How does the lecture define negative transfer?

Check your answer

A transfer method has negative transfer when it decreases target-task performance relative to learning the target task without transfer.

8. Give one static word-embedding limitation from the lecture.

Check your answer

The representation is not context-sensitive: the same word vector does not change with sentence context. The lecture also says it does not distinguish senses and that only the embedding/first layer is pretrained.
