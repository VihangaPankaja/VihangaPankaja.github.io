Sequence-to-Sequence and Encoder–Decoder Models

Understand how ordered inputs map to outputs, compare sequence-task types, and trace the encoder–context–decoder flow.

Big picture

A sequence is a set of observations whose order carries meaning. Sequence-to-sequence (Seq2Seq) learning maps an ordered input sequence to an ordered output sequence. The task may keep or change sequence length and representation. The reversal example makes order explicit; the encoder–decoder architecture separates reading an input sequence from generating an output sequence.

Ordered observations and Seq2Seq tasks

Time-series measurements and audio samples are examples of ordered data: rearranging observations changes the signal being represented. Text and video frames also form sequences. A Seq2Seq task learns a mapping from input sequence X to output sequence Y; machine translation is a central example.

Application What the sequence mapping does
Machine translation Translate text from one language to another
Image captioning Generate a textual description of an image
Video captioning Generate textual descriptions for video content
Text summarization Produce a concise summary that preserves the main information
Question answering Generate an answer to a natural-language question
Speech recognition Convert spoken language into text
Time-series forecasting Predict future observations from historical sequential data

Two separate task taxonomies

The lecture classifies tasks along two different axes. Length asks whether input and output lengths are fixed or variable. Modality asks whether the input and output representations are from the same kind of data or different kinds. These labels do not determine how many outputs align with each input step; that is a separate mapping-pattern question.

Axis Case Lecture example
Sequence length Fixed input and output lengths Sequence reversal
Sequence length Variable input and output lengths Machine translation
Sequence modality Same modality Machine translation (text to text)
Sequence modality Different modalities Image captioning (image to text)

For example, machine translation is shown as variable-length and same-modality: a text sequence maps to another text sequence. Image captioning is shown as a different-modality task: an image representation maps to a word sequence. These are two descriptions of the task, not competing categories.

Input/output mapping patterns

The mapping pattern describes the number and alignment of inputs and outputs. In many-to-many Type I, an output is associated with each input step. In many-to-many Type II, the model consumes an input sequence and generates an output sequence; the two sequences need not have step-by-step alignment.

Input/output mapping What is produced Lecture example
Many-to-one One output label from an input sequence Sentiment classification: a sequence of words → sentiment class
One-to-many An output sequence from one input Image captioning: image → sequence of words
Many-to-many, Type I One output aligned with each input step Frame-level video action recognition: video frame → action class
Many-to-many, Type II An output sequence from an input sequence Video captioning: video frames → caption

Keep the Type I and Type II distinction visible in examples: per-frame action recognition labels frames, while video captioning turns a sequence of frames into a caption. Sentiment classification instead maps many words to one class, and image captioning maps one image to many words.

Numerical sequence representations

Neural networks process numerical representations, so text-based symbols must be encoded before a model can use them. The lecture lists one-hot encoding, Bag-of-Words (BoW), Word2Vec, BERT, and Wav2Vec. The key sequence distinction is that a per-step representation can keep each symbol attached to its time step, while an aggregated BoW vector records token occurrences without their positions.

Representation What to remember for sequence tasks
One-hot encoding Represents each discrete category with a vector whose active position identifies that category. The category axis is separate from the sequence/time axis.
Bag-of-Words (BoW) Aggregates token occurrence counts or presence. Because it does not retain token positions, it discards word order.
Word2Vec Listed by the lecture as a numerical encoding technique.
BERT Listed by the lecture as a numerical encoding technique.

Reverse-sequence example

The lecture gives a fixed-length Seq2Seq task: the target is the input values in reverse order. To check each target position, use one-based input and target positions. If the sequence length is six, target position j comes from input position 7−j. The viewer walks all six alignments using the exact supplied sequences.

Worked example: align every target position

Six-step alignment for the reverse-sequence task

Given sequencesInput: X=[3,2,5,4,9,1]Target: Y=[1,9,4,5,2,3]Positions are one-based; for a length-six reversal, target position j takes input position 7−j.

1. Align target position 1

The reversal rule is Yj=X7−j. For j=1, the input position is 7−1=6: Y1=X6=1.

2. Align target position 2

For j=2, the input position is 7−2=5: Y2=X5=9.

3. Align target position 3

For j=3, the input position is 7−3=4: Y3=X4=4.

4. Align target position 4

For j=4, the input position is 7−4=3: Y4=X3=5.

5. Align target position 5

For j=5, the input position is 7−5=2: Y5=X2=2.

6. Align target position 6 and check

For j=6, the input position is 7−6=1: Y6=X1=3.

The target is [1,9,4,5,2,3], exactly the input [3,2,5,4,9,1] in reverse order. Check: both have six entries and the same multiset of values; only their order changes.

Why the MLP baseline struggles with reversal

The lecture’s multilayer perceptron (MLP) processes each time step independently. Without a mechanism that carries information across positions, it does not model temporal dependencies and cannot learn which distant input position supplies each reversed output. This explains the slide’s poor MLP result for the reversal task; recurrent state and gate details are covered in the prerequisite topic.

Encoder–decoder and context

An encoder–decoder divides Seq2Seq into two roles. The encoder converts the input sequence into a context representation. Information passes through that context to the decoder, which generates the output sequence. The input and output can have different lengths and different representations, as in translating between languages.

The lecture connects this architecture to machine translation, image and video captioning, summarization, question answering, speech recognition, and time-series forecasting. For the recurrent hidden-state transfer, RNN, LSTM, and GRU details, continue to RNNs, LSTMs, and GRUs.

Common mistakes

  • Treating fixed/variable length and same/different modality as one taxonomy. They describe separate properties of a task.
  • Calling all many-to-many tasks aligned. Type I has per-input-step outputs; Type II maps an input sequence to an output sequence.
  • Treating a BoW count vector as if it preserved word positions. Aggregation loses order.
  • Confusing the number of time steps with the number of categories in a one-hot vector. A sample may have six time steps and ten possible category IDs.
  • Assuming the MLP parameter count or slide-reported accuracy proves that its computation tracks earlier sequence elements. The key limitation is that the MLP processes time steps independently.
  • Confusing the encoder–decoder sequence flow with the recurrent state-transfer details; those implementation details are covered in the prerequisite topic.

Exam focus

  • Define sequence data by meaningful order, and explain why changing order changes the data.
  • Classify length, modality, and input/output mapping independently.
  • Distinguish many-to-many Type I frame alignment from Type II sequence generation.
  • State why a numerical representation is needed and why BoW alone loses order.
  • Apply the reversal position rule: target position j receives input position 7−j for the six-element example.
  • Explain the encoder → context representation → decoder flow and why input/output lengths or representations may differ.

Practice questions

1. A translation task has variable input/output lengths and maps text to text. Which two taxonomy labels describe those properties?

Check your answer

It is variable-length and same-modality. These labels describe independent axes.

2. A video system assigns one action class to every frame. Is this many-to-many Type I or Type II?

Check your answer

Many-to-many Type I: an output class is aligned with each input frame.

3. What is the difference between the reversal example’s six time steps and ten one-hot categories?

Check your answer

Six is the number of ordered positions in the sample. Ten is the number of possible category IDs, so each time step can be represented by a ten-entry one-hot vector.

4. For the supplied input, what value is aligned with target position 2, and how do you locate it?

Check your answer

Target position 2 uses input position 7−2=5. The fifth input value is 9, so Y2=9.

5. Why does the lecture say the MLP performs poorly on reversal?

Check your answer

It processes each time step independently and therefore does not model dependencies between sequence positions needed to map an input value to its reversed target position.

6. What does the context representation do in the encoder–decoder diagram?

Check your answer

It carries information from the encoder’s input-sequence representation to the decoder, which uses it to generate the output sequence.
