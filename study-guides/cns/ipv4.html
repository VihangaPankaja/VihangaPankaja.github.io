IPv4 addressing, subnetting and VLSM

A prefix divides each 32-bit IPv4 address into a network and host part. Once that boundary is clear, you can calculate subnet ranges, check local membership, aggregate routes and allocate mixed-size networks without overlap.

Big picture

IPv4 gives each interface a 32-bit address. A subnet prefix says how many leading bits identify the network; the remaining bits identify an address within it. The same boundary lets a host decide whether a destination is local, lets routers describe address blocks compactly, and lets a network planner fit LANs and links into a finite parent block.

Read an IPv4 address and its prefix

Each IPv4 address has four 8-bit octets, usually written in decimal. An interface connects a host or router to a link and has its own IP address; a router normally has several interfaces, often in different networks. The lecture’s full representation is:

Form 223.1.7.4
Binary 11011111 00000001 00000111 00000100
Hexadecimal DF010704
Unsigned decimal 3741386500

The lecture’s topology uses three /24-style networks—223.1.1.xx, 223.1.2.xx and 223.1.3.xx—joined through a router with an interface in each network. Hosts on a shared network can exchange frames locally; the router connects the distinct prefixes.

For /n, the first n bits form the network prefix and the remaining 32−n bits are the host part. A subnet mask writes a 1 for each network bit followed by 0s for host bits. CIDR expresses the same boundary as address/prefix, for example 200.23.16.0/28. The n may end inside an octet, so do not assume that the first three decimal numbers always describe the network.

The lecture’s slide 16 labels the totals minus one as “No. of Hosts” (3, 7, 15, 31, 255, 65535). For the ordinary subnet convention used in both labs, reserve the all-zero network identifier and all-one broadcast, leaving 2h−2 usable addresses. The slide also incorrectly says that 200.23.17.16 can be assigned in 200.23.17.16/28: here .16 is the network identifier, usable hosts are .17–.30, and .31 is broadcast. RFC 1122 defines special network and broadcast address forms; RFC 3021 specifies the /31 point-to-point exception. These labs use /30, so the ordinary two-address reservation applies (RFC 1122, RFC 3021).

Class A/B/C fixed boundaries are historical, not modern allocation rules; the lecture itself calls classful addressing obsolete. CIDR’s explicit prefix supports blocks sized to actual need, rather than forcing a class B sized allocation for a much smaller network (RFC 4632). The slide’s old class ranges are context only: A 1.0.0.0–127.255.255.255, B 128.0.0.0–191.255.255.255, C 192.0.0.0–223.255.255.255, D 224.0.0.0–239.255.255.255; they do not denote current assignable host ranges. For example, 127.0.0.0/8 is loopback space, not an ordinary host subnet (RFC 1122).

CIDR can divide one address in different ways

For lecture address 200.23.16.5, a /28 gives network 200.23.16.0/28 and host offset 0.0.0.5; its mask is 255.255.255.240. A /14 gives 200.20.0.0/14, host offset 0.3.16.5, and mask 255.252.0.0. The prefix—not the address’s old class—sets the division.

Calculate a network address and range

Bitwise AND the address with its mask. A 1 AND 1 stays 1; every other pair becomes 0. This preserves the network bits and clears host bits: network=AND(address,mask). The first address in the resulting block has all host bits zero; the broadcast has all host bits one. Ordinary usable host addresses lie between them, from network+1throughbroadcast−1.

Lab 2.1 · AND a host address with its mask

Input: host 192.168.10.131; mask 255.255.255.192 (/26).

1. Count the network bits

The mask 255.255.255.192 is /26: three full octets give 24 one-bits, and 192 = 11000000 contributes two more. The last six address bits are host bits.

2. Apply AND in the partial octet

Address .131       10000011
Mask .192           11000000
                    --------
Network octet       10000000 = 128

A bit remains 1 only when both corresponding bits are 1. The first 24 bits are preserved by 255; the last six bits are cleared by 0s.

3. Read the network and check the range

The result is 192.168.10.128/26. There are six host bits, so this block has 64 total addresses, .128 through .191. Under the ordinary subnet convention, .128 is the network identifier, .191 the broadcast, and .129–.190 the usable host range. The given .131 is inside it.

The shortcut is to calculate the block size in the partial octet as 256−mask octet. Round that octet down to the nearest multiple of the block size, then zero all later octets. The complete Lab 2.1 calculations are below; the AND examples in the partial octets show why the boundary lands there.

Check subnet membership and choose a gateway

Two addresses share a subnet only when their network addresses match under the same prefix. On a shared local link, matching prefixes allow direct local delivery; separate networks need a router and correctly configured gateway. The calculation by itself does not prove physical connectivity or that an interface is up.

Lab 2.1 · Do two /28 addresses share a subnet?

Input: PC-A 192.168.1.18; PC-B 192.168.1.33; both use 255.255.255.240 (/28).

1. Find PC-A’s block

A /28 leaves four host bits: each block has 16 addresses. In the last octet, block boundaries are multiples of 16. 18 falls in 16–31, so PC-A is in 192.168.1.16/28.

2. Find PC-B’s block

33 falls in 32–47, so PC-B is in 192.168.1.32/28. The network identifiers differ; the addresses are not in the same subnet.

3. Answer the lab’s two follow-ups

If both PCs share the same local link and are configured correctly, they cannot deliver directly to each other as same-subnet hosts; a routed path is needed. The highest usable address in PC-A’s block is 192.168.1.30 because .31 is the broadcast address. PC-B needs an unused address in 192.168.1.17–192.168.1.30 to join PC-A’s subnet; an address already in use cannot be assigned again.

The broader Lab 2.1 case uses /15, mask 255.254.0.0. The second octet advances in blocks of two: both 10.0.0.16 and 10.1.14.68 lie in 10.0.0.0/15, whose full range is 10.0.0.0–10.1.255.255. Under the lab’s shared-local-link assumption they are in the same network and can communicate directly. The lowest usable PC-B address is 10.0.0.1.

The lab’s company policy assigns the first usable address as gateway. For 172.16.140.24/18 (255.255.192.0), third-octet blocks advance by 64; 140 is in 128–191, so network is 172.16.128.0 and gateway is 172.16.128.1. For 192.168.184.227/29 (255.255.255.248), last-octet blocks advance by 8; 227 is in 224–231, giving network .224, usable range .225–.230, broadcast .231, and gateway 192.168.184.225.

Subdivide and aggregate prefixes

The lecture divides 200.23.16.0/20 into eight aligned /23 customer blocks. The /20 contains the whole range 200.23.16.0–200.23.31.255; each /23 uses 512 addresses and advances the third octet by two.

Customer Assigned prefix Customer Assigned prefix
0 200.23.16.0/23 4 200.23.24.0/23
1 200.23.18.0/23 5 200.23.26.0/23
2 200.23.20.0/23 6 200.23.28.0/23
3 200.23.22.0/23 7 200.23.30.0/23

An upstream router can advertise the covering 200.23.16.0/20 route for those allocations because every /23 is aligned within that parent. This is equal-size subdivision followed by route aggregation. VLSM below instead chooses different prefix sizes for different host requirements. The lecture’s second provider aggregate is 199.31.0.0/16.

Plan a variable-length address scheme

VLSM repeatedly subdivides a parent block so that large LANs receive larger blocks and point-to-point links receive small ones. Sort needs from largest to smallest, choose the smallest aligned power-of-two block that has enough usable addresses, allocate it, and carry forward the unused aligned remainder. This order prevents a small allocation from fragmenting space needed by a later large subnet.

8. Assign endpoints and validate the plan

For each /30, network+1,network+2,network+3 are the endpoint and broadcast offsets: HQ S0/0/0 172.16.254.1/30 ↔ BR1 S0/0/0 172.16.254.2; HQ S0/0/1 172.16.254.5 ↔ BR2 S0/0/1 172.16.254.6; BR1 S0/0/1 172.16.254.9 ↔ BR2 S0/0/0 172.16.254.10. Verify reachability separately from address validity

In Lab 2.2, configure the planned addresses and masks, activate the router interfaces, and test the directly connected serial peers: from HQ ping BR1 172.16.254.2, from HQ ping BR2 172.16.254.6, and from BR1 ping BR2 172.16.254.10. The worksheet sets the DCE side’s serial clock with clock rate 128000; the worksheet labels HQ S0/0/1, BR1 S0/0/0, and BR2 S0/0/0 as the DCE ends. Confirm the actual cable/device role before applying the command. The worksheet says the GigabitEthernet LANs are simulated with no attached devices; they stay down/down, and no routing protocol is configured. Thus a remote simulated-LAN ping failure is expected and does not show that the address plan is wrong. These are the worksheet’s expected checks, not a report of live router execution.

Lab 3.1 provides a second compact illustration: R1 G0/0 is 192.168.0.1/24, R1 G0/1 is 192.168.1.1/24; PC-B 192.168.0.3/24 uses .0.1 as gateway and PC-A 192.168.1.3/24 uses .1.1. The two hosts occupy different /24s, so R1 must be configured with active interfaces to route between them. The initial failed ping before R1 configuration is not an address arithmetic failure. Common mistakes

  • Counting the prefix as complete octets only. /20, /11, and /26 cut through an octet; apply the partial mask bits.
  • Calling the total address combinations the usable-host count. For the ordinary /30 and LAN convention here, subtract the network identifier and broadcast, leaving 2h−2 usable hosts.
  • Assigning the network identifier or broadcast to an endpoint. For 200.23.17.16/28, .16 and .31 are not ordinary host addresses.
  • Comparing full addresses instead of masked network addresses. A shared subnet depends on both address and prefix.
  • Treating equal subnet membership as proof of reachability. Devices must share a local link for direct delivery; routed paths also require working interfaces and routes.
  • Allocating VLSM blocks in arbitrary order or at unaligned boundaries. Start largest-first and place each power-of-two block on its natural boundary.
  • Treating Lab 2.2’s remote simulated LAN ping failures as VLSM errors. The worksheet explicitly says those LAN interfaces are down/down and routing is absent.

Exam focus

  • Convert dotted decimal octets using weights 128, 64, 32, 16, 8, 4, 2, 1, preserving leading zeroes.
  • For /n, the mask has n one-bits; host-bit count is 32−n; ordinary subnet capacity is 2h−2 usable hosts.
  • Network address: network=AND(address,mask); block size at a partial octet: 256−mask octet.
  • Broadcast sets all host bits to 1; usable range is network +1 through broadcast −1 under the convention used in these labs.
  • For VLSM, sort largest-first, select smallest fit, allocate aligned blocks, carry the remainder, assign endpoint addresses and validate capacity, parent containment and non-overlap.
  • Aggregation is valid when the component prefixes are contiguous, aligned and contained by the announced parent.

Practice

Why does AND with 255 leave an IPv4 octet unchanged?

Check your answer

Each bit in 255 is 1; x AND 1 = x for each bit. A mask octet of 0 clears the corresponding address octet.

Is 192.168.1.31 a usable host in 192.168.1.16/28?

Check your answer

No. /28 has 16 addresses per block; .16 is the network identifier and .31 is the broadcast. The usable range is .17–.30.

Why can the six LANs and three /30 links fit in the Lab 2.2 /17?

Check your answer

The first three LAN blocks use 28,672 addresses; the remaining three use 3,584:

28,672+3,584=32,256

The three /30 links add 12 addresses:

32,256+12=32,268

The parent /17 has 32,768 addresses, so 32,268<32,768. All blocks are aligned and disjoint; 500 addresses remain unallocated, including the unused fourth /30.

Does a successful HQ-to-BR1 serial ping prove the remote LANs can be reached?

Check your answer

No. It proves that the directly connected serial peer responded. The worksheet’s simulated Ethernet LANs have no attached devices, remain down/down, and require routing before remote LAN reachability can be tested.
