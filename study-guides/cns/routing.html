Network layer and routing

Routers move packets between networks. The central distinction is between choosing routes for traffic and forwarding each packet using the table that results.

The network layer moves packets between networks

The network layer is OSI Layer 3. The lecture lists establishing, maintaining, and terminating connections; insulating upper layers from transmission technologies; addressing; and routing. Its packet-switching model has hosts at the edge and switches or routers as intermediate nodes connected by point-to-point or multipoint links. A sender divides a data stream into packets, each with a header and data. Intermediate nodes pass each packet along until it reaches its destination.

The drawing shows the idea: a packet travels link by link through routers. The router makes a local forwarding choice at each hop; it does not need to know every detail of the application data.

Datagram and virtual-circuit service

The lecture contrasts two network service models. In a datagram (connectionless) network, there is no connection setup. Each packet carries its destination address, and each router looks up that destination when the packet arrives. In a virtual-circuit (connection-oriented) network, a connection is set up first and the end stations exchange sequenced packet streams. Routers keep per-connection state and forward using a connection identifier (CID) that can change at each link.

The last row records the lecture's broad service-model contrast, not a guarantee for every network protocol. Error handling, reliability, and congestion behavior depend on the specific protocols and network.

Addressing, routing, and forwarding

Addressing identifies end stations. The lecture compares flat identifiers (personal names or its example Ethernet strings 54b37630e050 and 549395b2a750) with hierarchical addresses: a postal address has nested place names, and 94 11 2 640382 is labelled as country, area, operator, and subscriber portions. These are illustrations of addressing structure, not IP subnet calculations. Addressing exists at several layers—physical, data link, network, and application—so the address used depends on which layer is making a decision. See OSI and encapsulation for layer roles and IPv4 addressing for network prefixes and subnet calculations.

End systems send and receive traffic; intermediate systems relay it between subnets. Keep routing and forwarding separate: routing computes or configures paths and builds forwarding tables; forwarding is the router's per-packet action of selecting an output using that table. A useful route method should be correct, simple, robust, stable, fair, and optimal for its chosen metric. These are design goals, not one formula that every network can maximize at once.

Route choices and metrics

Static (non-adaptive) routes are predefined. A small network may have a route for each destination and often a default route for destinations without a more specific entry. The lecture calls static routing labour-consuming and not resilient: an operator must update routes, and a fixed path will not automatically react to a changed network. Dynamic (adaptive) routing runs a routing protocol; the lecture describes centralized or distributed arrangements in which intermediate stations exchange routing information and calculate paths. A path may depend on link speed, delay, congestion, error rate, cost, and policy. Source routing is different: the source specifies the route.

“Distance” in a routing decision is a metric chosen by the routing design. It may mean hop count, physical distance, delay, inverse bandwidth, communication cost, or another measure. A path with fewer hops is not automatically the fastest or cheapest.

Hierarchical routing groups destinations using address prefixes and groups routers into regions. Routers handle paths within a region; gateways handle inter-region traffic. A hierarchy can simplify tables, especially when a larger network is summarized at a higher level.

The lecture's prefix sketch says to use a matching prefix in the table and otherwise use a default route. Modern routing clarification: when multiple prefixes match an IPv4 destination, forwarding normally chooses the most specific (longest matching) prefix. This resolves which matching entry wins; route aggregation is a separate way to advertise or store a broader prefix. See RFC 4632, section 5.1 and RFC 1812, section 5.2.4.3. This clarification adds no new route-computation lesson.

Routing mechanisms named in the lecture

The lecture surveys mechanism names rather than teaching their algorithms. Shortest-path routing seeks a minimum-length route under a selected metric. Flooding sends a packet on all unused outgoing links. Distance-vector routers keep destination-distance tables. Link-state routing tracks link state. Broadcast sends to every node.

Broadcast and flooding are not synonyms: broadcast describes the delivery goal (all nodes), while flooding is one forwarding method that may be used to spread a packet. Multicast targets a subset of hosts in a group. At a router, a multicast packet may go out on zero or more links according to which groups are reachable through those links.

Congestion and quality of service

Congestion occurs when offered traffic approaches network capacity. The lecture's graph distinguishes an ideal curve that rises and caps at capacity, a desirable curve that approaches the cap, and a congested curve that falls after a peak: adding offered load can eventually reduce delivered traffic. Open-loop control tries to prevent congestion before it occurs. Closed-loop control monitors the network, communicates developing congestion to an appropriate place, and takes action.

Quality of service (QoS) describes requirements such as reliability, delay, jitter (variation in delay), and bandwidth. The table preserves the lecture's relative examples. Its <2 s and <0.2 s values are illustrative slide thresholds, not service guarantees.

The lecture names three practical techniques: overprovisioning adds capacity, buffering absorbs short bursts at the cost of waiting, and traffic shaping controls when or how quickly traffic enters the network. It names Integrated Services (with RSVP as an example) for per-flow QoS, and Differentiated Services for classifying traffic and assigning different bandwidth, priority, or delay treatment by class.

Connecting unlike networks

Internetworking is needed because networks may differ in service, protocols, addressing, packet size, QoS, and security. The lecture's device-by-layer examples are repeaters and hubs at the physical layer, bridges and switches at the data-link layer, routers at the network layer, transport gateways at the transport layer, and application gateways at the application layer. This is a compact layer taxonomy; device behavior is covered in the corresponding OSI, LAN, and WAN notes.

Lab 3.1: configure and verify a router between two LANs

The lab builds PC-A — S1 — R1 — PC-B. PC-A connects to switch port F0/6; R1 connects to S1 at F0/5 from R1 G0/1; R1 G0/0 connects to PC-B. The two router interfaces are directly attached to the two IPv4 networks, so after configuration R1 needs no static route between these networks.

Device/interface IPv4 address Mask Default gateway
R1 G0/0 192.168.0.1 255.255.255.0 —
R1 G0/1 192.168.1.1 255.255.255.0 —
PC-A NIC 192.168.1.3 255.255.255.0 192.168.1.1
PC-B NIC 192.168.0.3 255.255.255.0 192.168.0.1

Before R1 is configured and its interfaces are enabled, PC-A cannot reach PC-B through a functioning gateway. Once both interfaces and both host gateways match the table, PC-A recognizes that PC-B is remote and sends the first-hop frame to gateway 192.168.1.1. R1 forwards the IP packet using its directly connected 192.168.0.0/24 route, then emits a new link-layer frame on G0/0 toward PC-B. On the reply, PC-B sends to gateway 192.168.0.1, and R1 forwards toward PC-A. The IP endpoints remain the two PCs while each link uses the next-hop interface's local delivery. For how the /24 networks follow from the mask, use IPv4 addressing.

Lab path: explain the successful ping after configuration

Lab values: PC-A 192.168.1.3/24, gateway 192.168.1.1; PC-B 192.168.0.3/24, gateway 192.168.0.1; R1 G0/1 192.168.1.1/24 and G0/0 192.168.0.1/24.

1 · PC-A chooses its gateway

PC-A is 192.168.1.3/24 and PC-B is 192.168.0.3/24. PC-A sees PC-B is outside its local network, so it sends the first-hop frame to its configured gateway 192.168.1.1.

2 · R1 uses the connected route

R1 receives the IP packet on G0/1. Its route for 192.168.0.0/24 is directly connected through G0/0, so no static route is needed between these two LANs.

3 · R1 forwards over the other LAN

R1 sends a new link-layer frame from G0/0 toward PC-B at 192.168.0.3. The IP destination remains PC-B; the outgoing local-link delivery is new.

4 · Check the return path

PC-B sends its reply to gateway 192.168.0.1. R1 has 192.168.1.0/24 directly connected through G0/1, returning the packet to PC-A. Independent check: show ip route should contain both expected C routes.

Lab reflection: diagnose a failed link or gateway

Diagnose the two Lab 3.1 reflection cases

Starting state: one router joins two /24 LANs; the reflection asks about a disabled G0/1 or a mismatched G0/1 address.

1 · Interface is administratively down

Enter interface g0/1 and issue no shutdown. Then recheck show ip interface brief. An administratively down state indicates configuration has disabled the interface; separately confirm the cable and operational state.

2 · Gateway address does not match

If R1 G0/1 is 192.168.1.2 while PC-A's gateway remains 192.168.1.1, the router is not answering at the configured gateway address. Correct R1 to .1 or update the gateway consistently. Sharing the /24 does not make .2 answer for .1.

3 · Verify the whole path

Check both router interface addresses and masks, no shutdown, cables and up/up states, PC addresses and gateways, then inspect show ip route. The expected connected routes are 192.168.0.0/24 on G0/0 and 192.168.1.0/24 on G0/1.

Review

Remember the packet destination stays constant in datagram forwarding while next hops change; a virtual-circuit lookup uses the incoming interface and CID together; routing builds or configures tables while forwarding applies them; and the lab's two C routes come from R1's two active, directly connected interfaces.

In the lecture's datagram trace, why does H2 remain the destination while A and C choose different next hops?

Check your answer

H2 is the packet's destination address. A uses its table to select C; C independently uses its table to select E. A next hop is the next router, not a replacement destination.

Which VC row is used at A for a packet arriving on C with CID 2, and what leaves A?

Check your answer

Match both input fields (C, 2). The table maps it to (H6, 1), so it leaves interface H6 with outgoing CID 1.

Why does Lab 3.1 need no static route between the two PC networks once R1 is configured?

Check your answer

R1 has one active interface in each network. Both networks are directly connected, so the router installs the two connected routes automatically.
