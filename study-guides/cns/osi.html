OSI model and encapsulation

A clear map of the OSI layers, their peer relationships, service terms and the way data is wrapped as it moves through a network.

Big picture

The OSI reference model makes a complicated, changing network easier to describe by dividing communication into layers with distinct jobs. A layer uses the service below it and offers a service above it. Matching layers on separate systems follow peer protocols, while the actual data moves through the lower layers. The OSI model is a shared reference framework, not a required implementation.

Why standards and layers help

Standards let products from different vendors communicate. A shared market gives purchasers more choice and supports mass production, which can lower cost. Standards may be voluntary, such as those published by ISO or the historical CCITT, regulatory requirements set by governments, or voluntary standards adopted by regulation.

Networks combine heterogeneous technologies and change quickly. Modularization and layering divide the design into manageable functions; standard interfaces let components work together and help engineers predict the effect of changes. Each layer should have a well-defined job. Boundaries should minimize unnecessary information flow, and the architecture should use enough layers to separate unrelated tasks without becoming unmanageable. Corresponding functions at different nodes give designers and users a common vocabulary.

The OSI reference model coordinates standards work and places existing standards in a common perspective. The lecture’s second deck dates ISO’s development of the model to 1974. ISO’s catalogue records the first ISO 7498 edition as published in October 1984, and its later ISO/IEC 7498-1 description says the model is not an implementation specification. The catalogue verifies publication dates and purpose, but does not establish the deck’s 1974 development date: treat that date as a lecture claim rather than a verified chronology. Services, interfaces and peer protocols

A service says what a layer offers to the layer above. An interface says how adjacent layers access that service. A protocol is the rule set used by matching peer entities on different systems. Peers communicate logically; data physically passes downward through the sender’s layers and upward through the receiver’s layers. Systems can implement the same functions differently if their peer protocols and interfaces remain compatible.

The seven OSI layers

Layer numbers rise from Physical (1) to Application (7). Read the layers upward to understand how a receiving host interprets data, and downward to follow sending. This is the only full layer map on this page.

LayerResponsibility and scope
7 · ApplicationAccess to network services for application processes, management functions and distributed applications; examples include file transfer, email, directory lookup, virtual terminal and the web.
6 · PresentationSyntax, formatting and data-representation differences between application entities; examples include encryption and virtual-terminal protocol.
5 · SessionApplication dialogue and session use; may manage simultaneous, alternate or one-way dialogue and checkpoints for recovery. Existing systems may handle these functions elsewhere.
4 · TransportEnd-to-end, process-to-process exchange; may provide ordering, flow/error control, multiplexing and requested quality of service (such as error rate, maximum delay, priority or security). These are service goals, not guarantees from every protocol.
3 · NetworkHost-to-host packet delivery across an internetwork, including addressing, routing, congestion control and quality of service; may establish, maintain or terminate connections across the communications facility.
2 · Data LinkFrames and controls one physical link, including link activation/maintenance/release and error/flow control. Examples include HDLC, LAP-B, LLC and LAP-D. A sound single link does not ensure an error-free multi-link path.
1 · PhysicalThe device/link interface and transmission of raw bits. Concerns include mechanical, electrical, functional and procedural characteristics; lecture examples include RS-232-C, RS-449/442/423 and portions of X.21.

Keep the scopes distinct: Data Link concerns one link, Network carries packets host to host across an internetwork, and Transport provides end-to-end service between processes. Layer 2 uses a link-layer address for the current link; Layer 3 uses a network-layer address to identify the destination host. The later LAN and Ethernet notes use the MAC view, while IPv4 addressing notes cover address and subnet calculations.

The lecture’s Data Link “error-free” and Transport reliability descriptions are service goals, not guarantees that every protocol eliminates all errors. A locally reliable link does not make a path of several links reliable end to end. Functions such as segmentation/reassembly, encapsulation, connection control, ordered delivery, flow control, error control and multiplexing are protocol capabilities; no claim is made that every protocol supplies all of them. Transport may make use of lower-layer service: a stronger Layer 3 service can permit simpler transport, while a less reliable network service may require more transport control.

Service access and service primitives

A layer can contain several service functions; each function can be a smaller task or routine. A Service Access Point (SAP) is the boundary point through which an adjacent layer accesses those services. A service interaction is described with four primitives:

PrimitiveDirection and meaning
RequestService user → provider: invoke a function.
IndicationProvider → remote service user: report or invoke the function at that SAP.
ResponseRemote service user → provider: complete a function previously indicated.
ConfirmProvider → original service user: complete a function previously requested.

For a requested operation, the provider completes the original user’s request with a confirm. An indication reports a provider-side event to the remote user, whose response completes that indicated function. These names describe service interactions; they do not mean every primitive is a separate network packet.

SDU, PCI, PDU, ICI and IDU

These terms are relative to the layer being discussed. User data passed from layer n+1 to layer n is that lower layer’s SDU. The peer protocol’s control information is PCI, and PCI plus SDU forms the layer’s PDU. At the adjacent SAP, ICI can carry temporary local information for invoking the service; the lecture defines an IDU as the total SAP transfer including SDU, PCI and ICI.

TermWhat it means at the layer boundary
SDUUser data passed transparently from layer n+1 to layer n.
PCIControl information exchanged by peer entities to guide protocol processing.
PDUThe layer’s protocol unit: PCI together with its SDU.
ICITemporary information passed between adjacent layers to invoke a service; it is not automatically sent to the remote peer.
IDUThe complete transfer across the SAP, including SDU, PCI and ICI.

The same bytes can have different names at adjacent layers: a layer’s PDU is carried as the lower layer’s SDU. ICI belongs to the interface handoff; do not count it automatically as transmitted peer-protocol data.

Encapsulation and decapsulation

Encapsulation adds a layer’s control information as data moves down the sender’s stack. At the receiver, each layer processes its control information and passes the remaining SDU upward. The slides list encapsulation as a protocol function and the quiz tests the immediate boundary: a link-layer frame encapsulates a network-layer packet.

Teaching example · one message, end-to-end and per-link information

Teaching example · follow one message through encapsulation

Given: source host A, destination host B, an intervening router R, and an application message M. Protocol fields and byte lengths are intentionally unspecified.

1 · Application data enters the stack

Host A has application data M for a process on host B. The upper-layer meaning is still M; this overview does not assign it a byte length or a specific application protocol.

Next: pass the data down through any presentation and session functions in use.

2 · Transport adds end-to-end control

The transport peer may add its own PCI, such as information needed by the chosen service. Call the resulting transport PDU T=PCI4+M. The exact fields depend on the protocol; this is a structural notation, not a universal header format.

Next: give T to the network layer as its SDU.

3 · Network identifies the destination host

The network layer adds its PCI, including network-layer source and destination information, giving N=PCI3+T. The destination identifies host B across the internetwork.

Next: give packet N to the data-link layer for the current link.

4 · Data Link wraps the packet for one link

For the first link, the data-link layer adds the control and addressing fields used by its link protocol: F1=PCI2+N (with any trailer as applicable). On an Ethernet link, these include source and destination MAC addresses and a frame check. Other link protocols use their own fields. This is why a frame carries a network-layer packet (Quiz 1, Q9).

Next: the physical layer transmits the frame as bits.

5 · A router rebuilds the link wrapper

At router R, the incoming link framing is processed and removed. The network packet is forwarded toward B, then placed in a new frame for the next link: F2=PCI2′+N. The link PCI changes with the link; the packet’s final network destination remains B.

Next: continue link by link until host B receives the packet.

6 · The destination decapsulates upward

Host B processes the received bits, link frame, network packet and transport unit in reverse order. Each layer interprets and removes its own applicable PCI, then passes the recovered SDU upward. The transport service delivers to the intended process if that protocol provides the required service.

Check: logical peer rules apply at corresponding layers, but the physical data traversed the lower layers. The end-to-end destination stayed B while each router used a new link wrapper.

Real field layouts depend on the protocol. At a router, the received link wrapper is replaced for the next link while the network packet is forwarded toward the same final host. For actual address resolution, switching, and IP forwarding, continue to LAN and Ethernet and IPv4 addressing.

TCP/IP in perspective

The second deck illustrates a TCP/IP model with Application, Transport, Internet and Data Link, and draws Physical beneath it as the required transmission service. Its figure retains OSI-style layer numbers beside the groups; those are reference positions, not formal TCP/IP numbering. The model does not show separate Session and Presentation layers, but their functions may be provided elsewhere, including by application or transport mechanisms. Physical transmission is still necessary even when shown outside the TCP/IP core.

The lecture lists broad system support, consistent APIs, a track record, lower complexity, and Internet/World Wide Web adoption among reasons TCP/IP became popular. These are the lecture’s contextual observations, not a protocol comparison or a claim that OSI functions are unnecessary.

Connection-oriented and connectionless modes

The first deck contrasts communication with an identifiable lifetime, negotiation, connection identifiers and related data units against independent, self-contained data units without negotiation. These are introductory distinctions, not universal rules for every protocol. Its “three-party” versus “two-party agreement” labels are underspecified, so they are not used here as definitions. The later transport notes cover the lecture’s transport connection procedures.

Apply the scopes in the lab examples

In Lab 1.1, PC-A is 192.168.1.3/24 and the switch VLAN 1 interface is 192.168.1.1/24. They are on the same subnet, so PC-A resolves the SVI’s MAC address and sends a local-link frame directly; no router is needed for this exchange. The IPv4 address identifies the network-layer endpoint, while the MAC address is used for the current link. In Lab 1.2, each switch learns the source MAC on the port where a frame arrives: for example, PC-B’s address is learned on S2 F0/18 and on S1’s inter-switch F0/1. A switch uses the destination MAC for its forwarding lookup. These observations apply the scopes above; the labs’ command procedures and full switching trace belong in LAN and Ethernet.

Common mistakes

  • A service describes what is offered; an interface describes adjacent-layer access; a protocol describes peer rules.
  • Peer communication is logical. The message still travels through lower layers and the physical medium.
  • A frame carries a Network-layer packet; it does not replace that packet.
  • Layer 2’s delivery scope is one link. Layer 3 is host-to-host, and Layer 4 is end-to-end between processes.
  • Do not treat a locally reliable link as proof of reliable delivery across a multi-link path.
  • Do not assume ICI is sent to a remote peer, or that the four service primitives are four packets.
  • A model’s function can exist in a real system even when that model does not show it as a separate layer.

Exam focus

  • OSI is a reference model for organizing and discussing communication functions.
  • Memorize the numbering direction: 1 Physical, 2 Data Link, 3 Network, 4 Transport, 5 Session, 6 Presentation, 7 Application.
  • Distinguish service, interface and peer protocol; know the SAP and request/indication/response/confirm directions.
  • Use PDU=PCI+SDU; IDU is the SAP transfer containing SDU, PCI and ICI under the lecture’s terminology.
  • Sending encapsulates downward; receiving decapsulates upward. A Data Link frame encapsulates a Network packet.
  • Distinguish link-local, host-to-host and end-to-end scopes.

Practice questions

A device’s Layer 2 service delivers a frame successfully to the next router. Does that establish end-to-end reliability? Why?

Check your answer

No. Data Link handles a single link. Later links can still fail, so end-to-end reliability requires suitable higher-layer service. Check the scope: the first link ends at the router, not at the destination process.

Which service primitive completes a function previously invoked by a request, and which completes a function previously indicated?

Check your answer

Confirm completes a request; response completes an indication. Trace the two paths: request → provider → confirm; indication → remote user → response.

What is the content encapsulated by a link-layer frame (Quiz 1, Q9)?

Check your answer

A Network-layer packet. Layer 2 frames the packet it receives from Layer 3; the packet is the frame’s payload.

In the teaching trace, which information is rebuilt by router R and which destination remains the same?

Check your answer

The link-layer wrapper is rebuilt for the next link. The network-layer final destination remains host B. The link destination is for the current link, while the network destination identifies the final host.

Identify the OSI layer number tested in Quiz 1, Q3 for Data Link.

Check your answer

Layer 2. Counting upward from Physical at Layer 1 places Data Link at Layer 2.
